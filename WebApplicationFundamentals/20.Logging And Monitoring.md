## 1. Application Logging

Logs record important application events.

```python name=app/logging_config.py
import logging
import sys


def configure_logging() -> None:
    logging.basicConfig(
        level=logging.INFO,
        format=(
            "%(asctime)s %(levelname)s %(name)s "
            "%(message)s"
        ),
        handlers=[logging.StreamHandler(sys.stdout)],
        force=True,
    )
```

Write logs to standard output so Docker or the hosting platform can collect them.

---

## 2. Log Levels

| Level | Purpose |
|---|---|
| `DEBUG` | Detailed development diagnostics |
| `INFO` | Normal application events |
| `WARNING` | Unexpected but recoverable situations |
| `ERROR` | Failed operations |
| `CRITICAL` | Severe failures affecting availability |

Keep verbose `DEBUG` logging disabled in production.

## 4. Request or Correlation IDs

A request ID connects all logs generated for one request.

```python name=app/middleware/request_id.py
from contextvars import ContextVar
from uuid import uuid4

from fastapi import Request, Response

request_id_context: ContextVar[str] = ContextVar(
    "request_id",
    default="unknown",
)


async def request_id_middleware(
    request: Request,
    call_next,
) -> Response:
    request_id = str(uuid4())
    token = request_id_context.set(request_id)

    try:
        response = await call_next(request)
        response.headers["X-Request-ID"] = request_id
        return response
    finally:
        request_id_context.reset(token)
```

Generating the ID on the server prevents untrusted values from being inserted into logs.

## 5. Request Logging Middleware

```python name=app/middleware/request_logging.py
import logging
from time import perf_counter

from fastapi import Request, Response

from app.middleware.request_id import request_id_context

logger = logging.getLogger(__name__)


async def request_logging_middleware(
    request: Request,
    call_next,
) -> Response:
    started_at = perf_counter()

    try:
        response = await call_next(request)
    except Exception:
        logger.exception(
            "Request failed method=%s path=%s request_id=%s",
            request.method,
            request.url.path,
            request_id_context.get(),
        )
        raise

    duration_ms = (perf_counter() - started_at) * 1_000

    logger.info(
        "Request completed method=%s path=%s status=%s "
        "duration_ms=%.2f request_id=%s",
        request.method,
        request.url.path,
        response.status_code,
        duration_ms,
        request_id_context.get(),
    )

    return response
```

Record the method, route, status, duration, and request ID. Avoid logging complete URLs because query strings may contain sensitive information.

## 6. Register Middleware

```python name=app/main.py
from fastapi import FastAPI

from app.logging_config import configure_logging
from app.middleware.request_id import request_id_middleware
from app.middleware.request_logging import request_logging_middleware

configure_logging()

app = FastAPI(debug=False)

app.middleware("http")(request_logging_middleware)
app.middleware("http")(request_id_middleware)
```

Middleware order matters. Test that the request ID is available to request logging and error handlers.

## 7. Never Log Sensitive Data

Do not log:

- Passwords or password hashes
- Access or refresh tokens
- Session cookies
- API keys
- Authorization headers
- Database connection strings
- Complete payment information
- Sensitive request or response bodies

```python name=app/security/logging.py
SENSITIVE_HEADERS = {
    "authorization",
    "cookie",
    "set-cookie",
    "x-api-key",
}


def safe_headers(headers: dict[str, str]) -> dict[str, str]:
    return {
        name: "[REDACTED]" if name.lower() in SENSITIVE_HEADERS else value
        for name, value in headers.items()
    }
```

Prefer not to log headers at all. If required for diagnostics, redact sensitive values first.

## 8. Metrics

Metrics provide numeric measurements over time.

Important API metrics include:

- Request count
- Error count
- Request duration
- Active requests
- Database query duration
- External service failures
- Authentication failures
- Rate-limit rejections

```python name=app/monitoring/metrics.py
from collections import Counter

request_counts: Counter[tuple[str, int]] = Counter()


def record_request(route: str, status_code: int) -> None:
    request_counts[(route, status_code)] += 1
```

This demonstrates the concept. Use a production monitoring system for distributed applications.

---

## 9. Avoid High-Cardinality Metric Labels

Unsafe label values include:

- User ID
- Email address
- Request ID
- Full URL
- Access token
- Unbounded search terms

Use stable route templates instead:

```text name=metric-labels.txt
Recommended: route="/users/{user_id}"
Avoid:       route="/users/938247"
```

High-cardinality labels increase monitoring cost and reduce performance.

## 10. Health Endpoints

```python name=app/routers/health.py
from fastapi import APIRouter, HTTPException, status
from sqlalchemy import text

from app.dependencies import DatabaseSession

router = APIRouter(prefix="/health", tags=["System"])


@router.get("/live")
def liveness() -> dict[str, str]:
    return {"status": "alive"}


@router.get("/ready")
def readiness(db: DatabaseSession) -> dict[str, str]:
    try:
        db.execute(text("SELECT 1"))
    except Exception:
        raise HTTPException(
            status_code=status.HTTP_503_SERVICE_UNAVAILABLE,
            detail="Service unavailable",
        ) from None

    return {"status": "ready"}
```

- **Liveness:** Confirms that the process is running.
- **Readiness:** Confirms that the application can serve traffic.

Do not expose database addresses or other infrastructure details.

## 11. Distributed Tracing

Tracing follows one request across multiple services.

```text name=trace-flow.txt
Frontend
   ↓ trace ID
FastAPI
   ↓ trace ID
Payment service
   ↓ trace ID
Database
```

A trace contains:

- **Trace:** Complete request journey
- **Span:** One operation within the journey
- **Trace ID:** Connects all spans
- **Duration:** Time taken by each operation

OpenTelemetry is commonly used to collect vendor-neutral traces.

## 12. Trace External Requests

```python name=app/services/payment_client.py
import httpx


async def get_payment(
    payment_id: str,
    trace_id: str,
) -> dict[str, object]:
    async with httpx.AsyncClient(timeout=5.0) as client:
        response = await client.get(
            f"https://payments.example.com/payments/{payment_id}",
            headers={"Traceparent": trace_id},
        )
        response.raise_for_status()
        return response.json()
```

In production, use a tracing library to create and propagate correctly formatted trace headers automatically.

The external host should come from trusted configuration, not user input.

## 13. Audit Logs

Audit logs record security-sensitive actions.

Examples:

- Login and logout
- Password changes
- Role or permission changes
- User deactivation
- Sensitive file access
- Data exports
- Administrative changes

```python name=app/audit.py
import logging

audit_logger = logging.getLogger("audit")


def record_role_change(
    actor_id: int,
    target_user_id: int,
    new_role: str,
) -> None:
    audit_logger.info(
        "Role changed actor_id=%s target_user_id=%s new_role=%s",
        actor_id,
        target_user_id,
        new_role,
    )
```

Record who performed the action, what changed, and when it occurred.

## 14. Audit Log Database Model

```python name=app/models/audit_event.py
from datetime import datetime

from sqlalchemy import DateTime, String
from sqlalchemy.orm import Mapped, mapped_column

from app.database import Base


class AuditEvent(Base):
    __tablename__ = "audit_events"

    id: Mapped[int] = mapped_column(primary_key=True)
    actor_id: Mapped[int | None] = mapped_column(index=True)
    action: Mapped[str] = mapped_column(String(100), index=True)
    target_type: Mapped[str] = mapped_column(String(100))
    target_id: Mapped[str] = mapped_column(String(100))
    occurred_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True),
        index=True,
    )
```

Audit records should be append-only for ordinary application users. Restrict read and write access using least privilege.

## 15. Security Event Logging

```python name=app/security/events.py
import hashlib
import logging

logger = logging.getLogger("security")


def log_failed_login(email: str) -> None:
    normalized_email = email.strip().lower()
    account_reference = hashlib.sha256(
        normalized_email.encode("utf-8")
    ).hexdigest()

    logger.warning(
        "Login failed account_reference=%s",
        account_reference,
    )
```

Hashing the identifier avoids storing the email directly in logs. Do not log the submitted password.

## 16. Alerts

Create alerts for meaningful conditions:

- Sudden increase in `5xx` responses
- High request latency
- Database connection failures
- Repeated login failures
- Unusual permission changes
- High rate-limit rejection count
- Low disk space
- Background-job failures

Avoid alerting on every individual error because excessive alerts may hide real incidents.

---

## 17. Useful Reliability Measurements

Common service-level indicators include:

| Measurement | Meaning |
|---|---|
| Availability | Percentage of successful requests |
| Latency | Time required to process requests |
| Error rate | Percentage of failed requests |
| Throughput | Requests processed per second |
| Saturation | Resource usage near system limits |

Measure percentiles such as `p50`, `p95`, and `p99` rather than relying only on average latency.

---

## 18. Log Retention and Access

Production logging should include:

- Defined retention periods
- Encryption in transit and at rest
- Restricted access
- Tamper protection for audit logs
- Automatic deletion after the retention period
- Backup and recovery where legally required

Do not retain personal or sensitive data longer than necessary.

## Key Points

- Use structured, centralized logs.
- Assign a request ID to every request.
- Never log credentials, tokens, secrets, or sensitive bodies.
- Monitor traffic, errors, latency, dependencies, and security events.
- Avoid personal or unbounded metric labels.
- Use tracing to follow requests across services.
- Keep audit logs for privileged and sensitive actions.
- Restrict and encrypt logs.
- Configure actionable alerts.
- Define log-retention and incident-response procedures.
