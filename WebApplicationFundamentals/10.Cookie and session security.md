
# Topic 10: Cookie and Session Security

Cookie-based authentication stores a random **session ID** in the browser. The actual session data remains on the server.

## 1. Session Authentication Flow

```text name=session-flow.txt
User submits credentials
        ↓
Server verifies credentials
        ↓
Server creates a random session ID
        ↓
Browser receives session ID in a secure cookie
        ↓
Browser sends the cookie with later requests
        ↓
Server validates the session
```

The cookie should contain only an unpredictable identifier—not a password or sensitive user data.

---

## 2. Generate a Secure Session ID

```python name=app/security/sessions.py
import secrets


def generate_session_id() -> str:
    return secrets.token_urlsafe(32)
```

`secrets` generates cryptographically secure random values. Session IDs must not be predictable.

---

## 3. Store Only a Session-ID Hash

```python name=app/security/sessions.py
import hashlib


def hash_session_id(session_id: str) -> str:
    return hashlib.sha256(session_id.encode("utf-8")).hexdigest()
```

Store the hash in the database and send the original session ID to the browser. If the database is exposed, attackers cannot directly use the stored hash as a cookie.

SHA-256 is suitable here because the session ID is long, random, and high-entropy. It is not suitable for hashing user passwords.

## 4. Session Database Model

```python name=app/models/session.py
from datetime import datetime

from sqlalchemy import DateTime, ForeignKey, String
from sqlalchemy.orm import Mapped, mapped_column

from app.database import Base


class UserSession(Base):
    __tablename__ = "user_sessions"

    id: Mapped[int] = mapped_column(primary_key=True)
    session_hash: Mapped[str] = mapped_column(
        String(64),
        unique=True,
        index=True,
    )
    user_id: Mapped[int] = mapped_column(
        ForeignKey("users.id", ondelete="CASCADE"),
        index=True,
    )
    expires_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True),
    )
    revoked_at: Mapped[datetime | None] = mapped_column(
        DateTime(timezone=True),
        default=None,
    )
```

The server stores the session owner, expiration time, and revocation state.

## 5. Set a Secure Session Cookie

```python name=app/security/cookies.py
from fastapi import Response


def set_session_cookie(
    response: Response,
    session_id: str,
) -> None:
    response.set_cookie(
        key="__Host-session",
        value=session_id,
        max_age=900,
        path="/",
        secure=True,
        httponly=True,
        samesite="strict",
    )
```

Security attributes:

- `HttpOnly`: Prevents JavaScript from reading the cookie.
- `Secure`: Sends the cookie only over HTTPS.
- `SameSite=Strict`: Strongly limits cross-site submission.
- `Path=/`: Makes the cookie available throughout the application.
- `Max-Age=900`: Expires it after 15 minutes.

The `__Host-` prefix requires HTTPS, `Path=/`, and no `Domain` attribute, reducing cookie-injection risks.

## 6. Create a Session After Login

```python name=app/services/session_service.py
from datetime import UTC, datetime, timedelta

from sqlalchemy.orm import Session

from app.models.session import UserSession
from app.security.sessions import generate_session_id, hash_session_id


def create_session(
    db: Session,
    user_id: int,
) -> str:
    session_id = generate_session_id()

    record = UserSession(
        session_hash=hash_session_id(session_id),
        user_id=user_id,
        expires_at=datetime.now(UTC) + timedelta(minutes=15),
    )

    db.add(record)
    db.commit()

    return session_id
```

Create the session only after verifying the user’s credentials.

## 7. Prevent Session Fixation

Never reuse a session ID supplied before login.

```python name=app/routers/login.py
from fastapi import APIRouter, Response

from app.dependencies import DatabaseSession
from app.security.cookies import set_session_cookie
from app.services.session_service import create_session

router = APIRouter(prefix="/auth")


@router.post("/login")
def login(
    response: Response,
    db: DatabaseSession,
) -> dict[str, str]:
    user_id = 1  # Result of verified credentials.

    session_id = create_session(db, user_id)
    set_session_cookie(response, session_id)

    return {"message": "Login successful"}
```

Generating a new session ID after successful login prevents an attacker from forcing the victim to use a known session ID.

## 8. Read the Session Cookie

```python name=app/dependencies/session_auth.py
from typing import Annotated

from fastapi import Cookie, HTTPException, status


def require_session_cookie(
    session_id: Annotated[
        str | None,
        Cookie(alias="__Host-session"),
    ] = None,
) -> str:
    if session_id is None:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Authentication required",
        )

    return session_id
```

FastAPI reads the cookie from the request. The server must still validate it against the session store.

## 9. Validate the Session

```python name=app/dependencies/session_auth.py
from datetime import UTC, datetime
from typing import Annotated

from fastapi import Depends, HTTPException, status
from sqlalchemy import select

from app.dependencies import DatabaseSession
from app.models.session import UserSession
from app.security.sessions import hash_session_id


def get_current_session(
    db: DatabaseSession,
    session_id: Annotated[str, Depends(require_session_cookie)],
) -> UserSession:
    session = db.scalar(
        select(UserSession).where(
            UserSession.session_hash == hash_session_id(session_id),
        )
    )

    if (
        session is None
        or session.revoked_at is not None
        or session.expires_at <= datetime.now(UTC)
    ):
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Invalid or expired session",
        )

    return session
```

The server checks that the session exists, has not expired, and has not been revoked.

## 10. Protect an Endpoint

```python name=app/routers/profile.py
from typing import Annotated

from fastapi import APIRouter, Depends

from app.dependencies.session_auth import get_current_session
from app.models.session import UserSession

router = APIRouter(prefix="/profile")

CurrentSession = Annotated[UserSession, Depends(get_current_session)]


@router.get("")
def get_profile(session: CurrentSession) -> dict[str, int]:
    return {"user_id": session.user_id}
```

A valid session authenticates the user. Sensitive operations still require separate authorization checks.

## 11. Logout and Revoke the Session

```python name=app/routers/logout.py
from datetime import UTC, datetime

from fastapi import Response, status


@router.post("/logout", status_code=status.HTTP_204_NO_CONTENT)
def logout(
    response: Response,
    session: CurrentSession,
    db: DatabaseSession,
) -> Response:
    session.revoked_at = datetime.now(UTC)
    db.commit()

    response.delete_cookie(
        key="__Host-session",
        path="/",
        secure=True,
        httponly=True,
        samesite="strict",
    )
    response.status_code = status.HTTP_204_NO_CONTENT

    return response
```

Logout must revoke the server-side session and remove the browser cookie.

## 12. Session Expiration

Use both:

- **Absolute timeout:** Session ends after a fixed period.
- **Idle timeout:** Session ends after a period without activity.

```text name=session-timeouts.txt
Idle timeout:     15 minutes without activity
Absolute timeout: 8 hours after login
```

Shorter timeouts are appropriate for administrative or financial applications.

## 13. Cross-Site Cookies

If the frontend and API require a cross-site cookie:

```python name=app/security/cookies.py
response.set_cookie(
    key="__Host-session",
    value=session_id,
    secure=True,
    httponly=True,
    samesite="none",
    path="/",
)
```

Frontend:

```javascript name=frontend.js
await fetch("https://api.example.com/profile", {
  credentials: "include",
});
```

`SameSite=None` requires `Secure`. Cross-site cookie authentication also requires strict CORS configuration and CSRF protection.

Use `SameSite=Strict` or `Lax` whenever the application design permits it.

## 14. CSRF Protection

Browsers automatically attach cookies, so an attacker may attempt to submit a request from another website.

One protection is a CSRF token:

```http name=csrf-request.http
POST /profile/email HTTP/1.1
Cookie: __Host-session=random-session-id
X-CSRF-Token: unpredictable-csrf-token
Content-Type: application/json
```

The server must compare the header token with the token associated with the session. Apply CSRF protection to state-changing methods such as `POST`, `PUT`, `PATCH`, and `DELETE`.

## 15. Session Revocation Events

Revoke sessions when:

- The user logs out
- The password changes
- The account is disabled
- Suspicious activity is detected
- An administrator removes access
- The user chooses “log out from all devices”

```python name=app/services/session_service.py
from datetime import UTC, datetime

from sqlalchemy import update


def revoke_all_user_sessions(
    db: DatabaseSession,
    user_id: int,
) -> None:
    db.execute(
        update(UserSession)
        .where(
            UserSession.user_id == user_id,
            UserSession.revoked_at.is_(None),
        )
        .values(revoked_at=datetime.now(UTC))
    )
    db.commit()
```

This invalidates every active session belonging to the user.

## 16. Cookie Authentication and CORS

For cross-origin cookie requests:

```python name=app/main.py
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://app.example.com"],
    allow_credentials=True,
    allow_methods=["GET", "POST", "PATCH", "DELETE"],
    allow_headers=["Content-Type", "X-CSRF-Token"],
)
```

Use a specific origin. Do not combine credentialed requests with unrestricted origins.

---

## Key Security Rules

- Generate session IDs with `secrets`.
- Generate a new session ID after login.
- Store only the session ID hash.
- Use `HttpOnly`, `Secure`, and the strictest usable `SameSite` setting.
- Keep sessions short-lived and revocable.
- Revoke sessions during logout and security-sensitive account changes.
- Use CSRF protection for cookie-authenticated state changes.
- Never put passwords or private information inside cookies.
- Use HTTPS in production.
- Check authorization after validating the session.
