
# Topic 15: Rate Limiting and Abuse Prevention

**Rate limiting** restricts how often a client can call an API. It helps prevent brute-force attacks, excessive resource use, and service disruption.

## 1. Why Rate Limiting Is Needed

Apply stricter limits to sensitive or expensive endpoints:

| Endpoint | Example limit |
|---|---:|
| Login | 5 attempts per 15 minutes |
| Password reset | 3 attempts per hour |
| Registration | 5 accounts per hour |
| Search | 60 requests per minute |
| General API | 100 requests per minute |

Actual limits should match the application’s risk and expected usage.

---

## 2. `429 Too Many Requests`

Return `429` when a client exceeds its limit.

```python name=app/main.py
from fastapi import FastAPI, HTTPException, status

app = FastAPI()


def reject_rate_limited_request() -> None:
    raise HTTPException(
        status_code=status.HTTP_429_TOO_MANY_REQUESTS,
        detail="Too many requests",
        headers={"Retry-After": "60"},
    )
```

`Retry-After` tells the client how many seconds to wait before retrying.

## 3. Fixed-Window Limiting

A fixed window counts requests during a specific period.

```text name=fixed-window.txt
Window: 10:00–10:01
Limit:  5 requests

Request 1 → Allowed
Request 2 → Allowed
Request 3 → Allowed
Request 4 → Allowed
Request 5 → Allowed
Request 6 → Rejected
```

It is simple but may allow request bursts around the boundary between two windows.

## 4. Simple In-Memory Example

```python name=app/security/rate_limit.py
from collections import defaultdict
from time import monotonic

WINDOW_SECONDS = 60
MAX_REQUESTS = 10

requests_by_client: dict[str, list[float]] = defaultdict(list)


def is_request_allowed(client_id: str) -> bool:
    now = monotonic()
    window_start = now - WINDOW_SECONDS

    recent_requests = [
        timestamp
        for timestamp in requests_by_client[client_id]
        if timestamp > window_start
    ]

    if len(recent_requests) >= MAX_REQUESTS:
        requests_by_client[client_id] = recent_requests
        return False

    recent_requests.append(now)
    requests_by_client[client_id] = recent_requests
    return True
```

This demonstrates a sliding-window approach. It is not suitable for production because each application process has separate memory.

## 5. FastAPI Rate-Limit Dependency

```python name=app/dependencies/rate_limit.py
from typing import Annotated

from fastapi import Header, HTTPException, status

from app.security.rate_limit import is_request_allowed


def enforce_rate_limit(
    x_client_id: Annotated[str | None, Header()] = None,
) -> None:
    if not x_client_id:
        raise HTTPException(
            status_code=status.HTTP_400_BAD_REQUEST,
            detail="Client identifier is required",
        )

    if not is_request_allowed(x_client_id):
        raise HTTPException(
            status_code=status.HTTP_429_TOO_MANY_REQUESTS,
            detail="Rate limit exceeded",
            headers={"Retry-After": "60"},
        )
```

Use the dependency on an endpoint:

```python name=app/routers/search.py
from fastapi import APIRouter, Depends, Query

from app.dependencies.rate_limit import enforce_rate_limit

router = APIRouter(prefix="/search")


@router.get("", dependencies=[Depends(enforce_rate_limit)])
def search(
    query: str = Query(min_length=2, max_length=100),
) -> dict[str, object]:
    return {"query": query, "items": []}
```

Do not trust a freely chosen client header in production. Use a validated user ID, API key ID, or carefully determined IP address.

## 6. Rate Limit by Authenticated User

```python name=app/routers/profile.py
from fastapi import APIRouter, HTTPException, status

from app.dependencies.auth import CurrentUser
from app.security.rate_limit import is_request_allowed

router = APIRouter(prefix="/profile")


@router.get("")
def get_profile(current_user: CurrentUser) -> dict[str, object]:
    client_id = f"user:{current_user.id}"

    if not is_request_allowed(client_id):
        raise HTTPException(
            status_code=status.HTTP_429_TOO_MANY_REQUESTS,
            detail="Rate limit exceeded",
            headers={"Retry-After": "60"},
        )

    return {
        "id": current_user.id,
        "email": current_user.email,
    }
```

Authenticated user IDs are usually more reliable than IP addresses.

## 7. Rate Limit by IP Address

```python name=app/security/client_ip.py
from fastapi import Request


def get_client_ip(request: Request) -> str:
    if request.client is None:
        return "unknown"

    return request.client.host
```

Use IP-based limits for unauthenticated endpoints such as login and registration.

Only trust headers such as `X-Forwarded-For` when they are set and sanitized by a trusted reverse proxy. Otherwise, clients can forge them.

## 8. Login Rate Limiting

```python name=app/routers/auth.py
from fastapi import APIRouter, HTTPException, Request, status

from app.security.client_ip import get_client_ip
from app.security.rate_limit import is_request_allowed

router = APIRouter(prefix="/auth")


@router.post("/login")
def login(request: Request) -> dict[str, str]:
    client_id = f"login-ip:{get_client_ip(request)}"

    if not is_request_allowed(client_id):
        raise HTTPException(
            status_code=status.HTTP_429_TOO_MANY_REQUESTS,
            detail="Too many login attempts",
            headers={"Retry-After": "900"},
        )

    # Verify credentials.
    return {"message": "Login processed"}
```

Login limits slow password-guessing attacks. Combine IP limits with account-based limits.

## 9. Avoid Account Enumeration

Use a normalized account identifier without exposing whether it exists.

```python name=app/services/login_limits.py
import hashlib


def create_account_limit_key(email: str) -> str:
    normalized_email = email.strip().lower()
    identifier = hashlib.sha256(
        normalized_email.encode("utf-8")
    ).hexdigest()

    return f"login-account:{identifier}"
```

Hashing the email avoids placing personal data directly in rate-limit keys and logs.

Return the same login error whether the email or password is incorrect.

## 10. Temporary Account Lockout

```python name=app/models/user.py
from datetime import datetime

from sqlalchemy import DateTime, Integer
from sqlalchemy.orm import Mapped, mapped_column


class User:
    failed_login_attempts: Mapped[int] = mapped_column(
        Integer,
        default=0,
        nullable=False,
    )
    locked_until: Mapped[datetime | None] = mapped_column(
        DateTime(timezone=True),
        default=None,
    )
```

After repeated failures:

```text name=lockout-policy.txt
5 failures  → Lock for 5 minutes
10 failures → Require stronger recovery or administrator review
```

Reset the failure count after successful authentication. Avoid permanent automatic lockout because attackers could intentionally lock other users’ accounts.

## 11. Token-Bucket Algorithm

A token bucket supports controlled bursts.

```text name=token-bucket.txt
Bucket capacity: 10 tokens
Refill rate:     1 token per second
Request cost:    1 token

Request allowed → Remove one token
No tokens left  → Return 429
```

This is useful when short bursts are acceptable but sustained excessive traffic is not.

One global limit is usually insufficient because endpoints have different security and performance costs.

## 13. Distributed Rate Limiting

Production applications commonly use:

- Redis
- An API gateway
- A reverse proxy
- A managed cloud rate-limiting service

```text name=distributed-rate-limit.txt
API instance 1 ─┐
API instance 2 ─┼→ Shared rate-limit store
API instance 3 ─┘
```

A shared store ensures all application instances enforce the same counters.

Operations should be atomic to prevent concurrent requests from bypassing the limit.

## 14. Standard Rate-Limit Headers

A response may include:

```http name=rate-limit-headers.http
HTTP/1.1 200 OK
RateLimit-Limit: 100
RateLimit-Remaining: 42
RateLimit-Reset: 37
```

When blocked:

```http name=rate-limit-blocked.http
HTTP/1.1 429 Too Many Requests
Retry-After: 37
RateLimit-Limit: 100
RateLimit-Remaining: 0
RateLimit-Reset: 37
```

These headers help well-behaved clients manage their request frequency.

## 15. Client Retry Behavior

```python name=client/retry.py
import asyncio

import httpx


async def get_with_retry(url: str) -> httpx.Response:
    async with httpx.AsyncClient(timeout=5.0) as client:
        response = await client.get(url)

        if response.status_code == 429:
            wait_seconds = min(
                int(response.headers.get("Retry-After", "1")),
                60,
            )
            await asyncio.sleep(wait_seconds)
            response = await client.get(url)

        response.raise_for_status()
        return response
```

Clients should respect `Retry-After`. Retry a limited number of times to avoid retry storms.

The URL should come from a trusted configuration or strict allow-list.

## 16. Protect Expensive Queries

```python name=app/routers/reports.py
from fastapi import Query


@router.get("/reports")
def get_reports(
    page: int = Query(default=1, ge=1),
    page_size: int = Query(default=20, ge=1, le=100),
) -> dict[str, object]:
    return {
        "items": [],
        "page": page,
        "page_size": page_size,
    }
```

Rate limiting should be combined with:

- Pagination limits
- Query timeouts
- Request size limits
- Caching
- Background jobs
- Database query optimization

Rate limiting alone cannot protect an inefficient endpoint.

## 17. Monitoring Abuse

Log rate-limit events without logging credentials or sensitive request data.

```python name=app/security/rate_limit_logging.py
import logging

logger = logging.getLogger("security")


def log_rate_limit_event(
    client_type: str,
    endpoint: str,
) -> None:
    logger.warning(
        "Rate limit exceeded client_type=%s endpoint=%s",
        client_type,
        endpoint,
    )
```

Monitor:

- Repeated login failures
- Sudden request spikes
- Large numbers of `429` responses
- Requests across many accounts from one source
- Expensive endpoint usage

Use alerts for unusual patterns.

## 18. Test Rate Limiting

```python name=tests/test_rate_limit.py
from fastapi.testclient import TestClient


def test_rate_limit_rejects_excess_requests(
    client: TestClient,
) -> None:
    headers = {"X-Client-ID": "test-client"}

    for _ in range(10):
        response = client.get("/search?query=python", headers=headers)
        assert response.status_code == 200

    blocked_response = client.get(
        "/search?query=python",
        headers=headers,
    )

    assert blocked_response.status_code == 429
    assert "Retry-After" in blocked_response.headers
```

Reset or isolate the rate-limit store between tests to keep tests independent.

## Key Security Rules

- Apply stricter limits to login and password-reset endpoints.
- Combine IP, user, account, and API-key limits where appropriate.
- Return `429` with `Retry-After`.
- Use a shared atomic store for distributed production systems.
- Do not trust forwarded IP headers unless a trusted proxy controls them.
- Avoid permanent automatic account lockouts.
- Limit retries on the client.
- Monitor repeated limit violations.
- Combine rate limiting with authorization, input limits, timeouts, and efficient queries.
