# Topic 23: Testing Web APIs

API testing verifies behavior, security, compatibility, and reliability before deployment.

## 1. Testing Levels

| Test type | Purpose |
|---|---|
| Unit | Tests one function or class in isolation |
| Integration | Tests components such as API, database, and authentication together |
| End-to-end | Tests complete user workflows |
| Contract | Verifies request and response compatibility |
| Security | Tests access controls and malicious inputs |
| Performance | Measures latency, throughput, and stability |

Use many fast unit tests, focused integration tests, and fewer end-to-end tests.

## 5. Unit Test Business Logic

Keep business logic separate from routes so it can be tested directly.

```python name=app/services/pricing.py
from decimal import Decimal


def calculate_total(
    unit_price: Decimal,
    quantity: int,
) -> Decimal:
    if unit_price < 0:
        raise ValueError("unit_price must not be negative")

    if quantity < 1:
        raise ValueError("quantity must be at least 1")

    return unit_price * quantity
```

```python name=tests/unit/test_pricing.py
from decimal import Decimal

import pytest

from app.services.pricing import calculate_total


def test_calculate_total() -> None:
    result = calculate_total(Decimal("12.50"), 2)

    assert result == Decimal("25.00")


@pytest.mark.parametrize("quantity", [0, -1])
def test_rejects_invalid_quantity(quantity: int) -> None:
    with pytest.raises(
        ValueError,
        match="quantity must be at least 1",
    ):
        calculate_total(Decimal("12.50"), quantity)
```

Unit tests should be fast and independent of databases or external services.

## 6. Override FastAPI Dependencies

Replace production dependencies with controlled test versions.

```python name=tests/test_profile.py
from collections.abc import Iterator
from dataclasses import dataclass

import pytest
from fastapi.testclient import TestClient

from app.dependencies.auth import get_current_user
from app.main import app


@dataclass
class TestUser:
    id: int
    email: str
    is_active: bool = True


def override_current_user() -> TestUser:
    return TestUser(id=1, email="alice@example.com")


@pytest.fixture
def authenticated_client() -> Iterator[TestClient]:
    app.dependency_overrides[get_current_user] = override_current_user

    try:
        with TestClient(app) as client:
            yield client
    finally:
        app.dependency_overrides.clear()


def test_profile_returns_current_user(
    authenticated_client: TestClient,
) -> None:
    response = authenticated_client.get("/profile")

    assert response.status_code == 200
    assert response.json()["id"] == 1
```

Always clear overrides to prevent one test from affecting another.

## 11. Database Integration Tests

Use a separate database created specifically for testing. Never point tests at production data.

```python name=tests/conftest.py
import os

TEST_DATABASE_URL = os.environ.get("TEST_DATABASE_URL")

if not TEST_DATABASE_URL:
    raise RuntimeError("TEST_DATABASE_URL is required")

if "test" not in TEST_DATABASE_URL.lower():
    raise RuntimeError(
        "Refusing to run: database URL does not appear to be a test database"
    )
```

A stronger safeguard is to use a dedicated container, database account, and network inaccessible from production.

## 12. Roll Back Database Changes

```python name=tests/conftest.py
from collections.abc import Iterator

import pytest
from sqlalchemy import create_engine
from sqlalchemy.orm import Session

test_engine = create_engine(TEST_DATABASE_URL)


@pytest.fixture
def db() -> Iterator[Session]:
    connection = test_engine.connect()
    transaction = connection.begin()
    session = Session(bind=connection)

    try:
        yield session
    finally:
        session.close()
        transaction.rollback()
        connection.close()
```

Rolling back after each test keeps tests isolated and repeatable.

Application code that calls `commit()` may require a nested-transaction fixture or a fresh database schema per test worker.

## 13. Test Database Constraints

```python name=tests/integration/test_users.py
import pytest
from sqlalchemy.exc import IntegrityError
from sqlalchemy.orm import Session

from app.models.user import User


def test_email_must_be_unique(db: Session) -> None:
    db.add(User(email="alice@example.com"))
    db.flush()

    db.add(User(email="alice@example.com"))

    with pytest.raises(IntegrityError):
        db.flush()
```

Application validation is useful, but database constraints are the final protection against concurrency and invalid state.

## 14. Mock an External Service

```python name=app/services/payment_service.py
import httpx


async def get_payment_status(
    client: httpx.AsyncClient,
    payment_id: str,
) -> str:
    response = await client.get(
        f"/payments/{payment_id}",
    )
    response.raise_for_status()

    payload = response.json()
    return str(payload["status"])
```

```python name=tests/unit/test_payment_service.py
import httpx
import pytest

from app.services.payment_service import get_payment_status


@pytest.mark.asyncio
async def test_get_payment_status() -> None:
    def handler(request: httpx.Request) -> httpx.Response:
        assert request.url.path == "/payments/pay-123"
        return httpx.Response(
            200,
            json={"status": "completed"},
        )

    transport = httpx.MockTransport(handler)

    async with httpx.AsyncClient(
        base_url="https://payments.test",
        transport=transport,
    ) as client:
        status = await get_payment_status(client, "pay-123")

    assert status == "completed"
```

Mocking makes tests deterministic and prevents accidental calls to real services.

## 16. Contract Testing

Contract tests verify that response shapes remain compatible.

```python name=tests/contract/test_user_response.py
from fastapi.testclient import TestClient


def test_user_response_contract(
    authenticated_client: TestClient,
) -> None:
    response = authenticated_client.get("/profile")

    assert response.status_code == 200

    payload = response.json()

    assert set(payload) == {"id", "email"}
    assert isinstance(payload["id"], int)
    assert isinstance(payload["email"], str)
```

Be cautious with exact field-set checks if adding optional response fields is considered backward-compatible.

OpenAPI schema checks and consumer-driven contract tools can provide stronger compatibility testing.

## 18. Test File Upload Security

```python name=tests/security/test_uploads.py
from fastapi.testclient import TestClient


def test_upload_rejects_executable_content(
    authenticated_client: TestClient,
) -> None:
    response = authenticated_client.post(
        "/files",
        files={
            "file": (
                "../../payload.py",
                b"print('unsafe')",
                "image/png",
            )
        },
    )

    assert response.status_code == 415


def test_upload_rejects_oversized_file(
    authenticated_client: TestClient,
) -> None:
    oversized_content = b"a" * (2 * 1024 * 1024 + 1)

    response = authenticated_client.post(
        "/files",
        files={
            "file": (
                "large.png",
                oversized_content,
                "image/png",
            )
        },
    )

    assert response.status_code == 413
```

Test actual signatures, size limits, filename handling, authorization, and malware-scanning states.

## 20. Test CORS Preflight

```python name=tests/security/test_cors.py
from fastapi.testclient import TestClient


def test_trusted_origin_preflight(
    client: TestClient,
) -> None:
    response = client.options(
        "/profile",
        headers={
            "Origin": "https://app.example.com",
            "Access-Control-Request-Method": "PATCH",
            "Access-Control-Request-Headers": (
                "content-type,x-csrf-token"
            ),
        },
    )

    assert response.status_code == 200
    assert (
        response.headers["Access-Control-Allow-Origin"]
        == "https://app.example.com"
    )


def test_untrusted_origin_is_not_allowed(
    client: TestClient,
) -> None:
    response = client.options(
        "/profile",
        headers={
            "Origin": "https://malicious.example",
            "Access-Control-Request-Method": "PATCH",
        },
    )

    assert response.headers.get(
        "Access-Control-Allow-Origin"
    ) != "https://malicious.example"
```

Do not test only successful origins; verify that unknown origins are denied.

## 21. Test Rate Limiting

```python name=tests/security/test_rate_limit.py
from fastapi.testclient import TestClient


def test_login_rate_limit(
    client: TestClient,
) -> None:
    credentials = {
        "email": "alice@example.com",
        "password": "incorrect-password",
    }

    responses = [
        client.post("/auth/login", json=credentials)
        for _ in range(6)
    ]

    assert responses[-1].status_code == 429
    assert "Retry-After" in responses[-1].headers
```

Use an isolated rate-limit store and reset it between tests.

## 22. Test Idempotency

```python name=tests/integration/test_idempotency.py
from fastapi.testclient import TestClient


def test_repeated_order_request_returns_same_result(
    authenticated_client: TestClient,
) -> None:
    headers = {
        "Idempotency-Key": "test-key-1234567890",
    }
    payload = {
        "product_id": 10,
        "quantity": 1,
    }

    first = authenticated_client.post(
        "/orders",
        headers=headers,
        json=payload,
    )
    second = authenticated_client.post(
        "/orders",
        headers=headers,
        json=payload,
    )

    assert first.status_code == 201
    assert second.status_code in {200, 201}
    assert first.json()["id"] == second.json()["id"]
```

Also verify that reusing a key with a different payload is rejected.

## 23. Performance Testing

A small `k6` test can measure basic throughput and latency.

```javascript name=tests/performance/health.js
import http from "k6/http";
import { check } from "k6";

export const options = {
  vus: 10,
  duration: "30s",
  thresholds: {
    http_req_failed: ["rate<0.01"],
    http_req_duration: ["p(95)<250"],
  },
};

export default function () {
  const response = http.get(
    `${__ENV.BASE_URL}/health/live`,
  );

  check(response, {
    "status is 200": (result) => result.status === 200,
  });
}
```

Run it against a controlled non-production environment:

```bash name=run-performance-test.sh
BASE_URL=https://staging.example.com k6 run tests/performance/health.js
```

Use synthetic test accounts and data. Do not load-test production without explicit approval and safeguards.

## Key Points

- Test business logic independently from HTTP routes.
- Use a dedicated test database and synthetic credentials.
- Override dependencies and clear overrides after each test.
- Test denied access as thoroughly as successful access.
- Cover validation boundaries, ownership, and tenant isolation.
- Mock external services and test their failure modes.
- Validate response contracts and OpenAPI changes.
- Test CSRF, CORS, uploads, rate limits, and idempotency.
- Run performance tests only in approved environments.
- Use coverage as a guide, not as the sole quality measure.
