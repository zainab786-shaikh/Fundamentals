
# Topic 16: Pagination, Filtering, Searching, and Sorting

These features let clients retrieve specific records without loading an entire database table.

---

## 1. Why Pagination Is Required

Returning every record can cause:

- Slow database queries
- High memory usage
- Large responses
- API timeouts
- Service abuse

Pagination returns records in smaller groups.

---

## 2. Offset Pagination

Offset pagination uses `page` and `page_size`.

```python name=app/routers/products.py
from fastapi import APIRouter, Query

router = APIRouter(prefix="/products", tags=["Products"])


@router.get("")
def list_products(
    page: int = Query(default=1, ge=1),
    page_size: int = Query(default=20, ge=1, le=100),
) -> dict[str, int]:
    offset = (page - 1) * page_size

    return {
        "page": page,
        "page_size": page_size,
        "offset": offset,
    }
```

Example:

```text name=offset-request.txt
GET /products?page=2&page_size=20
```

This skips the first 20 records and returns the next 20.

---

## 3. SQLAlchemy Offset Pagination

```python name=app/repositories/product_repository.py
from sqlalchemy import select
from sqlalchemy.orm import Session

from app.models.product import Product


def list_products(
    db: Session,
    page: int,
    page_size: int,
) -> list[Product]:
    statement = (
        select(Product)
        .order_by(Product.id)
        .offset((page - 1) * page_size)
        .limit(page_size)
    )

    return list(db.scalars(statement).all())
```

Always use `order_by()` so pagination produces a predictable order.

Large offsets can become slow because the database must skip many rows.

## 5. Count Total Records

```python name=app/repositories/product_repository.py
from sqlalchemy import func, select
from sqlalchemy.orm import Session

from app.models.product import Product


def count_products(db: Session) -> int:
    statement = select(func.count()).select_from(Product)
    return db.scalar(statement) or 0
```

Counting a very large or complex result can be expensive. Return a total only when the client needs it.

## 6. Cursor Pagination

Cursor pagination retrieves records after a known value.

```python name=app/routers/products.py
from fastapi import Query
from sqlalchemy import select

from app.dependencies import DatabaseSession
from app.models.product import Product


@router.get("/cursor")
def list_products_by_cursor(
    db: DatabaseSession,
    after_id: int | None = Query(default=None, ge=1),
    limit: int = Query(default=20, ge=1, le=100),
) -> dict[str, object]:
    statement = select(Product).order_by(Product.id).limit(limit + 1)

    if after_id is not None:
        statement = statement.where(Product.id > after_id)

    products = list(db.scalars(statement).all())
    has_more = len(products) > limit
    items = products[:limit]

    return {
        "items": items,
        "next_cursor": items[-1].id if has_more and items else None,
        "has_more": has_more,
    }
```

Cursor pagination performs better for large or frequently changing datasets.

---

## 7. Offset vs Cursor Pagination

| Type | Advantage | Limitation |
|---|---|---|
| Offset | Simple and supports page numbers | Large offsets may be slow |
| Cursor | Efficient and stable for changing data | Cannot easily jump to a page |
| Keyset | Fast using indexed sort values | Requires stable ordering |

Use offset pagination for small administrative lists. Use cursor pagination for feeds and large datasets.

## 8. Filtering

Filtering returns records matching specified conditions.

```python name=app/routers/products.py
from decimal import Decimal

from fastapi import Query


@router.get("/filtered")
def filter_products(
    category: str | None = Query(default=None, max_length=50),
    in_stock: bool | None = None,
    minimum_price: Decimal | None = Query(default=None, ge=0),
    maximum_price: Decimal | None = Query(default=None, ge=0),
) -> dict[str, object]:
    return {
        "category": category,
        "in_stock": in_stock,
        "minimum_price": minimum_price,
        "maximum_price": maximum_price,
    }
```

Example:

```text name=filter-request.txt
GET /products/filtered?category=electronics&in_stock=true&minimum_price=20
```

Validate ranges and lengths before querying the database.

## 9. Dynamic SQLAlchemy Filters

```python name=app/repositories/product_repository.py
from decimal import Decimal

from sqlalchemy import select
from sqlalchemy.orm import Session

from app.models.product import Product


def filter_products(
    db: Session,
    category: str | None,
    in_stock: bool | None,
    minimum_price: Decimal | None,
) -> list[Product]:
    statement = select(Product)

    if category is not None:
        statement = statement.where(Product.category == category)

    if in_stock is not None:
        statement = statement.where(Product.in_stock == in_stock)

    if minimum_price is not None:
        statement = statement.where(Product.price >= minimum_price)

    statement = statement.order_by(Product.id).limit(100)

    return list(db.scalars(statement).all())
```

SQLAlchemy parameterizes values, protecting the query from SQL injection.

## 10. Validate Related Filter Values

```python name=app/schemas/product_filters.py
from decimal import Decimal

from pydantic import BaseModel, model_validator


class ProductFilters(BaseModel):
    minimum_price: Decimal | None = None
    maximum_price: Decimal | None = None

    @model_validator(mode="after")
    def validate_price_range(self) -> "ProductFilters":
        if (
            self.minimum_price is not None
            and self.maximum_price is not None
            and self.minimum_price > self.maximum_price
        ):
            raise ValueError(
                "minimum_price cannot exceed maximum_price"
            )

        return self
```

Cross-field validation rejects impossible ranges before running a query.

## 12. SQLAlchemy Text Search

```python name=app/repositories/product_repository.py
from sqlalchemy import select
from sqlalchemy.orm import Session

from app.models.product import Product


def search_products(
    db: Session,
    query: str,
) -> list[Product]:
    search_value = f"%{query}%"

    statement = (
        select(Product)
        .where(Product.name.ilike(search_value))
        .order_by(Product.name, Product.id)
        .limit(50)
    )

    return list(db.scalars(statement).all())
```

SQLAlchemy safely parameterizes the search term. For large datasets, use PostgreSQL full-text search or a dedicated search engine.

## 13. Escape Wildcard Characters

In SQL `LIKE` searches, `%` and `_` are wildcard characters.

```python name=app/repositories/search_helpers.py
def escape_like(value: str) -> str:
    return (
        value.replace("\\", "\\\\")
        .replace("%", "\\%")
        .replace("_", "\\_")
    )
```

```python name=app/repositories/product_repository.py
search_value = f"%{escape_like(query)}%"

statement = select(Product).where(
    Product.name.ilike(search_value, escape="\\")
)
```

Escaping ensures `%` and `_` are treated as ordinary characters when literal matching is intended.

## 14. Sorting with an Allow-List

Never place an arbitrary client value directly into an SQL `ORDER BY` clause.

```python name=app/repositories/product_repository.py
from typing import Literal

from sqlalchemy import asc, desc, select

SortField = Literal["name", "price", "created_at"]
SortOrder = Literal["asc", "desc"]


def sorted_products(
    sort_by: SortField,
    order: SortOrder,
):
    allowed_columns = {
        "name": Product.name,
        "price": Product.price,
        "created_at": Product.created_at,
    }

    column = allowed_columns[sort_by]
    direction = asc if order == "asc" else desc

    return select(Product).order_by(direction(column), Product.id)
```

The allow-list prevents invalid column access and unsafe dynamic SQL.

---

## 15. Stable Sorting

Always add a unique secondary sort field.

```python name=app/repositories/product_repository.py
statement = select(Product).order_by(
    Product.created_at.desc(),
    Product.id.desc(),
)
```

Many products may have the same creation time. Sorting by `id` as well prevents unpredictable ordering between requests.

## 16. Combined Endpoint

```python name=app/routers/products.py
from typing import Literal

from fastapi import Query
from sqlalchemy import asc, desc, func, select

from app.dependencies import DatabaseSession
from app.models.product import Product


@router.get("/list")
def list_products(
    db: DatabaseSession,
    page: int = Query(default=1, ge=1),
    page_size: int = Query(default=20, ge=1, le=100),
    category: str | None = Query(default=None, max_length=50),
    search: str | None = Query(default=None, min_length=2, max_length=100),
    sort_by: Literal["name", "price", "created_at"] = "name",
    order: Literal["asc", "desc"] = "asc",
) -> dict[str, object]:
    allowed_columns = {
        "name": Product.name,
        "price": Product.price,
        "created_at": Product.created_at,
    }

    conditions = []

    if category is not None:
        conditions.append(Product.category == category)

    if search is not None:
        conditions.append(Product.name.ilike(f"%{escape_like(search)}%", escape="\\"))

    sort_column = allowed_columns[sort_by]
    sort_direction = asc if order == "asc" else desc

    data_statement = (
        select(Product)
        .where(*conditions)
        .order_by(sort_direction(sort_column), Product.id)
        .offset((page - 1) * page_size)
        .limit(page_size)
    )

    count_statement = (
        select(func.count())
        .select_from(Product)
        .where(*conditions)
    )

    products = list(db.scalars(data_statement).all())
    total = db.scalar(count_statement) or 0

    return {
        "items": products,
        "page": page,
        "page_size": page_size,
        "total": total,
    }
```

The endpoint combines validated pagination, filtering, searching, and sorting.

## 17. Index Frequently Queried Columns

```python name=app/models/product.py
from datetime import datetime
from decimal import Decimal

from sqlalchemy import DateTime, Index, Numeric, String
from sqlalchemy.orm import Mapped, mapped_column

from app.database import Base


class Product(Base):
    __tablename__ = "products"
    __table_args__ = (
        Index("ix_products_category_created", "category", "created_at"),
    )

    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(100), index=True)
    category: Mapped[str] = mapped_column(String(50))
    price: Mapped[Decimal] = mapped_column(Numeric(10, 2))
    created_at: Mapped[datetime] = mapped_column(DateTime(timezone=True))
```

Indexes improve filtering and sorting but consume storage and slightly slow writes. Create indexes based on real query patterns.

---

## 18. Prevent Expensive Queries

Apply these protections:

- Maximum page size
- Maximum search length
- Allow-listed filters and sort fields
- Query timeouts
- Appropriate database indexes
- Rate limiting
- Limited date ranges
- Maximum exported records

Do not allow clients to request unlimited records.

## Key Points

- Always paginate collection endpoints.
- Enforce a maximum page size.
- Use stable, deterministic ordering.
- Prefer cursor pagination for large or changing datasets.
- Validate and allow-list filters and sort fields.
- Use parameterized queries.
- Index frequently filtered and sorted columns.
- Limit expensive searches and total-count operations.
- Test edge cases and invalid query parameters.
