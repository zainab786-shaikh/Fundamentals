
# Topic 6: CORS Fundamentals

**CORS (Cross-Origin Resource Sharing)** allows an API to specify which browser origins may access its responses.

## 1. When Is CORS Required?

CORS is required when the frontend and API have different origins:

```text name=origins.txt
Frontend: http://localhost:3000
API:      http://localhost:8000
```

The ports differ, so these are separate origins.

---

## 2. Configure CORS in FastAPI

```python name=app/main.py
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

app = FastAPI()

app.add_middleware(
    CORSMiddleware,
    allow_origins=[
        "http://localhost:3000",
        "https://app.example.com",
    ],
    allow_credentials=True,
    allow_methods=["GET", "POST", "PATCH", "DELETE"],
    allow_headers=["Authorization", "Content-Type"],
)


@app.get("/users")
def list_users() -> list[dict[str, object]]:
    return [{"id": 1, "name": "Alice"}]
```

Only the listed browser origins, methods, and headers are allowed.

---

## 3. Allowed Origins

An origin includes its scheme, host, and port.

```python name=app/cors_config.py
ALLOWED_ORIGINS = [
    "https://app.example.com",
    "https://admin.example.com",
]
```

These are different origins:

```text name=origin-comparison.txt
https://app.example.com
http://app.example.com
https://app.example.com:8443
```

Use an explicit allow-list instead of accepting every origin.

---

## 4. `Access-Control-Allow-Origin`

For an allowed request, the API returns a header similar to:

```http name=cors-response.http
HTTP/1.1 200 OK
Access-Control-Allow-Origin: https://app.example.com
Content-Type: application/json
```

The browser checks this header before allowing frontend JavaScript to read the response.

---

## 5. Allowed Methods

```python name=app/main.py
app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://app.example.com"],
    allow_methods=["GET", "POST"],
)
```

This permits only `GET` and `POST` cross-origin requests.

Allow only methods required by the frontend.

---

## 6. Allowed Headers

```python name=app/main.py
app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://app.example.com"],
    allow_methods=["GET", "POST"],
    allow_headers=["Authorization", "Content-Type"],
)
```

This allows the browser to send:

- `Authorization`: Bearer token
- `Content-Type`: Body format

Avoid permitting unnecessary custom headers.

---

## 7. Credentialed Requests

Credentials can include cookies or browser authentication information.

```python name=app/main.py
app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://app.example.com"],
    allow_credentials=True,
    allow_methods=["GET", "POST"],
    allow_headers=["Content-Type"],
)
```

Frontend cookie request:

```javascript name=frontend.js
const response = await fetch("https://api.example.com/profile", {
  credentials: "include",
});
```

When using cross-site cookies, configure them securely with `HttpOnly`, `Secure`, and an appropriate `SameSite` policy. Cookie-based authentication also requires CSRF protection.

---

## 8. Wildcard Origins

```python name=app/main.py
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_methods=["GET"],
    allow_headers=[],
)
```

`"*"` permits browser requests from any origin.

Use it only for intentionally public APIs that do not use credentials or expose private information. Prefer explicit trusted origins.

---

## 9. Exposed Response Headers

JavaScript cannot access every response header automatically. Use `expose_headers` for headers the frontend needs:

```python name=app/main.py
app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://app.example.com"],
    allow_methods=["GET"],
    allow_headers=[],
    expose_headers=["X-Request-ID"],
)
```

Frontend example:

```javascript name=frontend.js
const response = await fetch("https://api.example.com/users");
const requestId = response.headers.get("X-Request-ID");
```

Expose only necessary non-sensitive headers.

---

## 10. Preflight Cache Duration

```python name=app/main.py
app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://app.example.com"],
    allow_methods=["GET", "POST", "PATCH", "DELETE"],
    allow_headers=["Authorization", "Content-Type"],
    max_age=600,
)
```

`max_age=600` allows the browser to cache a successful preflight result for 10 minutes.

## 11. Environment-Based Origins

```python name=app/config.py
from pydantic_settings import BaseSettings


class Settings(BaseSettings):
    cors_origins: list[str] = []


settings = Settings()
```

```python name=app/main.py
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

from app.config import settings

app = FastAPI()

app.add_middleware(
    CORSMiddleware,
    allow_origins=settings.cors_origins,
    allow_credentials=True,
    allow_methods=["GET", "POST", "PATCH", "DELETE"],
    allow_headers=["Authorization", "Content-Type"],
)
```

Example environment configuration:

```text name=.env.example
CORS_ORIGINS=["http://localhost:3000","https://app.example.com"]
```

Environment-based configuration keeps development and production origins separate.

---

## 12. CORS Is Not Access Control

CORS controls which browser origins may read responses. It does not verify users or permissions.

```python name=app/routers/admin.py
from fastapi import Depends, HTTPException, status


def require_admin() -> None:
    is_admin = False

    if not is_admin:
        raise HTTPException(
            status_code=status.HTTP_403_FORBIDDEN,
            detail="Insufficient permission",
        )


@app.get("/admin", dependencies=[Depends(require_admin)])
def admin_area() -> dict[str, str]:
    return {"message": "Authorized"}
```

Every protected endpoint still requires authentication and authorization.

## Key Points

- Use exact trusted origins.
- Allow only required methods and headers.
- Be careful with credentialed requests.
- Avoid wildcard origins for private APIs.
- CORS is enforced by browsers.
- CORS does not replace authentication, authorization, or CSRF protection.
