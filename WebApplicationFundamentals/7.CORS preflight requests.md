
# Topic 7: CORS Preflight Requests

A **preflight request** is an automatic `OPTIONS` request sent by a browser to check whether a cross-origin request is permitted.

## 1. Why Preflight Is Needed

Suppose the frontend sends:

```javascript name=frontend.js
await fetch("https://api.example.com/users/1", {
  method: "PATCH",
  headers: {
    Authorization: "Bearer access-token",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({ name: "Alice Smith" }),
});
```

Because it uses `PATCH`, JSON, and an `Authorization` header, the browser normally sends a preflight request first.

---

## 2. Preflight Request Flow

```text name=preflight-flow.txt
Browser → OPTIONS preflight request → API
Browser ← CORS permission response ← API

If permitted:

Browser → Actual PATCH request → API
Browser ← Actual response ← API
```

The browser sends the actual request only if the preflight response permits it.

---

## 3. Example Preflight Request

```http name=preflight-request.http
OPTIONS /users/1 HTTP/1.1
Host: api.example.com
Origin: https://app.example.com
Access-Control-Request-Method: PATCH
Access-Control-Request-Headers: authorization, content-type
```

Important headers:

- `Origin`: Frontend making the request
- `Access-Control-Request-Method`: Intended HTTP method
- `Access-Control-Request-Headers`: Intended request headers

---

## 4. Successful Preflight Response

```http name=preflight-response.http
HTTP/1.1 200 OK
Access-Control-Allow-Origin: https://app.example.com
Access-Control-Allow-Methods: GET, POST, PATCH, DELETE
Access-Control-Allow-Headers: Authorization, Content-Type
Access-Control-Allow-Credentials: true
Access-Control-Max-Age: 600
```

The browser confirms that the origin, method, headers, and credential policy are permitted.

---

## 5. Configure Preflight Handling in FastAPI

```python name=app/main.py
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

app = FastAPI()

app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://app.example.com"],
    allow_credentials=True,
    allow_methods=["GET", "POST", "PATCH", "DELETE"],
    allow_headers=["Authorization", "Content-Type"],
    expose_headers=["X-Request-ID"],
    max_age=600,
)
```

`CORSMiddleware` automatically handles valid preflight `OPTIONS` requests. You normally should not create separate `OPTIONS` routes.

---

## 6. Simple Requests

A browser may skip preflight when the request meets all “simple request” conditions.

A typical example is:

```javascript name=simple-request.js
await fetch("https://api.example.com/products", {
  method: "GET",
});
```

Simple requests generally use:

- `GET`, `HEAD`, or `POST`
- Only CORS-safelisted headers
- A safelisted content type, when applicable

The response still requires a valid `Access-Control-Allow-Origin` header.

---

## 7. Requests That Commonly Trigger Preflight

Preflight is commonly triggered by:

- `PUT`, `PATCH`, or `DELETE`
- `Authorization` headers
- Custom headers such as `X-Request-ID`
- `Content-Type: application/json`
- Other request features outside the CORS safelist

```javascript name=preflight-trigger.js
await fetch("https://api.example.com/orders/10", {
  method: "DELETE",
  headers: {
    Authorization: "Bearer access-token",
  },
});
```

The browser decides whether preflight is required—not the frontend developer or FastAPI endpoint.

---

## 8. Preflight with Credentials

Frontend:

```javascript name=credential-request.js
await fetch("https://api.example.com/profile", {
  method: "PATCH",
  credentials: "include",
  headers: {
    "Content-Type": "application/json",
  },
  body: JSON.stringify({ language: "en" }),
});
```

API configuration:

```python name=app/main.py
app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://app.example.com"],
    allow_credentials=True,
    allow_methods=["PATCH"],
    allow_headers=["Content-Type"],
)
```

Use a specific origin when credentials are allowed. Cookie authentication also requires secure cookie settings and CSRF protection.

---

## 9. Preflight Caching

```python name=app/main.py
app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://app.example.com"],
    allow_methods=["GET", "POST", "PATCH", "DELETE"],
    allow_headers=["Authorization", "Content-Type"],
    max_age=600,
)
```

`max_age=600` lets the browser cache successful preflight permission for up to 10 minutes, reducing repeated `OPTIONS` requests.

The browser controls whether and how long the result is actually cached.

---

## 10. Common Failure: Origin Not Allowed

Configuration:

```python name=app/main.py
allow_origins=["https://admin.example.com"]
```

Request origin:

```text name=request-origin.txt
https://app.example.com
```

These values do not match, so the browser blocks access.

Origins must match exactly, including:

- Scheme
- Host
- Port

---

## 11. Common Failure: Method Not Allowed

```python name=app/main.py
app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://app.example.com"],
    allow_methods=["GET", "POST"],
    allow_headers=["Content-Type"],
)
```

A frontend `DELETE` request fails because `DELETE` is not allowed.

Add it only if the frontend genuinely requires it:

```python name=app/main.py
allow_methods=["GET", "POST", "DELETE"]
```

---

## 12. Common Failure: Header Not Allowed

```javascript name=frontend.js
await fetch("https://api.example.com/profile", {
  headers: {
    Authorization: "Bearer access-token",
  },
});
```

The preflight fails if `Authorization` is absent from `allow_headers`.

```python name=app/main.py
allow_headers=["Authorization", "Content-Type"]
```

Header names are case-insensitive, but listing them consistently improves clarity.

---

## 13. Common Failure: Authentication Blocks `OPTIONS`

Incorrect security logic may require authentication for every request, including preflight:

```python name=app/middleware/auth.py
if request.method != "OPTIONS" and not authorization_header:
    return unauthorized_response
```

Preflight requests normally do not contain the user’s bearer token. CORS middleware should process preflight before endpoint authentication.

Do not treat a successful preflight as user authentication; authenticate the actual request.

---

## 14. Common Failure: HTTP Redirect

A preflight request may fail if an HTTP endpoint redirects to HTTPS or a route redirects because of a trailing slash.

```text name=redirect-example.txt
Requested:  https://api.example.com/users
Redirected: https://api.example.com/users/
```

Use the exact final HTTPS URL from the frontend and configure routes consistently to avoid relying on preflight redirects.

---

## 15. Testing a Preflight Request

```bash name=test-preflight.sh
curl -i -X OPTIONS "https://api.example.com/users/1" \
  -H "Origin: https://app.example.com" \
  -H "Access-Control-Request-Method: PATCH" \
  -H "Access-Control-Request-Headers: authorization,content-type"
```

Check that the response allows:

- `https://app.example.com`
- `PATCH`
- `Authorization`
- `Content-Type`

`curl` does not enforce CORS, but it can display the server’s preflight response headers.

---

## Key Points

- The browser automatically sends preflight requests.
- A preflight uses the `OPTIONS` method.
- It checks the origin, intended method, headers, and credentials policy.
- FastAPI’s `CORSMiddleware` should handle preflight automatically.
- Preflight permission is not authentication or authorization.
- Exact origin, method, and header configuration prevents most failures.
