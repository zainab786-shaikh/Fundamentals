
# Topic 5: Browser Same-Origin Policy

The **Same-Origin Policy (SOP)** is a browser security rule. It prevents a website from reading data from a different origin unless the target server explicitly allows it through CORS.

## 1. What Is an Origin?

An origin consists of:

```text name=origin-components.txt
scheme + host + port
```

Example:

```text name=origin-example.txt
https://app.example.com:443
└https┘ └────host─────┘ port
```

Paths and query strings are not part of the origin.

---

## 2. Same-Origin Request

These URLs have the same scheme, host, and port:

```text name=same-origin.txt
Page: https://app.example.com/dashboard
API:  https://app.example.com/api/users
```

The browser allows this request because both URLs have the same origin.

```javascript name=request.js
const response = await fetch("/api/users");
const users = await response.json();
```

A relative URL uses the page’s current origin.

---

## 3. Cross-Origin Request

These URLs have different hosts:

```text name=cross-origin.txt
Frontend: https://app.example.com
API:      https://api.example.com
```

Even though both belong to `example.com`, they are different origins because their hosts differ.

```javascript name=request.js
const response = await fetch("https://api.example.com/users");
const users = await response.json();
```

The API must return appropriate CORS headers before the browser allows JavaScript to read the response.

---

## 4. Different Schemes

These URLs have different origins:

```text name=different-schemes.txt
http://app.example.com
https://app.example.com
```

`http` and `https` are different schemes. Production applications should use HTTPS only.

---

## 5. Different Ports

These URLs also have different origins:

```text name=different-ports.txt
http://localhost:3000
http://localhost:8000
```

This is common during development:

- Frontend: port `3000`
- FastAPI: port `8000`

CORS configuration is required because the ports differ.

---

## 6. Paths Do Not Change the Origin

These URLs have the same origin:

```text name=same-origin-paths.txt
https://example.com/users
https://example.com/products
https://example.com/api/orders?page=1
```

Different paths and query parameters do not create different origins.

---

## 7. Why the Same-Origin Policy Exists

Suppose a user is logged in to:

```text name=bank-origin.txt
https://bank.example.com
```

A malicious page should not be able to read the user’s private bank data:

```javascript name=malicious-request.js
const response = await fetch("https://bank.example.com/accounts");
const privateData = await response.json();
```

The browser blocks JavaScript from reading the response unless the bank explicitly permits the malicious origin.

SOP protects users from unauthorized cross-origin data access.

---

## 8. Browser Request versus Response Access

A cross-origin request may still reach the server. The browser can block JavaScript from accessing the response.

```text name=browser-cors-flow.txt
Browser sends request
        ↓
Server processes request
        ↓
Server returns response
        ↓
Browser checks CORS headers
        ↓
JavaScript receives or is denied access
```

CORS is enforced mainly by browsers, not by FastAPI business logic.

Therefore, CORS must not replace authentication or authorization.

---

## 9. Server-to-Server Requests

The Same-Origin Policy does not normally apply to server-side HTTP clients.

```python name=server_request.py
import httpx


async def get_users() -> list[dict[str, object]]:
    async with httpx.AsyncClient(timeout=5.0) as client:
        response = await client.get("https://api.example.com/users")
        response.raise_for_status()
        return response.json()
```

Server-to-server requests can call other origins without browser CORS restrictions.

The server must still use authentication, HTTPS, strict URL allow-lists, and timeouts.

---

## 10. Postman and Command-Line Clients

Tools such as API clients and `curl` are not browsers, so they generally do not enforce browser CORS rules.

```bash name=test-api.sh
curl --fail-with-body https://api.example.com/users
```

An API may work in `curl` but fail in a browser because of incorrect CORS configuration.

---

## 11. Same-Origin Policy Is Not Authentication

CORS answers:

> Which browser origins may read this API response?

Authentication answers:

> Who is making this request?

Authorization answers:

> Is this user allowed to perform this action?

```text name=security-layers.txt
CORS           → Controls permitted browser origins
Authentication → Verifies user identity
Authorization  → Verifies user permissions
```

A permitted origin does not mean every user from that origin should receive access.

---

## 12. Common Browser Error

A browser may display an error similar to:

```text name=cors-error.txt
Access to fetch at 'https://api.example.com/users'
from origin 'https://app.example.com' has been blocked
by CORS policy.
```

Common causes:

- The frontend origin is not allowed.
- The API omitted CORS response headers.
- The requested method is not allowed.
- A custom header is not allowed.
- Credentials are used with an invalid CORS configuration.
- The preflight `OPTIONS` request failed.
- The frontend is calling the wrong API URL.

## Key Points

- An origin is **scheme + host + port**.
- A difference in any component creates a cross-origin request.
- Browsers enforce the Same-Origin Policy.
- Paths do not affect the origin.
- CORS can permit selected cross-origin browser access.
- CORS is not authentication or authorization.
- Server-side tools generally do not enforce browser CORS restrictions.
