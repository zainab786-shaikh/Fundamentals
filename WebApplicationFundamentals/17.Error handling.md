
# Topic 17: Error Handling and Consistent API Responses

Error handling should return clear, predictable, and safe responses without exposing internal details.

## 1. Standard Error Structure

Use the same format for all errors:

```json name=error-response.json
{
  "error": {
    "code": "user_not_found",
    "message": "User not found",
    "request_id": "req-123"
  }
}
```

- `code`: Stable identifier for client logic
- `message`: Safe, readable explanation
- `request_id`: Connects the response to server logs

---

## 2. Define an Application Exception

```python name=app/exceptions.py
class ApplicationError(Exception):
    def __init__(
        self,
        code: str,
        message: str,
        status_code: int,
    ) -> None:
        self.code = code
        self.message = message
        self.status_code = status_code
        super().__init__(message)
```

A custom exception keeps business errors consistent.

## 3. Raise a Business Error

```python name=app/services/user_service.py
from app.exceptions import ApplicationError


def get_user(user_id: int) -> dict[str, object]:
    user = None  # Replace with a database query.

    if user is None:
        raise ApplicationError(
            code="user_not_found",
            message="User not found",
            status_code=404,
        )

    return user
```

The service reports what failed without managing the HTTP response directly.

## 4. Central Exception Handler

```python name=app/main.py
from uuid import uuid4

from fastapi import FastAPI, Request
from fastapi.responses import JSONResponse

from app.exceptions import ApplicationError

app = FastAPI(debug=False)


@app.exception_handler(ApplicationError)
async def handle_application_error(
    request: Request,
    exception: ApplicationError,
) -> JSONResponse:
    request_id = request.headers.get("X-Request-ID") or str(uuid4())

    return JSONResponse(
        status_code=exception.status_code,
        content={
            "error": {
                "code": exception.code,
                "message": exception.message,
                "request_id": request_id,
            }
        },
    )
```

The handler converts application exceptions into a standard JSON response.

## 5. Handle Validation Errors

FastAPI raises `RequestValidationError` for invalid request data.

```python name=app/main.py
from fastapi.exceptions import RequestValidationError


@app.exception_handler(RequestValidationError)
async def handle_validation_error(
    request: Request,
    exception: RequestValidationError,
) -> JSONResponse:
    request_id = request.headers.get("X-Request-ID") or str(uuid4())

    return JSONResponse(
        status_code=422,
        content={
            "error": {
                "code": "validation_failed",
                "message": "Request validation failed",
                "details": exception.errors(),
                "request_id": request_id,
            }
        },
    )
```

Field details help clients correct invalid input. Ensure rejected values do not expose secrets.

## 6. Handle Unexpected Errors Safely

```python name=app/main.py
import logging

logger = logging.getLogger(__name__)


@app.exception_handler(Exception)
async def handle_unexpected_error(
    request: Request,
    exception: Exception,
) -> JSONResponse:
    request_id = request.headers.get("X-Request-ID") or str(uuid4())

    logger.exception(
        "Unexpected API error request_id=%s path=%s",
        request_id,
        request.url.path,
    )

    return JSONResponse(
        status_code=500,
        content={
            "error": {
                "code": "internal_error",
                "message": "Internal server error",
                "request_id": request_id,
            }
        },
    )
```

Log the technical error on the server, but return a generic message to the client.

Never expose:

- Stack traces
- SQL statements
- File-system paths
- Connection strings
- Tokens or secrets

## 7. Roll Back Database Failures

```python name=app/services/product_service.py
import logging

from sqlalchemy.exc import IntegrityError, SQLAlchemyError
from sqlalchemy.orm import Session

from app.exceptions import ApplicationError

logger = logging.getLogger(__name__)


def create_product(db: Session, product: object) -> object:
    try:
        db.add(product)
        db.commit()
        db.refresh(product)
        return product

    except IntegrityError:
        db.rollback()
        raise ApplicationError(
            code="product_conflict",
            message="Product already exists",
            status_code=409,
        ) from None

    except SQLAlchemyError:
        db.rollback()
        logger.exception("Database operation failed")

        raise ApplicationError(
            code="database_error",
            message="Unable to complete the request",
            status_code=500,
        ) from None
```

Always call `rollback()` after a failed transaction before reusing the session.

## 8. Choose the Correct Status Code

| Code | Use |
|---:|---|
| `400` | Invalid request logic |
| `401` | Missing or invalid authentication |
| `403` | Insufficient permission |
| `404` | Resource not found |
| `409` | Duplicate or state conflict |
| `422` | Request validation failed |
| `429` | Rate limit exceeded |
| `500` | Unexpected server error |
| `503` | Dependency temporarily unavailable |

Correct status codes help clients decide whether to correct, retry, or abandon a request.

## 9. Do Not Catch Every Error Locally

Avoid repeating error handling in every route:

```python name=app/routers/users.py
@router.get("/{user_id}")
def get_user(user_id: int) -> dict[str, object]:
    return user_service.get_user(user_id)
```

Let central exception handlers produce the response. This keeps routes short and consistent.

## 10. Add Request IDs to Responses

```python name=app/middleware/request_id.py
from uuid import uuid4

from fastapi import Request, Response


async def request_id_middleware(
    request: Request,
    call_next,
) -> Response:
    request_id = request.headers.get("X-Request-ID") or str(uuid4())
    response = await call_next(request)
    response.headers["X-Request-ID"] = request_id
    return response
```

Register it:

```python name=app/main.py
app.middleware("http")(request_id_middleware)
```

Request IDs make production troubleshooting easier. Validate client-provided IDs before including them in logs.

## 11. Test Error Responses

```python name=tests/test_errors.py
from fastapi.testclient import TestClient


def test_missing_user_returns_standard_error(
    client: TestClient,
) -> None:
    response = client.get("/users/999")
    body = response.json()

    assert response.status_code == 404
    assert body["error"]["code"] == "user_not_found"
    assert body["error"]["message"] == "User not found"
    assert "request_id" in body["error"]
```

Test expected errors, validation failures, database conflicts, and unexpected failures.

## Key Points

- Use one consistent error-response structure.
- Return correct HTTP status codes.
- Handle exceptions centrally.
- Roll back failed database transactions.
- Log internal errors without logging secrets.
- Never expose stack traces in production.
- Include request IDs for troubleshooting.
- Test both successful and failed requests.
