
# Topic 9: Token-Based Authentication

Token authentication lets a client access protected APIs without sending a username and password with every request.

## 1. Basic Token Flow

```text name=token-flow.txt
User signs in
    ↓
Server verifies credentials
    ↓
Server returns access and refresh tokens
    ↓
Client sends access token to API
    ↓
Server validates token
```

Always use HTTPS because tokens must be protected in transit.

---

## 2. Access Token

An access token grants short-term access to protected endpoints.

```http name=profile-request.http
GET /profile HTTP/1.1
Host: api.example.com
Authorization: Bearer access-token
```

Access tokens should:

- Expire quickly, commonly within several minutes
- Have limited permissions
- Never appear in URLs or logs
- Be validated on every protected request

---

## 3. Refresh Token

A refresh token obtains a new access token without requiring another login.

```text name=token-lifetimes.txt
Access token  → Short lifetime; used with API requests
Refresh token → Longer lifetime; used only to renew access
```

Refresh tokens are more sensitive because they remain valid longer. Store them securely and support revocation and rotation.

---

## 4. JWT Structure

A JSON Web Token has three Base64URL-encoded sections:

```text name=jwt-structure.txt
header.payload.signature
```

Example payload:

```json name=jwt-payload.json
{
  "sub": "123",
  "iss": "https://auth.example.com",
  "aud": "store-api",
  "exp": 1792900800,
  "iat": 1792899900,
  "jti": "79044315-ad8c-476e-baf8-d476c4c8fd12"
}
```

Common claims:

| Claim | Purpose |
|---|---|
| `sub` | User or subject identifier |
| `iss` | Token issuer |
| `aud` | Intended API |
| `exp` | Expiration time |
| `iat` | Issued-at time |
| `jti` | Unique token identifier |

JWT content is encoded, not encrypted. Never place passwords, secrets, or unnecessary personal data inside it.

## 6. Token Configuration

```python name=app/config.py
from pydantic import SecretStr
from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    jwt_secret: SecretStr
    jwt_issuer: str = "https://auth.example.com"
    jwt_audience: str = "store-api"
    jwt_algorithm: str = "HS256"
    access_token_minutes: int = 15

    model_config = SettingsConfigDict(
        env_file=".env",
        extra="ignore",
    )


settings = Settings()
```

```text name=.env.example
JWT_SECRET=replace-with-a-long-random-secret
JWT_ISSUER=https://auth.example.com
JWT_AUDIENCE=store-api
JWT_ALGORITHM=HS256
ACCESS_TOKEN_MINUTES=15
```

Store the real signing secret in a secret manager or environment variable. Do not commit it.

## 7. Create an Access Token

```python name=app/security/tokens.py
from datetime import UTC, datetime, timedelta
from uuid import uuid4

import jwt

from app.config import settings


def create_access_token(user_id: int) -> str:
    now = datetime.now(UTC)

    payload = {
        "sub": str(user_id),
        "iss": settings.jwt_issuer,
        "aud": settings.jwt_audience,
        "iat": now,
        "exp": now + timedelta(
            minutes=settings.access_token_minutes,
        ),
        "jti": str(uuid4()),
        "type": "access",
    }

    return jwt.encode(
        payload,
        settings.jwt_secret.get_secret_value(),
        algorithm=settings.jwt_algorithm,
    )
```

The token has a short lifetime, a unique ID, and an explicit token type.

## 8. Validate an Access Token

```python name=app/security/tokens.py
from typing import Any

from jwt.exceptions import InvalidTokenError


def decode_access_token(token: str) -> dict[str, Any]:
    try:
        payload = jwt.decode(
            token,
            settings.jwt_secret.get_secret_value(),
            algorithms=[settings.jwt_algorithm],
            issuer=settings.jwt_issuer,
            audience=settings.jwt_audience,
            options={
                "require": [
                    "sub",
                    "iss",
                    "aud",
                    "iat",
                    "exp",
                    "jti",
                    "type",
                ]
            },
        )
    except InvalidTokenError as error:
        raise ValueError("Invalid or expired token") from error

    if payload["type"] != "access":
        raise ValueError("Incorrect token type")

    return payload
```

Validation checks:

- Signature
- Allowed algorithm
- Issuer
- Audience
- Expiration
- Required claims
- Token type

Never select the accepted algorithm from untrusted token data.

## 9. Authenticate the Current User

```python name=app/dependencies/auth.py
from typing import Annotated

from fastapi import Depends, HTTPException, status
from fastapi.security import OAuth2PasswordBearer
from jwt.exceptions import InvalidTokenError

from app.dependencies import DatabaseSession
from app.models.user import User
from app.security.tokens import decode_access_token

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="/auth/token")


def get_current_user(
    db: DatabaseSession,
    token: Annotated[str, Depends(oauth2_scheme)],
) -> User:
    credentials_error = HTTPException(
        status_code=status.HTTP_401_UNAUTHORIZED,
        detail="Invalid or expired credentials",
        headers={"WWW-Authenticate": "Bearer"},
    )

    try:
        payload = decode_access_token(token)
        user_id = int(payload["sub"])
    except (ValueError, TypeError, InvalidTokenError):
        raise credentials_error from None

    user = db.get(User, user_id)

    if user is None or not user.is_active:
        raise credentials_error

    return user


CurrentUser = Annotated[User, Depends(get_current_user)]
```

The database check ensures that deleted or disabled users cannot continue using an otherwise valid token.

## 10. Protect an Endpoint

```python name=app/routers/profile.py
from fastapi import APIRouter

from app.dependencies.auth import CurrentUser

router = APIRouter(prefix="/profile", tags=["Profile"])


@router.get("")
def get_profile(current_user: CurrentUser) -> dict[str, object]:
    return {
        "id": current_user.id,
        "email": current_user.email,
    }
```

FastAPI rejects the request unless the bearer token is valid and belongs to an active user.

## 11. Create Refresh Tokens

```python name=app/security/refresh_tokens.py
import secrets


def generate_refresh_token() -> str:
    return secrets.token_urlsafe(48)
```

An opaque random refresh token is simpler to revoke than a self-contained JWT refresh token.

Store only its hash in the database:

```python name=app/security/refresh_tokens.py
import hashlib


def hash_refresh_token(token: str) -> str:
    return hashlib.sha256(token.encode("utf-8")).hexdigest()
```

A high-entropy random token may be hashed with SHA-256 because it is generated randomly, unlike a human password.

## 12. Refresh-Token Database Record

```python name=app/models/refresh_token.py
from datetime import datetime

from sqlalchemy import DateTime, ForeignKey, String
from sqlalchemy.orm import Mapped, mapped_column

from app.database import Base


class RefreshToken(Base):
    __tablename__ = "refresh_tokens"

    id: Mapped[int] = mapped_column(primary_key=True)
    token_hash: Mapped[str] = mapped_column(
        String(64),
        unique=True,
        index=True,
    )
    user_id: Mapped[int] = mapped_column(
        ForeignKey("users.id", ondelete="CASCADE"),
        index=True,
    )
    expires_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True),
    )
    revoked_at: Mapped[datetime | None] = mapped_column(
        DateTime(timezone=True),
        default=None,
    )
```

The database tracks expiration and revocation without storing the original refresh token.

## 13. Refresh-Token Rotation

```text name=refresh-rotation.txt
Client sends refresh token A
        ↓
Server invalidates token A
        ↓
Server issues access token and refresh token B
        ↓
Token A cannot be used again
```

Rotation limits damage if a refresh token is stolen. Reuse of an old token should revoke the related token family and require a new login.

---

## 14. Token Revocation

Common reasons to revoke refresh tokens:

- User logs out
- Password is changed
- Account is disabled
- Token reuse is detected
- Device is removed
- Security incident occurs

```python name=app/services/token_service.py
from datetime import UTC, datetime

from sqlalchemy.orm import Session

from app.models.refresh_token import RefreshToken


def revoke_refresh_token(
    db: Session,
    refresh_token: RefreshToken,
) -> None:
    refresh_token.revoked_at = datetime.now(UTC)
    db.commit()
```

Short-lived access tokens commonly remain valid until expiration. Highly sensitive systems may also maintain an access-token deny list.

## 15. Safe Token Storage

### Browser application

Preferred options depend on the architecture:

- Keep short-lived access tokens in memory.
- Store refresh tokens in `HttpOnly`, `Secure` cookies.
- Add CSRF protection when cookies authenticate requests.
- Avoid `localStorage` for long-lived sensitive tokens because injected JavaScript can read it.

### Mobile or desktop application

Use the operating system’s secure credential storage, such as Keychain or a secure keystore.

---

## 16. JWT vs Opaque Tokens

| Type | Advantage | Trade-off |
|---|---|---|
| JWT | API can validate locally | Immediate revocation is harder |
| Opaque token | Easy centralized revocation | Requires server-side lookup |

Use JWTs when distributed validation is useful. Use opaque tokens when simple revocation and central control are more important.

---

## 17. Common Token Mistakes

Avoid:

- Putting tokens in query strings
- Logging tokens
- Using tokens without expiration
- Accepting any signing algorithm
- Skipping issuer or audience validation
- Storing sensitive data in JWT payloads
- Using access tokens as refresh tokens
- Keeping refresh tokens without rotation
- Giving tokens unnecessary permissions

## Key Points

- Access tokens should be short-lived.
- Refresh tokens should be securely stored, rotated, and revocable.
- Validate signature, algorithm, issuer, audience, expiration, and type.
- Recheck user status and permissions when processing protected requests.
- Use HTTPS and never expose tokens through URLs or logs.
- JWT payloads are readable unless separately encrypted.
