
# Topic 4: RESTful API Design

REST organizes an API around **resources**, standard HTTP methods, and predictable URLs.

## 1. Resources

A resource is an entity managed by the API, such as a user, product, or order.

```text name=resources.txt
/users
/products
/orders
```

Use nouns for resource names because HTTP methods already describe the action.

```text name=resource-naming.txt
Recommended:      GET /users
Not recommended:  GET /getUsers
```

---

## 2. Collection and Individual Routes

A collection route represents multiple resources. An ID identifies one resource.

```python name=app/main.py
from fastapi import FastAPI

app = FastAPI()


@app.get("/users")
def list_users() -> list[dict[str, object]]:
    return [{"id": 1, "name": "Alice"}]


@app.get("/users/{user_id}")
def get_user(user_id: int) -> dict[str, object]:
    return {"id": user_id, "name": "Alice"}
```

- `/users`: User collection
- `/users/1`: User with ID `1`

---

## 3. CRUD Route Design

```python name=app/routers/users.py
from fastapi import APIRouter, Response, status

router = APIRouter(prefix="/users", tags=["Users"])


@router.get("")
def list_users() -> list[dict[str, object]]:
    return []


@router.post("", status_code=status.HTTP_201_CREATED)
def create_user() -> dict[str, int]:
    return {"id": 1}


@router.get("/{user_id}")
def get_user(user_id: int) -> dict[str, int]:
    return {"id": user_id}


@router.patch("/{user_id}")
def update_user(user_id: int) -> dict[str, int]:
    return {"id": user_id}


@router.delete(
    "/{user_id}",
    status_code=status.HTTP_204_NO_CONTENT,
)
def delete_user(user_id: int) -> Response:
    return Response(status_code=status.HTTP_204_NO_CONTENT)
```

| Method | Route | Purpose |
|---|---|---|
| `GET` | `/users` | List users |
| `POST` | `/users` | Create a user |
| `GET` | `/users/{id}` | Get one user |
| `PATCH` | `/users/{id}` | Partially update a user |
| `DELETE` | `/users/{id}` | Delete a user |

## 4. Use Plural Nouns Consistently

```text name=naming-convention.txt
Recommended:
  /users
  /products
  /orders

Avoid mixing:
  /user
  /products
  /get-orders
```

Plural resource names are common, but consistency is more important than the specific convention.

---

## 5. Nested Resources

Nested routes show a relationship between resources.

```python name=app/routers/posts.py
from fastapi import APIRouter

router = APIRouter()


@router.get("/users/{user_id}/posts")
def list_user_posts(user_id: int) -> list[dict[str, object]]:
    return [
        {
            "id": 10,
            "title": "FastAPI Basics",
            "author_id": user_id,
        }
    ]
```

`/users/1/posts` means posts belonging to user `1`.

Avoid deeply nested routes:

```text name=nested-routes.txt
Recommended: /users/1/posts
Avoid:       /users/1/posts/10/comments/5/replies
```

Use a direct resource route when nesting becomes difficult to understand:

```text name=direct-resource-route.txt
/comments/5
```

## 6. Filtering

Use query parameters to filter a collection.

```python name=app/routers/products.py
from fastapi import APIRouter, Query

router = APIRouter(prefix="/products")


@router.get("")
def list_products(
    category: str | None = Query(default=None, max_length=50),
    in_stock: bool | None = None,
) -> dict[str, object]:
    return {
        "filters": {
            "category": category,
            "in_stock": in_stock,
        }
    }
```

Example:

```text name=filter-request.txt
GET /products?category=books&in_stock=true
```

Only support known, validated filters.

---

## 7. Sorting

Allow clients to sort using approved fields.

```python name=app/routers/products.py
from typing import Literal

from fastapi import Query


@router.get("/sorted")
def list_sorted_products(
    sort_by: Literal["name", "price", "created_at"] = "name",
    order: Literal["asc", "desc"] = "asc",
) -> dict[str, str]:
    return {"sort_by": sort_by, "order": order}
```

Example:

```text name=sort-request.txt
GET /products/sorted?sort_by=price&order=desc
```

An allow-list prevents invalid fields and unsafe dynamic database queries.

## 8. Pagination

Pagination prevents one request from retrieving too many records.

```python name=app/routers/users.py
from fastapi import Query


@router.get("/paginated")
def list_paginated_users(
    page: int = Query(default=1, ge=1),
    page_size: int = Query(default=20, ge=1, le=100),
) -> dict[str, object]:
    return {
        "items": [],
        "page": page,
        "page_size": page_size,
        "total": 0,
    }
```

Example:

```text name=pagination-request.txt
GET /users/paginated?page=2&page_size=20
```

Always enforce a maximum page size to protect database performance.

---

## 9. Stateless Requests

Each request should contain everything required to process it.

```http name=stateless-request.http
GET /profile HTTP/1.1
Host: api.example.com
Authorization: Bearer access-token
Accept: application/json
```

The server should not depend on a previous API request. It may still use a database, cache, or authenticated session.

## 10. Idempotency

Repeating an idempotent request should produce the same intended result.

```python name=app/routers/users.py
from pydantic import BaseModel


class UserReplacement(BaseModel):
    name: str
    is_active: bool


@router.put("/{user_id}")
def replace_user(
    user_id: int,
    data: UserReplacement,
) -> dict[str, object]:
    return {"id": user_id, **data.model_dump()}
```

Sending the same `PUT` request repeatedly leaves the resource in the same state.

For payment or order creation, accept an idempotency key to prevent duplicate processing:

```http name=idempotent-order.http
POST /orders HTTP/1.1
Idempotency-Key: 710f74a8-7644-49ef-993b-d69d6f223e57
Content-Type: application/json
```

The server securely stores the key and returns the original result for repeated requests.

## 11. API Versioning

Versioning allows an API to introduce breaking changes without immediately affecting existing clients.

```python name=app/main.py
from fastapi import FastAPI

from app.routers.users import router as users_router

app = FastAPI()

app.include_router(users_router, prefix="/api/v1")
```

Example:

```text name=versioned-routes.txt
/api/v1/users
/api/v2/users
```

Create a new major version only for breaking changes.

---

## 12. Backward Compatibility

A change is backward-compatible when existing clients continue to work.

Usually safe:

- Adding an optional response field
- Adding a new endpoint
- Adding an optional request field

Potentially breaking:

- Renaming or removing a field
- Changing a field’s data type
- Making an optional field required
- Changing status codes or response structure

Deprecate old behavior before removing it.

---

## 13. Consistent Response Shapes

Use predictable response structures across endpoints.

```json name=list-response.json
{
  "items": [
    {
      "id": 1,
      "name": "Alice"
    }
  ],
  "page": 1,
  "page_size": 20,
  "total": 1
}
```

A consistent structure makes client applications easier to build and maintain.

## 14. Resource Ownership

A valid resource ID does not automatically grant access.

```python name=app/routers/documents.py
from fastapi import HTTPException, status


def check_document_access(
    document_owner_id: int,
    current_user_id: int,
) -> None:
    if document_owner_id != current_user_id:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail="Document not found",
        )
```

Always verify ownership or explicit permission. Returning `404` can avoid revealing that another user’s private resource exists.

## Key Guidelines

- Use nouns in URLs and HTTP methods for actions.
- Keep names and response formats consistent.
- Validate filtering, sorting, and pagination inputs.
- Keep requests stateless.
- Check authentication, permissions, and resource ownership.
- Version breaking API changes.
- Protect non-idempotent operations from duplicate execution.
