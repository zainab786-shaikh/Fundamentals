
# Topic 13: Common Web API Security Risks

Web APIs receive untrusted data and expose sensitive operations. Security must be enforced on the server, even when the frontend already performs checks.

## 1. SQL Injection

SQL injection occurs when untrusted input is combined directly with an SQL statement.

**Unsafe:**

```python name=app/repositories/unsafe_users.py
query = f"SELECT * FROM users WHERE email = '{email}'"
```

**Secure:**

```python name=app/repositories/users.py
from sqlalchemy import select
from sqlalchemy.orm import Session

from app.models.user import User


def find_user(db: Session, email: str) -> User | None:
    statement = select(User).where(User.email == email)
    return db.scalar(statement)
```

SQLAlchemy parameterizes the value. Never build SQL using string concatenation.

## 2. Broken Authentication

Broken authentication allows attackers to impersonate users through weak passwords, stolen tokens, or insecure sessions.

```python name=app/security/passwords.py
from pwdlib import PasswordHash

password_hasher = PasswordHash.recommended()


def hash_password(password: str) -> str:
    return password_hasher.hash(password)


def verify_password(password: str, stored_hash: str) -> bool:
    return password_hasher.verify(password, stored_hash)
```

Protection:

- Hash passwords with Argon2 or bcrypt.
- Use HTTPS.
- Rate-limit login attempts.
- Use short-lived tokens.
- Regenerate session IDs after login.
- Revoke sessions after password changes.

---

## 3. Broken Authorization

Broken authorization occurs when an authenticated user accesses an operation or resource without permission.

```python name=app/routers/documents.py
from fastapi import HTTPException, status
from sqlalchemy import select

from app.dependencies import DatabaseSession
from app.dependencies.auth import CurrentUser
from app.models.document import Document


def get_document(
    document_id: int,
    current_user: CurrentUser,
    db: DatabaseSession,
) -> Document:
    document = db.scalar(
        select(Document).where(
            Document.id == document_id,
            Document.owner_id == current_user.id,
        )
    )

    if document is None:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail="Document not found",
        )

    return document
```

Check ownership and permissions on every protected request. Do not rely on the frontend to hide restricted actions.

## 4. Insecure Direct Object Reference

An IDOR happens when changing an identifier gives access to another user’s data.

```text name=idor-example.txt
/users/10/documents/100
/users/10/documents/101
```

Never authorize access using only the document ID. Include the authenticated owner or tenant in the database query.

```python name=app/repositories/documents.py
statement = select(Document).where(
    Document.id == document_id,
    Document.owner_id == current_user.id,
)
```

Use `404` when revealing the resource’s existence would expose private information.

## 5. Mass Assignment

Mass assignment occurs when clients can update fields they should not control.

**Unsafe request:**

```json name=unsafe-profile-update.json
{
  "display_name": "Alice",
  "role": "admin",
  "is_active": true
}
```

**Secure schema:**

```python name=app/schemas/profile.py
from pydantic import BaseModel, ConfigDict, Field


class ProfileUpdate(BaseModel):
    model_config = ConfigDict(extra="forbid")

    display_name: str | None = Field(
        default=None,
        min_length=2,
        max_length=100,
    )
```

Exclude `role`, `permissions`, `tenant_id`, and similar privileged fields. Reject unexpected input.

## 6. Cross-Site Scripting

XSS occurs when untrusted content is inserted into a web page as executable HTML or JavaScript.

**Unsafe browser code:**

```javascript name=frontend/unsafe.js
element.innerHTML = apiResponse.comment;
```

**Secure browser code:**

```javascript name=frontend/comment.js
element.textContent = apiResponse.comment;
```

Protection:

- Use context-aware output encoding.
- Prefer `textContent` over `innerHTML`.
- Sanitize HTML only when HTML input is genuinely required.
- Apply a restrictive Content Security Policy.
- Do not assume an API’s JSON response is safe to insert as HTML.

---

## 7. Cross-Site Request Forgery

CSRF tricks a browser into sending an authenticated request using automatically attached cookies.

```http name=csrf-protected-request.http
PATCH /profile HTTP/1.1
Cookie: __Host-session=random-session-id
X-CSRF-Token: unpredictable-token
Content-Type: application/json
```

Protection for cookie authentication:

- Use CSRF tokens.
- Use `SameSite=Strict` or `Lax` when possible.
- Validate `Origin` for state-changing requests.
- Allow only trusted CORS origins.
- Never use `GET` for operations that modify data.

## 8. Server-Side Request Forgery

SSRF occurs when an attacker makes the API request an unauthorized internal or external URL.

**Unsafe:**

```python name=app/services/unsafe_fetch.py
response = await client.get(user_supplied_url)
```

**Secure allow-list:**

```python name=app/security/external_urls.py
from urllib.parse import urlsplit

ALLOWED_HOSTS = {"api.example.com"}
ALLOWED_PORTS = {None, 443}
ALLOWED_PATH_PREFIX = "/public/"


def validate_url(value: str) -> str:
    parsed = urlsplit(value)

    if parsed.scheme != "https":
        raise ValueError("Only HTTPS is allowed")

    if parsed.hostname not in ALLOWED_HOSTS:
        raise ValueError("Host is not allowed")

    if parsed.port not in ALLOWED_PORTS:
        raise ValueError("Port is not allowed")

    if not parsed.path.startswith(ALLOWED_PATH_PREFIX):
        raise ValueError("Path is not allowed")

    if parsed.username or parsed.password:
        raise ValueError("URL credentials are not allowed")

    return value
```

Also reject unsafe redirects and protect against DNS rebinding when handling highly sensitive requests.

## 9. Path Traversal

Path traversal uses values such as `../` to access files outside an allowed directory.

```python name=app/services/files.py
from pathlib import Path

BASE_DIRECTORY = Path("documents").resolve()


def get_safe_path(file_name: str) -> Path:
    if Path(file_name).name != file_name:
        raise ValueError("Invalid file name")

    candidate = (BASE_DIRECTORY / file_name).resolve()

    if not candidate.is_relative_to(BASE_DIRECTORY):
        raise ValueError("File is outside the allowed directory")

    return candidate
```

Prefer server-generated file identifiers instead of accepting file paths from clients.

## 10. Command Injection

Command injection occurs when untrusted input becomes part of a system command.

**Unsafe:**

```python name=app/services/unsafe_command.py
import os

os.system(f"ping {user_input}")
```

**Safer:**

```python name=app/services/network.py
import ipaddress
import subprocess


def ping(address: str) -> str:
    validated_address = str(ipaddress.ip_address(address))

    result = subprocess.run(
        ["ping", "-c", "1", validated_address],
        shell=False,
        check=True,
        capture_output=True,
        text=True,
        timeout=5,
    )

    return result.stdout
```

Avoid system commands where possible. Otherwise, validate input, pass arguments separately, and keep `shell=False`.

The command arguments differ across operating systems, so account for Windows and Unix compatibility.

## 11. Unsafe Deserialization

Unsafe deserialization can execute code or create unexpected objects from untrusted data.

**Avoid untrusted pickle data:**

```python name=app/services/unsafe_deserialization.py
import pickle

data = pickle.loads(untrusted_bytes)
```

**Use validated JSON instead:**

```python name=app/schemas/settings.py
from pydantic import BaseModel, ConfigDict


class UserSettings(BaseModel):
    model_config = ConfigDict(extra="forbid")

    theme: str
    notifications_enabled: bool
```

```python name=app/services/settings.py
import json

from app.schemas.settings import UserSettings


def parse_settings(raw_data: str) -> UserSettings:
    parsed = json.loads(raw_data)
    return UserSettings.model_validate(parsed)
```

JSON does not create arbitrary Python objects. Schema validation restricts the accepted structure.

## 12. Sensitive Data Exposure

Sensitive data can leak through API responses, logs, URLs, or error messages.

```python name=app/schemas/user.py
from pydantic import BaseModel, ConfigDict, EmailStr


class UserResponse(BaseModel):
    id: int
    email: EmailStr

    model_config = ConfigDict(from_attributes=True)
```

Response schemas prevent accidental exposure of fields such as:

- Password hashes
- Access and refresh tokens
- API keys
- Private notes
- Internal security fields

Never include secrets in query strings because URLs are commonly logged.

## 13. Verbose Error Messages

Detailed production errors may reveal SQL, file paths, dependencies, or internal code.

```python name=app/handlers.py
import logging

from fastapi import Request
from fastapi.responses import JSONResponse

logger = logging.getLogger(__name__)


async def unexpected_error_handler(
    request: Request,
    exception: Exception,
) -> JSONResponse:
    logger.exception(
        "Unexpected API error path=%s",
        request.url.path,
    )

    return JSONResponse(
        status_code=500,
        content={
            "error": {
                "code": "internal_error",
                "message": "Internal server error",
            }
        },
    )
```

Log technical details securely on the server. Return only a generic message to clients.

## 14. Security Misconfiguration

Common configuration problems include:

- Debug mode enabled in production
- Wildcard CORS for private APIs
- Default passwords
- Public database ports
- Unprotected API documentation
- Missing security headers
- Excessive cloud or database privileges

```python name=app/main.py
from fastapi import FastAPI

app = FastAPI(debug=False)
```

Use secure production defaults and deny access unless it is explicitly required.

## 15. Missing Rate Limiting

Without limits, attackers can repeatedly call login, registration, search, or expensive endpoints.

```http name=rate-limit-response.http
HTTP/1.1 429 Too Many Requests
Retry-After: 60
Content-Type: application/json

{
  "detail": "Rate limit exceeded"
}
```

Apply limits by:

- IP address
- Authenticated user
- API key
- Endpoint sensitivity

Production limits should use a shared store or API gateway so they work across all application instances.

## 16. Unrestricted File Uploads

File uploads can consume storage or contain malicious content.

```python name=app/routers/uploads.py
from fastapi import HTTPException, UploadFile

MAX_FILE_SIZE = 2 * 1024 * 1024
PNG_SIGNATURE = b"\x89PNG\r\n\x1a\n"


async def validate_png(file: UploadFile) -> bytes:
    content = await file.read(MAX_FILE_SIZE + 1)

    if len(content) > MAX_FILE_SIZE:
        raise HTTPException(413, "File is too large")

    if not content.startswith(PNG_SIGNATURE):
        raise HTTPException(415, "Only PNG files are allowed")

    return content
```

Also:

- Generate filenames on the server.
- Store uploads outside executable directories.
- Scan files for malware.
- Require authorization for downloads.

## 17. Vulnerable Dependencies

Outdated packages may contain known security vulnerabilities.

```bash name=scripts/security-scan.sh
python -m pip install pip-audit
pip-audit
```

Pin dependencies, review update notes, and run vulnerability scans in CI/CD.

## Security Checklist

- Validate all untrusted input.
- Use parameterized database queries.
- Authenticate and authorize every protected request.
- Check ownership and tenant boundaries.
- Reject unexpected fields.
- Use secure password hashing and short-lived sessions.
- Protect cookie authentication against CSRF.
- Strictly allow-list external URLs.
- Limit uploads and verify their actual format.
- Return safe errors and avoid logging secrets.
- Apply rate limits and least privilege.
- Scan dependencies regularly.
