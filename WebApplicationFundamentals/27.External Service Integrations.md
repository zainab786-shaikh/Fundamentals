# Topic 29: External Service Integrations, Webhooks, Retries, and Resilience

External integrations introduce network failures, untrusted data, authentication risks, and partial failures. Apply explicit trust boundaries, strict timeouts, idempotency, and safe retry policies.

## 1. Integration Flow

```text name=integration-flow.txt
API
  ↓ authenticated HTTPS request
External service
  ↓ response or asynchronous webhook
Webhook endpoint
  ↓ verify signature and reject replay
Application processing
```

Treat responses and webhooks as untrusted input, even when they come from a known provider.

## 3. Strictly Validate the Base URL

```python name=app/security/integration_urls.py
from urllib.parse import urlsplit

ALLOWED_PAYMENT_HOSTS = {"payments.example.com"}
ALLOWED_PAYMENT_PORTS = {None, 443}


def validate_payment_base_url(value: str) -> str:
    parsed = urlsplit(value)

    if parsed.scheme != "https":
        raise ValueError("Payment service must use HTTPS")

    if parsed.username is not None or parsed.password is not None:
        raise ValueError("URL credentials are not allowed")

    if parsed.hostname not in ALLOWED_PAYMENT_HOSTS:
        raise ValueError("Payment host is not allowed")

    if parsed.port not in ALLOWED_PAYMENT_PORTS:
        raise ValueError("Payment port is not allowed")

    if parsed.path not in {"", "/"}:
        raise ValueError("Unexpected base URL path")

    if parsed.query or parsed.fragment:
        raise ValueError("Query strings and fragments are not allowed")

    return value.rstrip("/")
```

Validate scheme, exact host, port, path, credentials, query, and fragment. This reduces SSRF and configuration-tampering risks.

## 5. Safely Construct Request Paths

Do not append unrestricted client input to URLs.

```python name=app/integrations/payment_client.py
from urllib.parse import quote

import httpx


class PaymentClient:
    def __init__(self, client: httpx.AsyncClient) -> None:
        self._client = client

    async def get_payment(
        self,
        payment_id: str,
    ) -> httpx.Response:
        if not payment_id.isascii() or not payment_id.isalnum():
            raise ValueError("Invalid payment ID")

        safe_payment_id = quote(payment_id, safe="")

        return await self._client.get(
            f"/v1/payments/{safe_payment_id}",
        )
```

Prefer constrained identifiers, proper URL encoding, and fixed path templates.

Never accept an arbitrary destination URL when the integration requires only one approved service.

## 8. Retry Only Safe Operations

Retries are usually appropriate for:

- Connection failures
- Timeouts before a response
- Selected `429` responses
- Temporary `502`, `503`, and `504` responses
- Idempotent reads

Do not automatically retry:

- Validation failures
- Authentication failures
- Permission failures
- Most other `4xx` responses
- Non-idempotent writes without an idempotency key

## 9. Bounded Retry with Backoff and Jitter

```python name=app/integrations/retry.py
import asyncio
import random
from collections.abc import Awaitable, Callable
from typing import TypeVar

import httpx

T = TypeVar("T")


async def retry_temporary_failure(
    operation: Callable[[], Awaitable[T]],
    maximum_attempts: int = 3,
) -> T:
    if maximum_attempts < 1:
        raise ValueError("maximum_attempts must be positive")

    for attempt in range(1, maximum_attempts + 1):
        try:
            return await operation()
        except (
            httpx.ConnectError,
            httpx.TimeoutException,
        ):
            if attempt == maximum_attempts:
                raise

            base_delay = 2 ** (attempt - 1)
            jitter = random.uniform(0, base_delay * 0.2)
            await asyncio.sleep(base_delay + jitter)

    raise RuntimeError("Retry loop exited unexpectedly")
```

Keep retries limited. Retries consume capacity and can amplify an outage.

## 10. Respect `Retry-After`

```python name=app/integrations/retry_after.py
from email.utils import parsedate_to_datetime
from datetime import UTC, datetime


def parse_retry_after(
    value: str | None,
    maximum_seconds: int = 60,
) -> int:
    if value is None:
        return 1

    if value.isdigit():
        return min(int(value), maximum_seconds)

    try:
        retry_at = parsedate_to_datetime(value)

        if retry_at.tzinfo is None:
            retry_at = retry_at.replace(tzinfo=UTC)

        delay = int(
            (retry_at - datetime.now(UTC)).total_seconds()
        )

        return max(0, min(delay, maximum_seconds))
    except (TypeError, ValueError, OverflowError):
        return 1
```

Cap server-supplied delays so one response cannot indefinitely block a worker.

## 11. Idempotent Write Requests

Use an idempotency key when retrying a write:

```python name=app/integrations/payment_client.py
from decimal import Decimal
from uuid import UUID

import httpx


async def create_payment(
    client: httpx.AsyncClient,
    order_id: UUID,
    amount: Decimal,
    currency: str,
) -> PaymentResponse:
    idempotency_key = f"order-payment:{order_id}"

    response = await client.post(
        "/v1/payments",
        headers={
            "Idempotency-Key": idempotency_key,
        },
        json={
            "order_id": str(order_id),
            "amount": str(amount),
            "currency": currency,
        },
    )

    response.raise_for_status()
    return PaymentResponse.model_validate(response.json())
```

The provider must guarantee idempotency-key semantics. Associate the key with a stable operation and identical payload.

## 12. Circuit Breakers

A circuit breaker stops repeated requests to a failing dependency.

```text name=circuit-breaker-states.txt
Closed:
  Requests pass normally.

Open:
  Requests fail immediately without calling the dependency.

Half-open:
  A limited test request checks whether the dependency recovered.
```

Circuit breakers reduce resource exhaustion and cascading failures. Use a maintained library, gateway, or service-mesh implementation rather than an ad hoc distributed breaker.

---

## 13. Bulkhead Isolation

Separate resource pools prevent one integration from consuming all available capacity.

```text name=bulkhead-isolation.txt
Payment integration → dedicated connection pool and concurrency limit
Email integration   → separate pool and concurrency limit
Storage integration → separate pool and concurrency limit
```

Apply:

- Per-service connection limits
- Concurrency limits
- Dedicated worker queues
- Request deadlines
- Independent circuit breakers

A slow optional service should not make the entire API unavailable.

# Webhooks

## 14. Webhook Security Model

A webhook endpoint receives requests from an external system.

```text name=webhook-flow.txt
Provider creates event
       ↓
Provider signs raw request body
       ↓
Application verifies signature and timestamp
       ↓
Application rejects duplicates
       ↓
Application enqueues processing
       ↓
Application responds quickly
```

Do not trust source IP alone. Provider IP ranges may change, proxies may obscure addresses, and network identity does not prove message integrity.

---

## 15. Sign the Raw Request Body

A typical HMAC signature covers the timestamp and exact raw body:

```text name=webhook-signature-format.txt
signed_payload = timestamp + "." + raw_request_body
signature = HMAC-SHA256(webhook_secret, signed_payload)
```

The exact format is provider-specific. Follow the provider’s official specification.

Do not parse and reserialize JSON before verification because whitespace and key ordering may change.

---

## 16. Verify Webhook Signatures

```python name=app/security/webhooks.py
import hashlib
import hmac
import time


class InvalidWebhookError(ValueError):
    pass


def verify_webhook_signature(
    body: bytes,
    timestamp: str,
    supplied_signature: str,
    secret: str,
    tolerance_seconds: int = 300,
) -> None:
    try:
        timestamp_value = int(timestamp)
    except ValueError as error:
        raise InvalidWebhookError(
            "Invalid webhook timestamp"
        ) from error

    current_time = int(time.time())

    if abs(current_time - timestamp_value) > tolerance_seconds:
        raise InvalidWebhookError(
            "Webhook timestamp is outside the allowed window"
        )

    signed_payload = (
        timestamp.encode("ascii")
        + b"."
        + body
    )

    expected_signature = hmac.new(
        secret.encode("utf-8"),
        signed_payload,
        hashlib.sha256,
    ).hexdigest()

    if not hmac.compare_digest(
        supplied_signature,
        expected_signature,
    ):
        raise InvalidWebhookError(
            "Invalid webhook signature"
        )
```

Security controls:

- Modern HMAC algorithm
- Constant-time comparison
- Timestamp validation
- Exact raw-body verification
- Secret stored outside source control

## 17. Limit Webhook Body Size

```python name=app/security/request_body.py
from fastapi import HTTPException, Request, status

MAX_WEBHOOK_SIZE = 256 * 1024


async def read_limited_body(request: Request) -> bytes:
    declared_length = request.headers.get("Content-Length")

    if declared_length is not None:
        try:
            if int(declared_length) > MAX_WEBHOOK_SIZE:
                raise HTTPException(
                    status.HTTP_413_CONTENT_TOO_LARGE,
                    "Webhook body is too large",
                )
        except ValueError:
            raise HTTPException(
                status.HTTP_400_BAD_REQUEST,
                "Invalid Content-Length",
            ) from None

    body = await request.body()

    if len(body) > MAX_WEBHOOK_SIZE:
        raise HTTPException(
            status.HTTP_413_CONTENT_TOO_LARGE,
            "Webhook body is too large",
        )

    return body
```

Also configure body-size limits at the ingress or reverse proxy, because application-level checks occur after some data has already arrived.

## 19. Complete Webhook Endpoint

```python name=app/routers/payment_webhooks.py
from typing import Annotated

from fastapi import APIRouter, Header, HTTPException, Request, status
from pydantic import ValidationError

from app.config import settings
from app.schemas.payment_webhook import PaymentWebhook
from app.security.request_body import read_limited_body
from app.security.webhooks import (
    InvalidWebhookError,
    verify_webhook_signature,
)

router = APIRouter(prefix="/webhooks", tags=["Webhooks"])


@router.post(
    "/payments",
    status_code=status.HTTP_202_ACCEPTED,
)
async def receive_payment_webhook(
    request: Request,
    webhook_timestamp: Annotated[
        str,
        Header(alias="Webhook-Timestamp"),
    ],
    webhook_signature: Annotated[
        str,
        Header(alias="Webhook-Signature"),
    ],
) -> dict[str, str]:
    body = await read_limited_body(request)

    try:
        verify_webhook_signature(
            body=body,
            timestamp=webhook_timestamp,
            supplied_signature=webhook_signature,
            secret=(
                settings.payment_webhook_secret
                .get_secret_value()
            ),
        )

        event = PaymentWebhook.model_validate_json(body)
    except (InvalidWebhookError, ValidationError):
        raise HTTPException(
            status_code=status.HTTP_400_BAD_REQUEST,
            detail="Invalid webhook",
        ) from None

    # Atomically record event.event_id and enqueue safe processing.
    _ = event

    return {"status": "accepted"}
```

Return a generic error. Do not reveal whether the signature, timestamp, or schema check failed.

## 20. Prevent Replay Attacks

Store each provider event ID under a unique constraint.

```python name=app/models/webhook_event.py
from datetime import datetime

from sqlalchemy import DateTime, String, UniqueConstraint
from sqlalchemy.orm import Mapped, mapped_column

from app.database import Base


class WebhookEvent(Base):
    __tablename__ = "webhook_events"
    __table_args__ = (
        UniqueConstraint(
            "provider",
            "external_event_id",
            name="uq_webhook_provider_event",
        ),
    )

    id: Mapped[int] = mapped_column(primary_key=True)
    provider: Mapped[str] = mapped_column(
        String(50),
        nullable=False,
    )
    external_event_id: Mapped[str] = mapped_column(
        String(100),
        nullable=False,
    )
    event_type: Mapped[str] = mapped_column(
        String(100),
        nullable=False,
    )
    received_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True),
        nullable=False,
    )
    processed_at: Mapped[datetime | None] = mapped_column(
        DateTime(timezone=True),
    )
```

Timestamp checking limits the replay window. The unique event ID provides durable duplicate detection.

## 21. Acknowledge Quickly

Webhook providers often retry when an endpoint responds slowly or fails.

Recommended flow:

```text name=webhook-processing.txt
1. Limit body size
2. Verify signature and timestamp
3. Validate the event schema
4. Atomically record the unique event ID
5. Enqueue durable processing
6. Return success promptly
7. Process business effects asynchronously
```

Do not perform slow external requests or report generation inside the webhook response path.

## 22. Handle Duplicate Events Idempotently

A duplicate webhook is normally not an error.

```python name=app/services/webhook_events.py
from datetime import UTC, datetime

from sqlalchemy.exc import IntegrityError
from sqlalchemy.orm import Session

from app.models.webhook_event import WebhookEvent


def record_webhook_event(
    db: Session,
    external_event_id: str,
    event_type: str,
) -> bool:
    event = WebhookEvent(
        provider="payment",
        external_event_id=external_event_id,
        event_type=event_type,
        received_at=datetime.now(UTC),
    )

    try:
        db.add(event)
        db.commit()
        return True
    except IntegrityError:
        db.rollback()
        return False
```

`False` indicates the event was previously received. Return a successful response so the provider stops retrying it.

## 23. Do Not Trust Webhook Business Data Blindly

For high-risk events, verify current state with the provider:

```text name=webhook-verification.txt
Webhook says payment completed
        ↓
Verify signature
        ↓
Retrieve payment through authenticated provider API
        ↓
Validate order, amount, currency, and status
        ↓
Apply idempotent business transition
```

This is useful when a webhook triggers shipment, account credit, entitlement, or another sensitive action.

Compare:

- Provider payment ID
- Internal order ID
- Expected amount
- Expected currency
- Allowed state transition
- Merchant or tenant identity

## 24. Secret Rotation

Support multiple webhook secrets during rotation:

```python name=app/security/webhook_rotation.py
def verify_with_active_secrets(
    body: bytes,
    timestamp: str,
    signature: str,
    secrets: tuple[str, ...],
) -> None:
    for secret in secrets:
        try:
            verify_webhook_signature(
                body=body,
                timestamp=timestamp,
                supplied_signature=signature,
                secret=secret,
            )
            return
        except InvalidWebhookError:
            continue

    raise InvalidWebhookError("Invalid webhook")
```

Rotation process:

1. Add the new secret.
2. Configure the provider to use it.
3. Accept old and new secrets temporarily.
4. Confirm traffic uses the new secret.
5. Remove and revoke the old secret.
6. Audit the change.

Do not keep retired secrets active indefinitely.

## 25. Outbound Webhooks

When sending webhooks to customers:

- Require HTTPS.
- Strictly validate destination host, port, and path.
- Block private, loopback, link-local, and metadata addresses.
- Revalidate redirect destinations or disable redirects.
- Protect against DNS rebinding.
- Sign every request.
- Use bounded retries.
- Apply per-destination concurrency limits.
- Avoid sensitive payloads.

User-configurable webhook destinations create a significant SSRF risk. Route delivery through a hardened egress service where practical.

## 26. Sign Outbound Webhooks

```python name=app/security/outbound_webhooks.py
import hashlib
import hmac
import time


def create_webhook_signature(
    body: bytes,
    secret: str,
) -> tuple[str, str]:
    timestamp = str(int(time.time()))
    signed_payload = timestamp.encode("ascii") + b"." + body

    signature = hmac.new(
        secret.encode("utf-8"),
        signed_payload,
        hashlib.sha256,
    ).hexdigest()

    return timestamp, signature
```

Include a unique event ID so receivers can reject duplicate delivery.

## 30. Integration Security Checklist

- Use HTTPS and strict destination allow-lists.
- Keep credentials in a secret manager.
- Give each integration a least-privileged identity.
- Reuse clients with explicit timeouts and connection limits.
- Disable redirects unless specifically required and validated.
- Validate every external response.
- Retry only temporary failures and safe operations.
- Use idempotency keys for retried writes.
- Apply circuit breakers and bulkhead isolation.
- Verify webhook signatures against the raw body.
- Enforce timestamp tolerances and unique event IDs.
- Validate webhook schemas and body sizes.
- Process webhooks asynchronously and idempotently.
- Rotate credentials and webhook secrets.
- Redact secrets and sensitive payloads from telemetry.
- Test outages, retries, duplicate delivery, and malformed responses.

## Key Points

- External services are failure-prone and outside the application’s trust boundary.
- Every outbound request needs an allow-listed destination, timeout, and bounded resource usage.
- Every external response requires schema validation.
- Retries must be limited, classified, and protected by idempotency.
- Webhook authentication requires signature verification over the exact raw body.
- Timestamp checks and unique event IDs prevent replay and duplicate effects.
- Sensitive business events may require verification through the provider’s authenticated API.
- Resilience controls must prevent one failing dependency from exhausting the entire application.
