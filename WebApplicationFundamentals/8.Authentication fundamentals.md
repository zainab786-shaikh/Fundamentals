
# Topic 8: Authentication Fundamentals

**Authentication** verifies who is making an API request. It does not decide what the user is allowed to do—that is authorization.

## 1. Authentication Flow

```text name=authentication-flow.txt
User sends credentials
        ↓
Server verifies credentials
        ↓
Server issues a session or token
        ↓
Client includes it in later requests
        ↓
Server validates it before granting access
```

Use HTTPS for every step to protect credentials and tokens in transit.

---

## 2. Authentication vs Authorization

```text name=authentication-vs-authorization.txt
Authentication: Who are you?
Authorization:  What are you allowed to do?
```

Example:

- A valid token authenticates Alice.
- An `admin:reports` permission authorizes Alice to read reports.

Both checks are required for protected operations.

## 3. Password Authentication

The user submits an identifier and password.

```python name=app/schemas/auth.py
from pydantic import BaseModel, EmailStr, Field


class LoginRequest(BaseModel):
    email: EmailStr
    password: str = Field(min_length=12, max_length=128)
```

Validate input length to reject malformed or excessively large requests.

## 4. Hash Passwords with Argon2

Install the password library:

```bash name=install-password-library.sh
pip install "pwdlib[argon2]"
```

```python name=app/security/passwords.py
from pwdlib import PasswordHash

password_hasher = PasswordHash.recommended()


def hash_password(password: str) -> str:
    return password_hasher.hash(password)


def verify_password(password: str, stored_hash: str) -> bool:
    return password_hasher.verify(password, stored_hash)
```

Store only the generated hash. Password hashing is deliberately slow, making stolen hashes harder to crack.

Never store plain-text passwords or use fast hashes such as SHA-256 for password storage.

## 5. User Registration

```python name=app/routers/auth.py
from fastapi import APIRouter, status

from app.security.passwords import hash_password

router = APIRouter(prefix="/auth", tags=["Authentication"])


@router.post("/register", status_code=status.HTTP_201_CREATED)
def register(data: LoginRequest) -> dict[str, str]:
    password_hash = hash_password(data.password)

    # Save data.email and password_hash in the database.
    return {"message": "Account created"}
```

The password must be hashed before database storage. Never return or log the password or hash.

A real application should also:

- Enforce a unique normalized email
- Require email verification when appropriate
- Apply registration rate limits
- Assign the least-privileged role by default

## 6. Secure Login

```python name=app/services/authentication.py
from fastapi import HTTPException, status

from app.security.passwords import verify_password


def authenticate_user(
    user: object | None,
    password: str,
) -> object:
    if user is None or not verify_password(
        password,
        user.password_hash,
    ):
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Invalid email or password",
            headers={"WWW-Authenticate": "Bearer"},
        )

    if not user.is_active:
        raise HTTPException(
            status_code=status.HTTP_403_FORBIDDEN,
            detail="Account is unavailable",
        )

    return user
```

Return the same error for an unknown email and an incorrect password. This makes account discovery harder.

Apply rate limiting and temporary lockout after repeated failures.

## 7. API-Key Authentication

An API key identifies an application or service.

```python name=app/security/api_key.py
import hmac
import os
from typing import Annotated

from fastapi import Header, HTTPException, status

EXPECTED_API_KEY = os.environ["API_KEY"]


def require_api_key(
    x_api_key: Annotated[str | None, Header()] = None,
) -> None:
    if x_api_key is None or not hmac.compare_digest(
        x_api_key,
        EXPECTED_API_KEY,
    ):
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Invalid credentials",
        )
```

Use it as a dependency:

```python name=app/routers/integrations.py
from fastapi import APIRouter, Depends

from app.security.api_key import require_api_key

router = APIRouter(prefix="/integrations")


@router.get("/status", dependencies=[Depends(require_api_key)])
def integration_status() -> dict[str, str]:
    return {"status": "available"}
```

Store API keys in a secret manager or environment variable. Rotate them regularly and assign only required permissions.

## 8. HTTP Basic Authentication

Basic authentication sends a username and password with every request.

```python name=app/security/basic_auth.py
import secrets
from typing import Annotated

from fastapi import Depends, HTTPException, status
from fastapi.security import HTTPBasic, HTTPBasicCredentials

basic_scheme = HTTPBasic()


def authenticate_basic(
    credentials: Annotated[HTTPBasicCredentials, Depends(basic_scheme)],
) -> str:
    username_valid = secrets.compare_digest(
        credentials.username,
        "service-user",
    )
    password_valid = secrets.compare_digest(
        credentials.password,
        "example-only",
    )

    if not username_valid or not password_valid:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Invalid credentials",
            headers={"WWW-Authenticate": "Basic"},
        )

    return credentials.username
```

Basic authentication must use HTTPS because Base64 encoding is not encryption. For most modern APIs, short-lived bearer tokens are preferable.

Real credentials must not be hardcoded.

## 9. Bearer-Token Authentication

The client sends an access token in the `Authorization` header.

```http name=bearer-request.http
GET /profile HTTP/1.1
Host: api.example.com
Authorization: Bearer access-token
```

FastAPI can extract the token:

```python name=app/security/bearer.py
from typing import Annotated

from fastapi import Depends
from fastapi.security import OAuth2PasswordBearer

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="/auth/token")


def get_token(
    token: Annotated[str, Depends(oauth2_scheme)],
) -> str:
    return token
```

The server must validate the token’s signature, expiration, issuer, audience, and required claims before trusting it.

Never place tokens in URLs because URLs may appear in browser history, server logs, and analytics.

## 10. Cookie-Based Authentication

The server can store a session identifier in a secure cookie.

```python name=app/routers/session.py
from fastapi import Response


def set_session_cookie(
    response: Response,
    session_id: str,
) -> None:
    response.set_cookie(
        key="session_id",
        value=session_id,
        httponly=True,
        secure=True,
        samesite="strict",
        max_age=900,
        path="/",
    )
```

Security settings:

- `HttpOnly`: JavaScript cannot read the cookie.
- `Secure`: Browser sends it only over HTTPS.
- `SameSite=Strict`: Reduces cross-site submission.
- Short expiration: Limits stolen-session lifetime.

Generate a new unpredictable session ID after login to prevent session fixation. Cookie authentication also requires CSRF protection.

## 11. OAuth 2.0

OAuth 2.0 allows an application to obtain limited access to an API.

Main roles:

```text name=oauth-roles.txt
Resource owner:        The user
Client:                The requesting application
Authorization server: Issues tokens
Resource server:       The protected API
```

For browser and mobile applications, use **Authorization Code with PKCE**. Avoid deprecated flows such as the implicit grant.

OAuth 2.0 handles delegated authorization; it is not by itself a user identity protocol.

---

## 12. OpenID Connect

OpenID Connect adds authentication and identity information on top of OAuth 2.0.

```text name=oidc-tokens.txt
Access token → Used to call an API
ID token     → Describes the authenticated user
```

Use a well-maintained OpenID Connect library and validate:

- Signature
- Issuer
- Audience
- Expiration
- Nonce, when required

Do not use an ID token as an API access token unless the API explicitly supports it.

## 13. Multi-Factor Authentication

MFA requires another factor in addition to a password.

Common factors:

- Authenticator application code
- Hardware security key or passkey
- Recovery code

Security keys and passkeys provide stronger phishing resistance than SMS codes.

MFA is especially important for administrators and sensitive operations.

## 14. Logout

For server-side sessions, delete the session on the server and remove the cookie.

```python name=app/routers/logout.py
from fastapi import Response, status


@router.post("/logout", status_code=status.HTTP_204_NO_CONTENT)
def logout(response: Response) -> Response:
    # Delete the server-side session from the database or cache.
    response.delete_cookie(
        key="session_id",
        path="/",
        secure=True,
        httponly=True,
        samesite="strict",
    )
    response.status_code = status.HTTP_204_NO_CONTENT
    return response
```

For token authentication, revoke refresh tokens where supported. Short-lived access tokens may remain valid until they expire.

## 15. Authentication Failure Codes

| Status | Meaning |
|---:|---|
| `401 Unauthorized` | Credentials are missing, invalid, or expired |
| `403 Forbidden` | Identity is valid, but access is not permitted |
| `429 Too Many Requests` | Too many authentication attempts |

A `401` bearer response should normally include:

```http name=authentication-error.http
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer
Content-Type: application/json
```

## Key Security Rules

- Use HTTPS only.
- Hash passwords with Argon2 or bcrypt.
- Never store or log plain-text passwords.
- Keep API keys and signing secrets outside source code.
- Use short-lived access tokens.
- Rotate and revoke credentials where possible.
- Rate-limit login, registration, and password-reset endpoints.
- Regenerate session identifiers after login.
- Use generic authentication failure messages.
- Perform authorization checks after authentication.
