
# Topic 2: HTTP Methods

HTTP methods tell the API what action the client wants to perform.

## 1. `GET` — Read Data

```python name=app/main.py
from fastapi import FastAPI

app = FastAPI()


@app.get("/users/{user_id}")
def get_user(user_id: int) -> dict[str, object]:
    return {"id": user_id, "name": "Alice"}
```

`GET /users/1` retrieves user `1`.

- Should not modify data.
- Request data normally comes through the path or query string.
- Successful response: `200 OK`.

---

## 2. `POST` — Create Data

```python name=app/main.py
from fastapi import FastAPI, status
from pydantic import BaseModel, Field

app = FastAPI()


class UserCreate(BaseModel):
    name: str = Field(min_length=2, max_length=100)


@app.post("/users", status_code=status.HTTP_201_CREATED)
def create_user(data: UserCreate) -> dict[str, object]:
    return {"id": 1, "name": data.name}
```

`POST /users` creates a new user.

- Data is sent in the request body.
- Usually creates a new resource.
- Successful response: `201 Created`.

---

## 3. `PUT` — Replace a Resource

```python name=app/main.py
from pydantic import BaseModel, EmailStr


class UserReplace(BaseModel):
    name: str
    email: EmailStr
    is_active: bool


@app.put("/users/{user_id}")
def replace_user(
    user_id: int,
    data: UserReplace,
) -> dict[str, object]:
    return {"id": user_id, **data.model_dump()}
```

`PUT /users/1` replaces the complete user representation.

- The client normally sends every required field.
- Omitted optional fields may return to their defaults.
- Successful response: `200 OK` or `204 No Content`.

---

## 4. `PATCH` — Update Selected Fields

```python name=app/main.py
from pydantic import BaseModel, Field


class UserUpdate(BaseModel):
    name: str | None = Field(default=None, min_length=2)
    is_active: bool | None = None


@app.patch("/users/{user_id}")
def update_user(
    user_id: int,
    data: UserUpdate,
) -> dict[str, object]:
    changes = data.model_dump(exclude_unset=True)
    return {"id": user_id, "changes": changes}
```

`PATCH /users/1` updates only the supplied fields.

Example body:

```json name=update-user.json
{
  "is_active": false
}
```

Use `PATCH` when the complete resource should not be replaced.

---

## 5. `DELETE` — Remove Data

```python name=app/main.py
from fastapi import Response, status


@app.delete(
    "/users/{user_id}",
    status_code=status.HTTP_204_NO_CONTENT,
)
def delete_user(user_id: int) -> Response:
    return Response(status_code=status.HTTP_204_NO_CONTENT)
```

`DELETE /users/1` removes user `1`.

- `204 No Content` means deletion succeeded.
- A `204` response must not contain a body.
- Authorization should be checked before deletion.

---

## 6. `HEAD` — Read Headers Only

```python name=app/main.py
from fastapi import Response


@app.head("/users/{user_id}")
def check_user(user_id: int) -> Response:
    return Response(
        status_code=200,
        headers={"X-User-ID": str(user_id)},
    )
```

`HEAD` works like `GET`, but the response contains no body.

It can check:

- Whether a resource exists
- Content size
- Cache information
- Last modification time

---

## 7. `OPTIONS` — Discover Request Options

```python name=app/main.py
from fastapi import Response


@app.options("/users")
def users_options() -> Response:
    return Response(
        status_code=204,
        headers={"Allow": "GET, POST, OPTIONS"},
    )
```

`OPTIONS` tells the client which operations are supported.

Browsers also use it for **CORS preflight requests**. Normally, FastAPI’s CORS middleware handles those automatically.

---

## 8. Safe Methods

A safe method should only read data:

- `GET`
- `HEAD`
- `OPTIONS`

Calling a safe method should not create, update, or delete records.

---

## 9. Idempotent Methods

An idempotent request has the same intended result when repeated.

| Method | Idempotent? | Reason |
|---|---:|---|
| `GET` | Yes | Repeated reads do not change the resource |
| `PUT` | Yes | Repeated replacements produce the same state |
| `DELETE` | Yes | The resource remains deleted |
| `POST` | Usually no | Repeating it may create multiple records |
| `PATCH` | Depends | Some partial updates may produce repeated changes |

For retryable `POST` operations such as payments, use an **idempotency key** to prevent duplicate processing.

---

## Method Summary

| Method | Purpose | Common success code |
|---|---|---:|
| `GET` | Read data | `200` |
| `POST` | Create data | `201` |
| `PUT` | Replace data | `200` or `204` |
| `PATCH` | Partially update data | `200` or `204` |
| `DELETE` | Remove data | `204` |
| `HEAD` | Read headers only | `200` |
| `OPTIONS` | Discover available operations | `204` |
