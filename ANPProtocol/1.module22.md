Lesson 22: Real DID Resolution & DID Documents

In Lesson 21, we used:

AGENT_DID = "did:wba:travel.company.com"


But we cheated a little.

We treated the DID as if it magically gave us identity.

In a real ANP system, a DID must be resolved into a DID Document before it becomes useful. ANP's identity layer is based on DID concepts where identity information, verification methods, and services are obtained through DID resolution.

The Problem

Suppose a message arrives:

{
  "sender": "did:wba:weather.company.com"
}


Question:

Where is the public key?

How do I verify signatures?

What endpoints does this agent expose?

How do I authenticate it?


The DID itself does not contain this information.

Real World Analogy

Think of:

Passport Number


Example:

P12345678


The passport number identifies a person.

But the actual record contains:

Name
Photo
Nationality
Expiration Date


Similarly:

DID


identifies an agent.

The:

DID Document


contains the details.

DID Resolution

Resolution means:

DID
 ↓
Lookup
 ↓
DID Document


Example:

did:wba:weather.company.com


↓

{
  "id": "did:wba:weather.company.com",
  "verificationMethod": [...],
  "service": [...]
}

What Is a DID Document?

A DID Document is the metadata associated with a DID and typically contains:

Identity Information
Verification Methods
Public Keys
Authentication Methods
Service Endpoints


This is the foundation for authentication and secure communication.

Simplified DID Document
did_document = {

    "id":
    "did:wba:weather.company.com",

    "verificationMethod": [

        {
            "id": "#key-1",

            "type":
            "Ed25519",

            "publicKey":
            "ABC123XYZ"
        }
    ],

    "service": [

        {
            "id":
            "#messaging",

            "type":
            "MessagingService",

            "endpoint":
            "https://weather.company.com/message"
        }
    ]
}

Understanding Each Section
id
"id":
"did:wba:weather.company.com"


Identifies the owner of this document.

verificationMethod

Contains cryptographic verification methods.

Example:

{
    "id":"#key-1",

    "type":"Ed25519",

    "publicKey":"ABC123XYZ"
}


Used for:

Signature Verification
Authentication
Trust Establishment

service

Contains service endpoints.

Example:

{
    "endpoint":
    "https://weather.company.com/message"
}


Allows others to contact the agent.

Building a Resolver

Let's simulate resolution.

did_registry = {

    "did:wba:weather.company.com": {

        "id":
        "did:wba:weather.company.com",

        "verificationMethod": [

            {
                "id": "#key-1",

                "publicKey":
                "ABC123XYZ"
            }
        ],

        "service": [

            {
                "endpoint":
                "https://weather.company.com/message"
            }
        ]
    }
}

Resolver Function
def resolve_did(did):

    return did_registry.get(did)


Usage:

document = resolve_did(
    "did:wba:weather.company.com"
)

print(document)

DID Document vs Agent Description

Many people confuse these.

DID Document

Answers:

Who are you?

How do I verify you?

How do I contact you?


Contains:

Keys
Verification Methods
Services

Agent Description

Answers:

What can you do?


Contains:

Capabilities
Metadata
Protocols
Versions

Side-by-Side
DID Document

  "verificationMethod": [...],
  "service": [...]
}

Agent Description

  "capabilities": [
      "weather_lookup"
  ],

  "supported_protocols": [
      "json-v2"
  ]
