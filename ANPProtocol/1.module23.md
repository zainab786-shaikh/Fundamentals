The Problem

Suppose a message arrives:

{
  "sender": "did:wba:weather.company.com"
}


How do we know:

The sender owns that DID
RIGHT NOW?


Not:

Yesterday

Last Week

At Some Point


But at this exact moment.

Why DID Alone Is Insufficient

Anyone can claim:

{
  "did": "did:wba:weather.company.com"
}


Identity claim:

Not Trusted ❌


We need cryptographic proof.

Step 4: Authentication Service

Why?

Unique

Step 5: Challenge Endpoint
@app.get("/challenge/{did}")
def get_challenge(did):

    challenge = (
        secrets.token_hex(16)
    )

    challenge_store[did] = challenge

    return {

        "challenge":
        challenge
    }


Example response:

{
  "challenge":
  "af2391b18b9cc551"
}

What Just Happened?

Travel Agent asks:

Prove your identity.


Authentication Service replies:

Sign this challenge.

Step 6: Agent Signs Challenge
weather_agent.py
def sign_challenge(
    challenge
):

    return private_key.sign(

        challenge.encode()
    )


Usage:

signature = sign_challenge(
    challenge
)

Step 7: Authentication Request

Weather Agent sends:

{
  "did":
  "did:wba:weather.company.com",

  "signature":
  "<binary signature>"
}

Step 8: Verify Endpoint
@app.post("/verify")
def verify_auth(
    request: dict
):


Inputs:

did = request["did"]

signature = request["signature"]

Resolve DID
document = resolve_did(did)

Get Public Key
public_key = (

    document["verificationMethod"][0]
            ["publicKey"]
)

Retrieve Stored Challenge
challenge = challenge_store[did]

Verify Signature
try:

    public_key.verify(

        signature,

        challenge.encode()
    )

    return {

        "authenticated":
        True
    }

except Exception:

    return {

        "authenticated":
        False
    }

Why Replay Attacks Fail

Imagine an attacker captures:

Challenge: abc123

Signature: XYZ


Tomorrow the challenge becomes:

QWE999


The old signature:

XYZ


will fail verification.

This is why challenges must be:

Random
Unique
Short-lived

Add Challenge Expiration

Instead of:

challenge_store[did] = challenge


Store:

challenge_store[did] = {

    "challenge":
    challenge,

    "expires_at":
    time.time() + 300
}


Meaning:

5-minute validity
