Now let's solve a real authentication problem:

How do I know the agent is present right now and actually controls the private key?

This is exactly what DID-based authentication protocols are designed to prove. ANP includes DID authentication mechanisms that use cryptographic verification rather than passwords.

The Problem

Suppose a Weather Agent sends:

I am did:wba:weather.company.com


and provides a valid public key.

Question:

How do I know
it currently owns the private key?


Maybe:

An attacker copied old messages.

An attacker replayed an old signature.

An attacker stole data.


We need a live proof.

Real World Analogy

Imagine logging into a bank.

The bank says:

Enter OTP: 583291


You don't send:

An old OTP


You must prove yourself right now.

Authentication works similarly.

ANP Solution: Challenge-Response

Verifier generates:

Random Challenge


Example:

9f84a2c7


Agent signs it.

Verifier checks signature.

If valid:

Authentication Successful ✅

Step 1: Generate a Challenge

Never use:

static challenge


Use randomness.

import secrets

challenge = secrets.token_hex(16)

print(challenge)


Example:

f1a23c44c9d2a8e1d90ab33f5b7e912c


Each authentication gets a new challenge.

Step 2: Agent Receives Challenge
challenge = "f1a23c44c9d2a8e1d90ab33f5b7e912c"


Convert to bytes:

message = challenge.encode()

Step 3: Sign Challenge
signature = private_key.sign(
    message
)


Agent sends:

{
    "did":
    "did:wba:weather.company.com",

    "signature":
    signature
}

Step 4: Resolve DID

Coordinator resolves:

did:wba:weather.company.com


Gets DID Document:

{
    "id":
    "did:wba:weather.company.com",

    "public_key":
    public_key
}

Step 5: Verify
public_key.verify(
    signature,
    message
)


If verification succeeds:

Agent owns private key ✅

Complete Example
from cryptography.hazmat.primitives.asymmetric import ed25519
import secrets

# Generate agent identity

private_key = (
    ed25519.Ed25519PrivateKey.generate()
)

public_key = (
    private_key.public_key()
)

# Coordinator creates challenge

challenge = secrets.token_hex(16)

message = challenge.encode()

# Agent signs challenge

signature = private_key.sign(
    message
)

# Coordinator verifies

public_key.verify(
    signature,
    message
)

print("Authenticated")


Output:

Authenticated

What Just Happened?

Coordinator asked:

Prove you're the owner
of this DID.


Agent proved it by:

Signing a fresh challenge
with the private key.


No passwords involved.

Replay Attack Problem

Suppose yesterday's challenge was:

ABC123


Attacker captures:

Challenge

Signature


Tomorrow attacker resends:

Old Signature


Will it work?

No.

Because tomorrow's challenge is:

XYZ999


Different challenge.

Different signature required.

Why Random Challenges Matter

Bad:

challenge = "hello"


Always same.

Good:

challenge =
secrets.token_hex(16)


Different every time.

Authentication Function

Let's package it.

def authenticate(
    public_key,
    challenge,
    signature
):

    try:

        public_key.verify(
            signature,
            challenge.encode()
        )

        return True

    except Exception:

        return False


Usage:

result = authenticate(
    public_key,
    challenge,
    signature
)

print(result)


Output:

True
