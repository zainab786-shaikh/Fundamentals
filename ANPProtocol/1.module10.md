Now we'll learn the most common communication pattern in ANP:

Request
   ↓
Response


This pattern is foundational for agent interactions, where one agent asks another agent to perform some work and receives a result back. ANP's messaging layer builds upon identity, authentication, and secure communication to support such exchanges.

The Problem

Suppose:

Travel Agent


needs weather information.

It discovers:

Weather Agent


Question:

How does Travel Agent ask?

How does Weather Agent reply?

How does Travel Agent know which reply belongs to which request?

Real World Analogy

Think about customer support.

You submit:

Ticket #123


Later support replies:

Response for Ticket #123


The ticket number connects:

Request ↔ Response


Agent messaging needs something similar.

ANP Solution

Each request gets a unique ID.

Example:

request = {

    "message_id":
    "MSG-001",

    "from":
    "did:wba:travel.company.com",

    "to":
    "did:wba:weather.company.com",

    "payload": {

        "action":
        "weather_lookup",

        "city":
        "Mumbai"
    }
}

Understanding the Request
message_id
"MSG-001"


Uniquely identifies this interaction.

from

The requested work.

Weather Agent Processes Request
def handle_request(message):

    city = (
        message["payload"]["city"]
    )

    return f"Sunny in {city}"


Input:

Mumbai


Output:

Sunny in Mumbai

Building the Response

Response references the original message.

response = {

    "message_id":
    "MSG-002",

    "correlation_id":
    "MSG-001",

    "from":
    "did:wba:weather.company.com",

    "to":
    "did:wba:travel.company.com",

    "payload": {

        "weather":
        "Sunny in Mumbai"
    }
}

What is correlation_id?

Very important.

"correlation_id":
"MSG-001"


means:

This response belongs to
request MSG-001


Without this:

Responses become difficult
to match with requests.

Visual Flow
Travel Agent

     |
     | MSG-001

     v

     |
     | Process

MSG-002
(correlation_id=MSG-001)

     |

Why Not Reuse the Same ID?

Request:

MSG-001


Response:

MSG-002


Each message is unique.

The relationship is maintained through:

correlation_id

Python Message Model
from dataclasses import dataclass

@dataclass
class Message:

    message_id: str

    sender: str

    recipient: str

    payload: dict

    correlation_id: str | None = None

Creating a Request
request = Message(

    message_id="MSG-001",

    sender=
    "did:wba:travel.company.com",

    recipient=
    "did:wba:weather.company.com",

    payload={
        "city": "Mumbai"
    }
)

Creating a Response
response = Message(

    message_id="MSG-002",

    sender=
    "did:wba:weather.company.com",

    recipient=
    "did:wba:travel.company.com",

    correlation_id=
    "MSG-001",

    payload={
        "weather":
        "Sunny in Mumbai"
    }
)

Multiple Requests Problem

Suppose Travel Agent sends:

MSG-001 → Mumbai

MSG-002 → Delhi

MSG-003 → Bangalore


Responses arrive:

MSG-101

MSG-102

MSG-103


How do we map them?

Using:

correlation_id


Example:

{
    "message_id":"MSG-101",

    "correlation_id":"MSG-002",

    "weather":"Rainy"
}


Now we know:

Rainy belongs to Delhi.

Generic Request Handler
def process_request(message):

    action = (
        message["payload"]
               ["action"]
    )

    if action == "weather_lookup":

        city = (
            message["payload"]
                   ["city"]
        )

        return {

            "weather":
            f"Sunny in {city}"
        }
