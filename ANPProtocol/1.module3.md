ANP builds on W3C DID concepts, where a DID resolves to a DID Document containing information such as public keys, verification methods, and service endpoints.

Understanding Each Field
id

The DID itself.

"id":
"did:wba:weather.company.com"


Meaning:

This document belongs
to this DID.

verificationMethod

Contains public-key information.

"verificationMethod"


Think:

How can I verify signatures
from this identity?

service

Describes where the agent can be reached.

Example:

{
    "endpoint":
    "https://weather.company.com"
}


Meaning:

Here is the agent's address.

Building a DID Resolver

Imagine:

did_registry = {

    "did:wba:weather.company.com": {

        "id":
        "did:wba:weather.company.com",

        "service": [

            {
                "endpoint":
                "https://weather.company.com"
            }
        ]
    }
}

Resolve Function
def resolve_did(did):

    return did_registry.get(did)


Usage:

document = resolve_did(
    "did:wba:weather.company.com"
)

print(document)


Output:

{
    "id":
    "did:wba:weather.company.com",

    "service": [
        {
            "endpoint":
            "https://weather.company.com"
        }
    ]
}

Python Example

Let's build a tiny resolver.

registry = {

    "did:wba:weather.company.com": {

        "id":
        "did:wba:weather.company.com",

        "service": [

            {
                "endpoint":
                "https://weather.company.com"
            }
        ]
    }
}


def resolve_did(did):

    return registry.get(did)


print(
    resolve_did(
        "did:wba:weather.company.com"
    )
)


Output:

{
    'id': 'did:wba:weather.company.com',

    'service': [
        {
            'endpoint':
            'https://weather.company.com'
        }
    ]
}
