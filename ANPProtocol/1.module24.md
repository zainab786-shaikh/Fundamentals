Lesson 24: Real ANP Message Envelope

In Lesson 23, we built:

DID
   ↓
DID Resolution
   ↓
Authentication


Now we face the next challenge:

What exactly gets sent between agents?

So far we've used simple dictionaries:

{
    "action": "weather_lookup",
    "city": "Mumbai"
}


This works for demos.

But it's not sufficient for a real protocol.

The ANP messaging specifications define structured messaging concepts including identities, message metadata, direct messaging, attachments, groups, encryption, and federation-oriented communication.

The Problem

Suppose the Weather Agent receives:

{
    "city": "Mumbai"
}


Questions:

Who sent this?

When was it sent?

Which protocol version?

Which request is this related to?

Can I verify it?

Is it a request or response?


We don't know.

ANP Solution: Message Envelope

Separate:

Transport Metadata


from

Business Payload


Like an email:

From:
To:
Subject:
Date:

Body

Envelope Structure
{
    "message_id": "...",

    "sender": "...",

    "recipient": "...",

    "timestamp": "...",

    "protocol_version": "...",

    "payload": {...}
}

Field 1: Message ID

Every message must be uniquely identifiable.

Example:

"message_id":
"MSG-001"


Better:

import uuid

message_id = str(
    uuid.uuid4()
)


Example:

550e8400-e29b-41d4

Why Message IDs Matter

Without IDs:

Cannot correlate responses

Cannot trace requests

Cannot audit workflows


With IDs:

Every message is traceable

Field 2: Sender DID
"sender":
"did:wba:travel.company.com"


Answers:

Who created the message?

Field 3: Recipient DID
"recipient":
"did:wba:weather.company.com"


Answers:

Who should process the message?

Field 4: Timestamp
from datetime import datetime

timestamp = (
    datetime.utcnow()
    .isoformat()
)


Example:

2026-11-04T09:00:00Z

Why Timestamps Matter

Useful for:

Auditing

Expiration

Replay Protection

Monitoring

Field 5: Protocol Version

Remember ANP-06 negotiation.

Agents may agree on:

json-v1

json-v2


Store it:

"protocol_version":
"json-v2"


This allows compatibility checks.

Field 6: Message Type

Add:

"type":
"request"


Possible values:

request

response

notification

event

Request Example
"type":
"request"

Response Example
"type":
"response"

Field 7: Correlation ID

Critical for responses.

Request:

{
    "message_id":
    "REQ-001"
}


Response:

{
    "message_id":
    "RES-001",

    "correlation_id":
    "REQ-001"
}


This links them.

Field 8: Payload

Business content.

Example:

"payload": {

    "action":
    "weather_lookup",

    "city":
    "Mumbai"
}


The payload should be independent of transport metadata.

Field 9: Signature

Previously:

Challenge
↓
Signature
↓
Verification


Now apply the same idea to messages.

"signature":
"<signed hash>"


Allows recipients to verify integrity and sender ownership.

Pydantic Model
from pydantic import BaseModel
from typing import Optional


class MessageEnvelope(BaseModel):

    message_id: str

    type: str

    sender: str

    recipient: str

    timestamp: str

    protocol_version: str

    payload: dict

    signature: Optional[str] = None

    correlation_id: Optional[str] = None

Validation Rules

def validate(
    envelope

    assert envelope.message_id

    assert envelope.sender

    assert envelope.recipient

    assert envelope.protocol_version
