
# Topic 11: Logging and Error Handling

Logging records application activity. Error handling returns safe, consistent responses without exposing internal details.

## 1. Configure Structured Logging

```python name=app/logging_config.py
import logging
import sys


def configure_logging() -> None:
    logging.basicConfig(
        level=logging.INFO,
        format=(
            "%(asctime)s %(levelname)s %(name)s "
           "%(message)s"
        ),
        handlers=[logging.StreamHandler(sys.stdout)],
        force=True,
    )
```

Send logs to standard output so Docker or a hosting platform can collect them. Use `INFO` rather than `DEBUG` in production.

## 3. Add a Request ID

```python name=app/middleware/request_id.py
from contextvars import ContextVar
from uuid import uuid4

from fastapi import Request, Response

request_id_context: ContextVar[str] = ContextVar(
    "request_id",
    default="unknown",
)


async def request_id_middleware(
    request: Request,
    call_next,
) -> Response:
    request_id = request.headers.get("X-Request-ID") or str(uuid4())
    token = request_id_context.set(request_id)

    try:
        response = await call_next(request)
        response.headers["X-Request-ID"] = request_id
        return response
    finally:
        request_id_context.reset(token)
```

A request ID connects logs generated during the same request. A new ID is generated when the client does not provide one.

Register it:

```python name=app/main.py
from app.middleware.request_id import request_id_middleware

app.middleware("http")(request_id_middleware)
```

## 4. Log HTTP Requests

```python name=app/middleware/request_logging.py
import logging
from time import perf_counter

from fastapi import Request, Response

from app.middleware.request_id import request_id_context

logger = logging.getLogger(__name__)


async def request_logging_middleware(
    request: Request,
    call_next,
) -> Response:
    started_at = perf_counter()

    response = await call_next(request)

    duration_ms = (perf_counter() - started_at) * 1_000

    logger.info(
        "HTTP request completed method=%s path=%s status=%s "
        "duration_ms=%.2f request_id=%s",
        request.method,
        request.url.path,
        response.status_code,
        duration_ms,
        request_id_context.get(),
    )

    return response
```

Log the method, path, status, duration, and request ID. Do not log authorization headers, passwords, tokens, or full request bodies.

Register it:

```python name=app/main.py
from app.middleware.request_logging import request_logging_middleware

app.middleware("http")(request_logging_middleware)
```

## 5. Define a Custom Application Error

```python name=app/exceptions.py
class ApplicationError(Exception):
    def __init__(
        self,
        message: str,
        status_code: int = 400,
        error_code: str = "application_error",
    ) -> None:
        self.message = message
        self.status_code = status_code
        self.error_code = error_code
        super().__init__(message)
```

A custom exception provides a standard status, message, and machine-readable error code.

## 6. Handle Custom Errors Centrally

```python name=app/handlers.py
from fastapi import Request
from fastapi.responses import JSONResponse

from app.exceptions import ApplicationError
from app.middleware.request_id import request_id_context


async def application_error_handler(
    request: Request,
    exception: ApplicationError,
) -> JSONResponse:
    return JSONResponse(
        status_code=exception.status_code,
        content={
            "error": {
                "code": exception.error_code,
                "message": exception.message,
                "request_id": request_id_context.get(),
            }
        },
    )
```

Register the handler:

```python name=app/main.py
from app.exceptions import ApplicationError
from app.handlers import application_error_handler

app.add_exception_handler(
    ApplicationError,
    application_error_handler,
)
```

All application errors now have a consistent response format.

## 7. Raise a Domain Error

```python name=app/services/user_service.py
from sqlalchemy.orm import Session

from app.exceptions import ApplicationError


class UserService:
    def get_user(self, db: Session, user_id: int):
        user = self.repository.get_by_id(db, user_id)

        if user is None:
            raise ApplicationError(
                message="User not found",
                status_code=404,
                error_code="user_not_found",
            )

        return user
```

The service describes the business error. The central handler converts it into an HTTP response.

Example response:

```json name=user-not-found-response.json
{
  "error": {

    "message": "User not found",
    "request_id": "834d2f15-3ea0-416c-b36d-2fb85bb1be87"
  }
}
```

## 8. Handle Validation Errors

```python name=app/handlers.py
from fastapi import Request
from fastapi.exceptions import RequestValidationError
from fastapi.responses import JSONResponse

from app.middleware.request_id import request_id_context


async def validation_error_handler(
    request: Request,
    exception: RequestValidationError,
) -> JSONResponse:
    return JSONResponse(
        status_code=422,
        content={
            "error": {
                "code": "validation_failed",
                "message": "Request validation failed",
                "details": exception.errors(),
                "request_id": request_id_context.get(),
            }
        },
    )
```

Register it:

```python name=app/main.py
from fastapi.exceptions import RequestValidationError

from app.handlers import validation_error_handler

app.add_exception_handler(
    RequestValidationError,
    validation_error_handler,
)
```

Validation details help clients correct invalid fields. Ensure rejected values do not contain secrets before returning them.

## 9. Handle Unexpected Errors Safely

```python name=app/handlers.py
import logging

from fastapi import Request
from fastapi.responses import JSONResponse

from app.middleware.request_id import request_id_context

logger = logging.getLogger(__name__)


async def unexpected_error_handler(
    request: Request,
    exception: Exception,
) -> JSONResponse:
    request_id = request_id_context.get()

    logger.exception(
        "Unexpected error path=%s request_id=%s",
        request.url.path,
        request_id,
    )

    return JSONResponse(
        status_code=500,
        content={
            "error": {
                "code": "internal_error",
                "message": "Internal server error",
                "request_id": request_id,
            }
        },
    )
```

Register it:

```python name=app/main.py
from app.handlers import unexpected_error_handler

app.add_exception_handler(Exception, unexpected_error_handler)
```

The server logs technical details but returns a generic message. This prevents stack traces and database details from leaking.

## 10. Roll Back Failed Transactions

```python name=app/services/user_service.py
import logging

from sqlalchemy.exc import IntegrityError, SQLAlchemyError
from sqlalchemy.orm import Session

from app.exceptions import ApplicationError

logger = logging.getLogger(__name__)


def create_user(db: Session, user) -> object:
    try:
        db.add(user)
        db.commit()
        db.refresh(user)
        return user
    except IntegrityError:
        db.rollback()
        raise ApplicationError(
            message="Email is already registered",
            status_code=409,
            error_code="email_conflict",
        ) from None
    except SQLAlchemyError:
        db.rollback()
        logger.exception("Database operation failed")
        raise ApplicationError(
            message="Unable to complete the request",
            status_code=500,
            error_code="database_error",
        ) from None
```

Always roll back after a database failure. Do not return raw SQL or database error messages to clients.

## 11. Add Liveness and Readiness Endpoints

```python name=app/routers/health.py
from fastapi import APIRouter, HTTPException, status
from sqlalchemy import text

from app.dependencies import DatabaseSession

router = APIRouter(tags=["System"])


@router.get("/health/live")
def liveness() -> dict[str, str]:
    return {"status": "alive"}


@router.get("/health/ready")
def readiness(db: DatabaseSession) -> dict[str, str]:
    try:
        db.execute(text("SELECT 1"))
    except Exception:
        raise HTTPException(
            status_code=status.HTTP_503_SERVICE_UNAVAILABLE,
            detail="Service unavailable",
        ) from None

    return {"status": "ready"}
```

- **Liveness** confirms that the application process is running.
- **Readiness** confirms that required services, such as the database, are available.

Do not expose database names, credentials, or internal infrastructure details.

## 12. Add an Audit Log

```python name=app/services/user_service.py
import logging

from sqlalchemy.orm import Session

audit_logger = logging.getLogger("audit")


def deactivate_user(
    db: Session,
    target_user,
    acting_user_id: int,
) -> None:
    target_user.is_active = False
    db.commit()

    audit_logger.info(
        "User deactivated actor_id=%s target_id=%s",
        acting_user_id,
        target_user.id,
    )
```

Audit logs record who performed sensitive actions. Record identifiers and actions, but never record passwords, tokens, or private personal data.

## Logging Rules

- Log security events, errors, and important state changes.
- Never log passwords, tokens, API keys, cookies, or connection strings.
- Avoid logging full request and response bodies.
- Use request IDs to trace failures.
- Return generic production errors.
- Restrict access to logs because they may contain user identifiers.
- Configure log retention and monitoring alerts.
- Use audit logs for privileged or destructive operations.
