
# Topic 4: Database Fundamentals

We will use **PostgreSQL-style SQL**. SQLite is suitable for initial practice, while PostgreSQL is recommended for production FastAPI applications.

## 1. Tables, Rows, and Columns

```sql name=01_create_users.sql
CREATE TABLE users (
    id INTEGER PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(255) NOT NULL UNIQUE,
    is_active BOOLEAN NOT NULL DEFAULT TRUE
);
```

- Table: `users`
- Columns: `id`, `name`, `email`, `is_active`
- Each stored user is a row.
- `NOT NULL` requires a value.
- `UNIQUE` prevents duplicate emails.

---

## 2. Create a Record

```sql name=02_insert_user.sql
INSERT INTO users (id, name, email)
VALUES (1, 'Alice', 'alice@example.com');
```

`INSERT` adds a new row. The database automatically uses `TRUE` for `is_active`.

---

## 3. Read Records

```sql name=03_select_users.sql
SELECT id, name, email
FROM users
WHERE is_active = TRUE;
```

`SELECT` reads specific columns. `WHERE` filters the results.

Avoid `SELECT *` when you only need a few columns.

---

## 4. Update a Record

```sql name=04_update_user.sql
UPDATE users
SET name = 'Alice Smith'
WHERE id = 1;
```

`UPDATE` changes existing data. Always use an appropriate `WHERE` condition to avoid updating every row.

---

## 5. Delete a Record

```sql name=05_delete_user.sql
DELETE FROM users
WHERE id = 1;
```

`DELETE` removes matching rows. Without `WHERE`, it removes every row from the table.

---

## 6. Primary and Foreign Keys

```sql name=06_create_posts.sql
CREATE TABLE posts (
    id INTEGER PRIMARY KEY,
    title VARCHAR(200) NOT NULL,
    content TEXT NOT NULL,
    author_id INTEGER NOT NULL,
    FOREIGN KEY (author_id) REFERENCES users(id)
);
```

- `posts.id` uniquely identifies a post.
- `author_id` references an existing user.
- The foreign key protects relationship integrity.

---

## 7. One-to-Many Relationship

```sql name=07_user_posts.sql
SELECT
    users.name,
    posts.title
FROM users
JOIN posts ON posts.author_id = users.id
WHERE users.id = 1;
```

One user can have many posts. `JOIN` combines related rows from both tables.

---

## 8. One-to-One Relationship

```sql name=08_create_profiles.sql
CREATE TABLE profiles (
    id INTEGER PRIMARY KEY,
    bio VARCHAR(500),
    user_id INTEGER NOT NULL UNIQUE,
    FOREIGN KEY (user_id) REFERENCES users(id)
);
```

`UNIQUE` on `user_id` ensures that each user has at most one profile.

---

## 9. Many-to-Many Relationship

```sql name=09_many_to_many.sql
CREATE TABLE tags (
    id INTEGER PRIMARY KEY,
    name VARCHAR(50) NOT NULL UNIQUE
);

CREATE TABLE post_tags (
    post_id INTEGER NOT NULL,
    tag_id INTEGER NOT NULL,
    PRIMARY KEY (post_id, tag_id),
    FOREIGN KEY (post_id) REFERENCES posts(id),
    FOREIGN KEY (tag_id) REFERENCES tags(id)
);
```

A post can have many tags, and a tag can belong to many posts. The `post_tags` junction table connects them.

---

## 10. Sorting and Limiting Results

```sql name=10_sort_and_limit.sql
SELECT id, title
FROM posts
ORDER BY id DESC
LIMIT 10;
```

- `ORDER BY` sorts the results.
- `DESC` means descending order.
- `LIMIT` restricts the number of rows returned.

---

## 11. Indexes

```sql name=11_create_index.sql
CREATE INDEX idx_posts_author_id
ON posts(author_id);
```

An index can improve searches and joins using `author_id`. Indexes consume storage and can slightly slow writes, so add them only to frequently queried columns.

---

## 12. Transactions

```sql name=12_transaction.sql
BEGIN;

UPDATE accounts
SET balance = balance - 100
WHERE id = 1;

UPDATE accounts
SET balance = balance + 100
WHERE id = 2;

COMMIT;
```

A transaction treats multiple operations as one unit. Use `ROLLBACK` instead of `COMMIT` if an operation fails.

---

## 13. Database Constraints

```sql name=13_constraints.sql
CREATE TABLE products (
    id INTEGER PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    price NUMERIC(10, 2) NOT NULL CHECK (price > 0),
    stock INTEGER NOT NULL DEFAULT 0 CHECK (stock >= 0)
);
```

Constraints reject invalid data:

- `NOT NULL`: Value is required.
- `CHECK`: Value must satisfy a condition.
- `DEFAULT`: Supplies a default value.
- `PRIMARY KEY`: Uniquely identifies a row.

## 14. Parameterized Queries in Python

```python name=14_safe_query.py
import sqlite3

connection = sqlite3.connect("app.db")

try:
    email = "alice@example.com"

    user = connection.execute(
        "SELECT id, name FROM users WHERE email = ?",
        (email,),
    ).fetchone()

    print(user)
finally:
    connection.close()
```

The parameter is passed separately from the SQL. This prevents SQL injection; never build SQL with untrusted input using string concatenation.

## 15. Basic Normalization

```sql name=15_normalization.sql
CREATE TABLE categories (
    id INTEGER PRIMARY KEY,
    name VARCHAR(100) NOT NULL UNIQUE
);

CREATE TABLE products (
    id INTEGER PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    category_id INTEGER NOT NULL,
    FOREIGN KEY (category_id) REFERENCES categories(id)
);
```

Store category details once in `categories` instead of repeating category names for every product. This reduces duplication and inconsistency.
