# 1. Command-Line Application Development

A command-line interface (CLI) application runs from a terminal, accepts input as arguments or standard input, performs an operation, and returns output plus an exit code.

Example:

`python app.py greet Alice --uppercase`

---

## 1.1 CLI Fundamentals

### Command-line application structure

A CLI usually contains:

1. **Entry point** — starts the application.
2. **Input parsing** — reads arguments and options.
3. **Business logic** — performs the task.
4. **Output handling** — displays results or errors.
5. **Exit handling** — returns an exit code.

```python name=basic_cli.py
import sys


def main() -> int:
    print("Application started")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

`raise SystemExit(main())` passes the return value to the operating system.

---

### Commands, subcommands, arguments, and options

- **Command:** The application being executed: `git`
- **Subcommand:** A specific operation: `git clone`
- **Argument:** A required or positional value: `git clone repository_url`
- **Option:** A named setting: `git clone --depth 1 repository_url`

Example:

`tool convert input.csv output.json --pretty`

- `convert` — subcommand
- `input.csv` and `output.json` — positional arguments
- `--pretty` — option/flag

---

### Positional versus optional arguments

A positional argument is identified by its position. An optional argument has a name such as `--output`.

```python name=arguments.py
import argparse

parser = argparse.ArgumentParser()
parser.add_argument("input_file")                 # Positional
parser.add_argument("--output", default="out.txt")  # Optional
args = parser.parse_args()

print(args.input_file, args.output)
```

Usage:

`python arguments.py data.txt --output result.txt`

---

### Flags, default values, and environment variables

- A **flag** enables or disables behavior.
- A **default value** is used when an option is omitted.
- An **environment variable** provides external configuration.

```python name=settings.py
import argparse
import os

parser = argparse.ArgumentParser()
parser.add_argument("--verbose", action="store_true")
parser.add_argument("--port", type=int, default=8080)
args = parser.parse_args()

api_url = os.getenv("APP_API_URL", "https://api.example.com")

print(args.verbose, args.port, api_url)
```

Do not store passwords or API keys directly in source code.

---

### Standard input, output, and error streams

CLI applications use three standard streams:

- `stdin` — input
- `stdout` — normal output
- `stderr` — warnings and errors

```python name=streams.py
import sys

name = sys.stdin.readline().strip()
print(f"Hello, {name}", file=sys.stdout)
print("Example warning", file=sys.stderr)
```

Pipe input into the application:

`echo "Alice" | python streams.py`

---

### Exit codes and application lifecycle

By convention:

- `0` — success
- Non-zero — failure
- `1` — general error
- `2` — commonly used for invalid command-line usage

```python name=exit_codes.py
import sys


def main() -> int:
    if len(sys.argv) < 2:
        print("Error: missing file name", file=sys.stderr)
        return 2

    print(f"Processing {sys.argv[1]}")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

Application lifecycle:

**Start → parse input → validate → execute → output result → clean up → exit**

## 1.2 CLI Frameworks

### Building standard-library CLIs with `argparse`

`argparse` is included with Python and requires no additional dependency.

```python name=argparse_app.py
import argparse

parser = argparse.ArgumentParser(description="Greet a user")
parser.add_argument("name")
parser.add_argument("--uppercase", action="store_true")
args = parser.parse_args()

message = f"Hello, {args.name}"
print(message.upper() if args.uppercase else message)
```

Usage:

`python argparse_app.py Alice --uppercase`

---

### Building command-based applications with Click

Click is a third-party framework designed for command-based applications.

Install it:

`python -m pip install click`

```python name=click_app.py
import click


@click.group()
def cli() -> None:
    """User management utility."""


@cli.command()
@click.argument("name")
@click.option("--admin", is_flag=True, help="Create an administrator")
def create(name: str, admin: bool) -> None:
    role = "administrator" if admin else "user"
    click.echo(f"Creating {role}: {name}")


if __name__ == "__main__":
    cli()
```

Usage:

`python click_app.py create Alice --admin`

---

### Building type-safe CLIs with Typer

Typer uses Python type hints to define and validate CLI input. It is built on Click.

Install it:

`python -m pip install typer`

```python name=typer_app.py
import typer

app = typer.Typer()


@app.command()
def greet(name: str, count: int = 1) -> None:
    if count < 1:
        raise typer.BadParameter("count must be at least 1")

    for _ in range(count):
        typer.echo(f"Hello, {name}")


if __name__ == "__main__":
    app()
```

Usage:

`python typer_app.py Alice --count 2`

---

### Selecting between `argparse`, Click, and Typer

| Framework | Best suited for | Advantages | Trade-offs |
|---|---|---|---|
| `argparse` | Small tools and zero-dependency scripts | Built into Python | More boilerplate |
| Click | Mature command-based applications | Flexible and widely used | Third-party dependency |
| Typer | Modern typed applications | Type hints and automatic help | Adds Typer and Click dependencies |

**Simple recommendation:**

- Use `argparse` when avoiding dependencies is important.
- Use Click for highly customized or mature command trees.
- Use Typer for new, type-annotated CLI applications.

## 1.3 User Interaction

### Interactive prompts and confirmations

Prompts collect information while the application is running.

```python name=prompts.py
from getpass import getpass

username = input("Username: ").strip()
password = getpass("Password: ")

confirmation = input(f"Create user {username}? [y/N]: ").strip().lower()
if confirmation == "y":
    print("User created")
else:
    print("Cancelled")
```

Confirm destructive operations such as deleting files. Use `getpass()` so secrets are not displayed.

---

### Progress bars and status indicators

`tqdm` provides progress bars.

Install it:

`python -m pip install tqdm`

```python name=progress.py
import time
from tqdm import tqdm

for _ in tqdm(range(10), desc="Processing"):
    time.sleep(0.1)
```

Avoid progress animations when output is redirected to a file or CI log.

---

### Colored and formatted terminal output

Rich supports colors and formatted terminal output.

Install it:

`python -m pip install rich`

```python name=colored_output.py
from rich.console import Console

console = Console()
console.print("[green]Success:[/] deployment completed")
console.print("[red]Error:[/] deployment failed")
```

Do not use color as the only way to communicate status; include words such as “Success” or “Error” for accessibility.

---

### Tables and structured output

```python name=table_output.py
from rich.console import Console
from rich.table import Table

table = Table("Name", "Status")
table.add_row("API", "Healthy")
table.add_row("Database", "Healthy")

Console().print(table)
```

Tables are useful for people, but JSON or CSV is usually better for automation.

---

### Supporting JSON, CSV, and plain-text output

```python name=output_formats.py
import argparse
import csv
import json
import sys

records = [{"name": "API", "status": "healthy"}]

parser = argparse.ArgumentParser()
parser.add_argument("--format", choices=["text", "json", "csv"], default="text")
args = parser.parse_args()

if args.format == "json":
    print(json.dumps(records, indent=2))
elif args.format == "csv":
    writer = csv.DictWriter(sys.stdout, fieldnames=["name", "status"])
    writer.writeheader()
    writer.writerows(records)
else:
    for record in records:
        print(f"{record['name']}: {record['status']}")
```

Usage:

`python output_formats.py --format json`

Shell completion suggests commands and options when the user presses Tab.

Typer can install completion scripts:

`python typer_app.py --install-completion`

Completion support depends on the framework and shell, such as Bash, Zsh, Fish, or PowerShell.

## 1.4 Configuration and Validation

### Command-line configuration files

Configuration files store reusable application settings.

```python name=config.json
{
  "host": "localhost",
  "port": 8080
}
```

```python name=read_config.py
import json
from pathlib import Path

config_path = Path("config.json").resolve()

with config_path.open(encoding="utf-8") as file:
    config = json.load(file)

print(config["host"], config["port"])
```

Validate configuration values before using them.

---

### Environment-based configuration

Environment variables are useful for deployment-specific values and secrets.

```python name=environment_config.py
import os

api_url = os.getenv("APP_API_URL", "https://api.example.com")
api_key = os.getenv("APP_API_KEY")

if not api_key:
    raise SystemExit("APP_API_KEY is required")
```

PowerShell example:

`$env:APP_API_KEY = "secret-value"`

Bash example:

`export APP_API_KEY="secret-value"`

Use a secret manager in production rather than saving secrets in scripts or committed `.env` files.

---

### Argument and input validation

Validate type, range, length, and allowed values.

```python name=validation.py
import argparse


def valid_port(value: str) -> int:
    port = int(value)
    if not 1 <= port <= 65535:
        raise argparse.ArgumentTypeError("port must be between 1 and 65535")
    return port


parser = argparse.ArgumentParser()
parser.add_argument("--port", type=valid_port, default=8080)
args = parser.parse_args()

print(f"Using port {args.port}")
```

Allow-list validation is safer than trying to reject every possible invalid value.

---

### Secure password and secret input

Use `getpass` so the value is not displayed.

```python name=secret_input.py
from getpass import getpass

secret = getpass("API secret: ")

if len(secret) < 12:
    raise SystemExit("Secret must contain at least 12 characters")
```

Avoid printing, logging, or passing secrets as command-line arguments because process-listing tools may expose them.

---

### Configuration precedence

A common precedence order is:

**Command-line option → environment variable → configuration file → default**

```python name=configuration_precedence.py
import argparse
import os

FILE_PORT = 7000

parser = argparse.ArgumentParser()
parser.add_argument("--port", type=int)
args = parser.parse_args()

port = args.port or int(os.getenv("APP_PORT", FILE_PORT))
print(port)
```

For numeric values where `0` may be valid, explicitly check `args.port is not None` instead of using `or`.

---

### Meaningful error messages

A good error message explains:

- What failed
- Why it failed
- How to correct it

```python name=errors.py
from pathlib import Path
import sys

path = Path("input.txt")

if not path.is_file():
    print(
        f"Error: input file '{path}' does not exist. "
        "Provide an existing file path.",
        file=sys.stderr,
    )
    raise SystemExit(2)
```

Do not expose stack traces, secrets, or internal system details to end users in production.

## 1.5 Developer Tools

### Code-generation utilities

Code generators create repetitive source files from templates.

Example command:

`python generate.py User`

Possible result:

- `models/user.py`
- `tests/test_user.py`

Treat template input as data. Do not execute user-supplied template content.

---

### Project scaffolding tools

Scaffolding tools create an initial project structure.

Example:

`python scaffold.py my_app`

Possible structure:

```text
my_app/
├── pyproject.toml
├── README.md
├── src/
│   └── my_app/
└── tests/
```

Validate the project name and use `pathlib` to prevent path traversal such as `../../other-folder`.

---

### Log inspection tools

A log tool can filter entries by level or date.

```python name=inspect_log.py
from pathlib import Path

for line in Path("application.log").read_text(encoding="utf-8").splitlines():
    if "ERROR" in line:
        print(line)
```

For large files, iterate over the file instead of loading everything into memory.

---

### Source-file analysis tools

These tools inspect source code for imports, functions, complexity, or policy violations.

```python name=analyze_source.py
import ast
from pathlib import Path

source = Path("sample.py").read_text(encoding="utf-8")
tree = ast.parse(source)

for node in ast.walk(tree):
    if isinstance(node, ast.FunctionDef):
        print(node.name)
```

Using `ast` is safer and more reliable than parsing Python code with regular expressions.

---

### Build and deployment helpers

Build helpers automate repeatable tasks.

Examples:

- `python -m build`
- Run tests before deployment
- Create a container image
- Validate environment variables
- Publish an artifact

A helper should stop immediately when a required step fails and return a non-zero exit code.

---

### Git and repository utilities

Repository utilities may inspect status, branches, or commits.

`git status --short`

When calling Git from Python, pass arguments as a list and avoid `shell=True`.

```python name=git_status.py
import subprocess

result = subprocess.run(
    ["git", "status", "--short"],
    check=True,
    capture_output=True,
    text=True,
    timeout=30,
)

print(result.stdout)
```

This reduces command-injection risk and handles paths containing spaces correctly.

## 1.6 File Conversion Applications

### Text and character-encoding conversion

Convert text from one encoding to another.

```python name=encoding_conversion.py
from pathlib import Path

text = Path("input.txt").read_text(encoding="latin-1")
Path("output.txt").write_text(text, encoding="utf-8")
```

Handle encoding errors explicitly when processing untrusted files.

---

### CSV and JSON conversion

```python name=csv_to_json.py
import csv
import json
from pathlib import Path

with Path("input.csv").open(encoding="utf-8", newline="") as file:
    rows = list(csv.DictReader(file))

Path("output.json").write_text(
    json.dumps(rows, indent=2),
    encoding="utf-8",
)
```

CSV stores flat tabular data, while JSON supports nested objects and arrays.

---

### XML and YAML conversion

- XML is common in older integrations and document formats.
- YAML is commonly used for human-readable configuration.

YAML requires a third-party library:

`python -m pip install PyYAML`

```python name=json_to_yaml.py
import json
from pathlib import Path
import yaml

data = json.loads(Path("input.json").read_text(encoding="utf-8"))

Path("output.yaml").write_text(
    yaml.safe_dump(data, sort_keys=False),
    encoding="utf-8",
)
```

Always use `yaml.safe_load()` for untrusted YAML. Do not use unsafe object deserialization.

---

### Image and document conversion

Pillow can convert image formats.

`python -m pip install Pillow`

```python name=image_conversion.py
from pathlib import Path
from PIL import Image

source = Path("input.png")
destination = Path("output.jpg")

with Image.open(source) as image:
    image.convert("RGB").save(destination, quality=90)
```

Validate file type and size before processing uploaded images. Document conversion may require tools such as LibreOffice or Pandoc.

---

### Batch conversion

Batch conversion processes multiple files.

```python name=batch_conversion.py
from pathlib import Path

input_directory = Path("input")
output_directory = Path("output")
output_directory.mkdir(parents=True, exist_ok=True)

for source in input_directory.glob("*.txt"):
    destination = output_directory / f"{source.stem}.utf8.txt"
    text = source.read_text(encoding="latin-1")
    destination.write_text(text, encoding="utf-8")
```

Use resolved paths and ensure output remains inside the intended directory.

---

### Conversion validation and error reporting

Verify that conversion succeeded and report individual failures.

```python name=conversion_validation.py
from pathlib import Path
import sys

try:
    source = Path("input.txt")
    text = source.read_text(encoding="utf-8")

    if not text.strip():
        raise ValueError("input file is empty")

    Path("output.txt").write_text(text.upper(), encoding="utf-8")
except (OSError, UnicodeError, ValueError) as error:
    print(f"Conversion failed: {error}", file=sys.stderr)
    raise SystemExit(1)
```

For batch operations, provide a summary such as “8 succeeded, 2 failed.”

## 1.7 Administration Utilities

### File-system administration

Examples include listing, copying, moving, archiving, and deleting files.

```python name=copy_file.py
from pathlib import Path
import shutil

source = Path("data.txt")
destination = Path("backup/data.txt")

destination.parent.mkdir(parents=True, exist_ok=True)
shutil.copy2(source, destination)
```

Require confirmation before deletion and avoid following untrusted symbolic links.

---

### Process and service management

`subprocess` starts and monitors external programs.

```python name=run_process.py
import subprocess

try:
    result = subprocess.run(
        ["python", "--version"],
        check=True,
        capture_output=True,
        text=True,
        timeout=10,
    )
    print(result.stdout or result.stderr)
except subprocess.TimeoutExpired:
    raise SystemExit("Command timed out")
except subprocess.CalledProcessError as error:
    raise SystemExit(f"Command failed with exit code {error.returncode}")
```

Service management differs between Windows, Linux, and macOS and may require elevated permissions.

---

### User and permission utilities

These tools inspect users, groups, roles, or file permissions.

```python name=file_permissions.py
from pathlib import Path
import stat

path = Path("private.txt")
path.chmod(stat.S_IRUSR | stat.S_IWUSR)
```

This requests owner-only read/write access on POSIX systems. Windows permissions use a different security model.

Follow least privilege: request administrative access only when the operation truly requires it.

---

### System health checks

Health checks inspect resources or dependencies.

Install `psutil`:

`python -m pip install psutil`

```python name=health_check.py
import psutil

disk = psutil.disk_usage("/")
memory = psutil.virtual_memory()

print(f"Disk used: {disk.percent}%")
print(f"Memory used: {memory.percent}%")

if disk.percent >= 90:
    raise SystemExit("Critical: disk usage is at least 90%")
```

Thresholds should be configurable.

---

### Log collection and rotation

Python supports rotating log files.

```python name=rotating_logs.py
import logging
from logging.handlers import RotatingFileHandler

handler = RotatingFileHandler(
    "application.log",
    maxBytes=1_000_000,
    backupCount=5,
)

logger = logging.getLogger("application")
logger.setLevel(logging.INFO)
logger.addHandler(handler)

logger.info("Application started")
```

Never log passwords, access tokens, session identifiers, or personal data unnecessarily.

---

### Backup and restore utilities

A reliable backup tool should:

1. Copy or archive data.
2. Record metadata and time.
3. Verify integrity with a checksum.
4. Encrypt sensitive backups.
5. Test restore operations.

```python name=file_checksum.py
import hashlib
from pathlib import Path

digest = hashlib.sha256(Path("backup.zip").read_bytes()).hexdigest()
print(digest)
```

For large files, calculate the checksum in chunks rather than loading the complete file into memory.

---

### Cross-platform command execution

Prefer Python APIs such as `pathlib`, `shutil`, and `subprocess` over shell-specific commands.

```python name=cross_platform.py
import platform
from pathlib import Path

print(f"System: {platform.system()}")
print(f"Home: {Path.home()}")
```

If platform-specific behavior is unavoidable:

```python name=platform_command.py
import platform
import subprocess

command = ["ipconfig"] if platform.system() == "Windows" else ["ip", "address"]
subprocess.run(command, check=True, timeout=30)
```

Avoid `shell=True`, especially when any command value comes from a user.

## 1.8 Packaging and Distribution

### Project structure and entry points

A modern CLI project commonly uses this structure:

```text
weather-cli/
├── pyproject.toml
├── README.md
├── src/
│   └── weather_cli/
│       ├── __init__.py
│       └── cli.py
└── tests/
    └── test_cli.py
```

```python name=src/weather_cli/cli.py
def main() -> int:
    print("Weather CLI")
    return 0
```

The entry point lets users run `weather` instead of `python cli.py`.

---

### Packaging command-line applications

Use `pyproject.toml` for modern Python packaging.

````toml name=pyproject.toml
[build-system]
requires = ["setuptools>=75"]
build-backend = "setuptools.build_meta"

[project]
name = "weather-cli"
version = "1.0.0"
requires-python = ">=3.11"

[project.scripts]
weather = "weather_cli.cli:main"
````

Build the package:

`python -m pip install build`

`python -m build`

Install locally:

`python -m pip install .`

---

### Standalone executable generation

PyInstaller can package a Python application as an executable.

`python -m pip install pyinstaller`

`pyinstaller --onefile src/weather_cli/cli.py`

The executable is normally created in `dist/`.

Build separately for Windows, Linux, and macOS. A Windows executable generally cannot be built once and reused on every platform.

---

### Cross-platform compatibility

Use:

- `pathlib.Path` instead of manually joining paths
- `os.linesep` only when platform-specific line endings are necessary
- UTF-8 explicitly for text files
- Python APIs instead of Bash- or PowerShell-only commands
- Automated tests on Windows, Linux, and macOS

Avoid hard-coded paths such as `C:\temp` or `/home/user`.

---

### Versioning and update strategies

Semantic Versioning uses:

`MAJOR.MINOR.PATCH`

Example: `2.4.1`

- **MAJOR:** Breaking change
- **MINOR:** Backward-compatible feature
- **PATCH:** Backward-compatible bug or security fix

Update strategies include:

- `pip install --upgrade package-name`
- OS package managers
- Signed executable releases
- Managed enterprise deployment

Automatic updates should use HTTPS and verify the downloaded artifact's signature or trusted checksum.

---

### Publishing and installation

Typical package publishing process:

1. Run formatting, linting, tests, and security scans.
2. Build the package.
3. Validate package metadata.
4. Publish to a test registry.
5. Test installation.
6. Publish to the production registry.

Common commands:

`python -m build`

`python -m twine check dist/*`

`python -m twine upload dist/*`

Installation:

`python -m pip install weather-cli`

Keep publishing tokens in a secret manager or CI/CD secret store. Never commit them to the repository.

---

## Quick framework recommendation

For learning, start with this sequence:

1. Learn CLI concepts with `argparse`.
2. Use Typer for a modern typed application.
3. Learn Click when advanced customization is required.
4. Add Rich for formatted output.
5. Package the application using `pyproject.toml`.
6. Test it on Windows, Linux, and macOS.
7. Add input validation, secure secret handling, logging, and meaningful exit codes.
