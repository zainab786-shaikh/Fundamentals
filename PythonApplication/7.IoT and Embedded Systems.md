## 7.1 Introduction to IoT and Embedded Systems

### Embedded hardware and software fundamentals

An **embedded system** is a computer designed to perform a specific task. It usually contains:

- A processor or microcontroller
- Memory
- Input/output pins
- Firmware that controls the hardware

For example, a microcontroller can read a button and turn on an LED.

```python name=button_led.py
from machine import Pin
import time

button = Pin(14, Pin.IN, Pin.PULL_UP)
led = Pin(15, Pin.OUT)

while True:
    # A pull-up button reads 0 when pressed.
    led.value(button.value() == 0)
    time.sleep_ms(20)
```

### Sensors, actuators, and controllers

- **Sensor:** Measures the environment, such as temperature or light.
- **Actuator:** Performs an action, such as turning a motor or LED on.
- **Controller:** Reads sensors and decides how actuators should respond.

This example simulates a temperature controller:

```python name=temperature_controller.py
temperature_celsius = 31.5
maximum_temperature = 30.0

if temperature_celsius > maximum_temperature:
    print("Fan ON")
else:
    print("Fan OFF")
```

A real application would replace the printed messages with safe GPIO control.

### Communication protocols and system architecture

Common IoT protocols include:

- **I²C:** Connects sensors and displays over short distances.
- **SPI:** Provides faster communication with displays and storage.
- **UART:** Provides serial communication between two devices.
- **MQTT:** Exchanges small messages over a network.
- **HTTP:** Communicates with web APIs.
- **Bluetooth:** Supports nearby wireless communication.

A typical IoT architecture is:

```text
Sensor → Microcontroller → MQTT/HTTP → Server → Dashboard
```

### Real-time and resource-constrained programming

Embedded devices have limited memory, storage, processing power, and battery capacity. Programs should therefore:

- Avoid unnecessary object creation
- Process data in small chunks
- Use appropriate sampling intervals
- Release resources promptly
- Avoid blocking operations when responsiveness matters

```python name=periodic_sampling.py
import time

SAMPLE_INTERVAL_SECONDS = 5

while True:
    started_at = time.monotonic()

    print("Reading sensors...")

    elapsed = time.monotonic() - started_at
    remaining = max(0, SAMPLE_INTERVAL_SECONDS - elapsed)
    time.sleep(remaining)
```

## 7.2 Sensor Monitoring

### Reading temperature, humidity, light, and motion sensors

MicroPython can read a DHT temperature and humidity sensor:

```python name=dht_sensor.py
from machine import Pin
import dht
import time

sensor = dht.DHT22(Pin(4))

while True:
    try:
        sensor.measure()
        print(f"Temperature: {sensor.temperature():.1f} °C")
        print(f"Humidity: {sensor.humidity():.1f}%")
    except OSError as error:
        print(f"Sensor read failed: {error}")

    time.sleep(2)
```

A digital motion sensor can be read through GPIO:

```python name=motion_sensor.py
from machine import Pin
import time

motion_sensor = Pin(16, Pin.IN)

while True:
    if motion_sensor.value():
        print("Motion detected")

    time.sleep_ms(100)
```

### Sampling, filtering, and calibrating sensor data

Sensor measurements can contain noise. Averaging several readings creates a more stable result.

```python name=sensor_filter.py
def average_readings(readings: list[float]) -> float:
    if not readings:
        raise ValueError("At least one reading is required.")

    return sum(readings) / len(readings)


raw_readings = [20.1, 20.4, 19.9, 25.0, 20.2]

# Ignore physically unreasonable values for this environment.
valid_readings = [
    value for value in raw_readings
    if 0.0 <= value <= 40.0
]

filtered_value = average_readings(valid_readings)
calibration_offset = -0.3
calibrated_value = filtered_value + calibration_offset

print(f"Calibrated temperature: {calibrated_value:.1f} °C")
```

In production, validation limits should come from the sensor specification and expected environment.

### Storing and visualizing measurements

A Raspberry Pi can store readings in SQLite using parameterized queries:

```python name=store_sensor_data.py
import sqlite3
from datetime import datetime, timezone

temperature = 23.4

with sqlite3.connect("sensors.db") as connection:
    connection.execute("""
        CREATE TABLE IF NOT EXISTS measurements (
            id INTEGER PRIMARY KEY,
            recorded_at TEXT NOT NULL,
            temperature_celsius REAL NOT NULL
        )
    """)

    connection.execute(
        """
        INSERT INTO measurements (
            recorded_at,
            temperature_celsius
        ) VALUES (?, ?)
        """,
        (
            datetime.now(timezone.utc).isoformat(),
            temperature,
        ),
    )
```

The `?` placeholders prevent SQL injection and keep values separate from SQL commands.

### Creating threshold-based alerts

Thresholds should include a cooldown so the same alert is not sent continuously.

```python name=temperature_alert.py
import time

MAXIMUM_TEMPERATURE = 30.0
ALERT_COOLDOWN_SECONDS = 300

last_alert_at = 0.0


def check_temperature(temperature: float) -> None:
    global last_alert_at

    now = time.monotonic()
    alert_is_due = now - last_alert_at >= ALERT_COOLDOWN_SECONDS

    if temperature > MAXIMUM_TEMPERATURE and alert_is_due:
        print(f"ALERT: Temperature is {temperature:.1f} °C")
        last_alert_at = now


check_temperature(32.5)
```

### Controlling lighting, climate, and appliances

A GPIO output can control an LED or a properly isolated low-voltage relay module.

```python name=light_controller.py
from machine import Pin

light = Pin(18, Pin.OUT, value=0)


def set_light(enabled: bool) -> None:

set_light(True)
```

### Building schedules, rules, and automation workflows

This example turns a simulated light on during evening hours:

```python name=lighting_schedule.py
from datetime import datetime


def should_light_be_on(hour: int, motion_detected: bool) -> bool:
    evening = 18 <= hour < 23
    return evening and motion_detected


now = datetime.now()
light_enabled = should_light_be_on(
    hour=now.hour,

print("Light ON" if light_enabled else "Light OFF")
```

Keep rule evaluation separate from hardware control so it can be tested safely.

### Integrating smart-home platforms

MQTT allows a device to publish state and receive commands. This desktop/Raspberry Pi example uses `paho-mqtt`.

```python name=mqtt_light.py
import json
import os
import ssl

import paho.mqtt.client as mqtt

BROKER_HOST = os.environ["MQTT_HOST"]
BROKER_PORT = 8883
DEVICE_ID = os.environ["DEVICE_ID"]
USERNAME = os.environ["MQTT_USERNAME"]
PASSWORD = os.environ["MQTT_PASSWORD"]

COMMAND_TOPIC = f"home/lights/{DEVICE_ID}/command"
STATE_TOPIC = f"home/lights/{DEVICE_ID}/state"


def on_connect(client, userdata, flags, reason_code, properties):
    if reason_code == 0:
        client.subscribe(COMMAND_TOPIC)
    else:
        print(f"MQTT connection failed: {reason_code}")


def on_message(client, userdata, message):
    try:
        command = json.loads(message.payload.decode("utf-8"))
        enabled = command.get("enabled")

        if not isinstance(enabled, bool):
            raise ValueError("'enabled' must be a Boolean.")

        # Call the hardware controller here.
        client.publish(
            STATE_TOPIC,
            json.dumps({"enabled": enabled}),
            qos=1,
            retain=True,
        )
    except (UnicodeDecodeError, json.JSONDecodeError, ValueError) as error:
        print(f"Rejected invalid command: {error}")


client = mqtt.Client(mqtt.CallbackAPIVersion.VERSION2)
client.username_pw_set(USERNAME, PASSWORD)
client.tls_set(tls_version=ssl.PROTOCOL_TLS_CLIENT)
client.on_connect = on_connect
client.on_message = on_message
client.connect(BROKER_HOST, BROKER_PORT)
client.loop_forever()
```

Security measures include TLS, environment-based secrets, strict message validation, and device-specific topics.

### Supporting safe manual overrides

Manual control should be able to override automation when safety or accessibility requires it.

```python name=manual_override.py
from dataclasses import dataclass


@dataclass
class LightState:
    automatic_enabled: bool = True
    manual_value: bool | None = None


def calculate_output(state: LightState, sensor_value: bool) -> bool:
    if state.manual_value is not None:
        return state.manual_value

    if state.automatic_enabled:
        return sensor_value

    return False


state = LightState(manual_value=True)
print(calculate_output(state, sensor_value=False))
```

Define when an override expires and store it safely if it must survive a restart.

## 7.4 Device Controllers

### Controlling motors, relays, LEDs, and displays

PWM can control an LED’s brightness:

```python name=pwm_led.py
from machine import Pin, PWM
import time

led = PWM(Pin(15))
led.freq(1_000)

try:
    for duty_cycle in range(0, 65_536, 2_048):
        led.duty_u16(duty_cycle)
        time.sleep_ms(30)
finally:
    led.deinit()
```

Motors require a suitable motor driver. Never power a motor directly from a GPIO pin.

### Using GPIO, PWM, ADC, I²C, SPI, and UART

The following MicroPython examples show the basic purpose of each interface:

```python name=hardware_interfaces.py
from machine import ADC, I2C, Pin, SPI, UART

# GPIO: digital input/output.
led = Pin(15, Pin.OUT)
led.on()

# ADC: read an analog signal.
analog_sensor = ADC(Pin(26))
analog_value = analog_sensor.read_u16()

# I²C: scan for connected devices.
i2c = I2C(0, scl=Pin(1), sda=Pin(0), freq=400_000)
i2c_addresses = i2c.scan()

# SPI: configure a high-speed peripheral bus.
spi = SPI(
    0,
    baudrate=1_000_000,
    polarity=0,
    phase=0,
    sck=Pin(2),
    mosi=Pin(3),
    miso=Pin(4),
)

# UART: send serial data.
uart = UART(0, baudrate=115_200)
uart.write(b"Hello from the controller\n")

print(f"Analog value: {analog_value}")
print(f"I2C addresses: {i2c_addresses}")
```

Pin assignments and constructors differ by board and MicroPython port.

### Managing device state and error recovery

Representing state explicitly makes recovery easier:

```python name=device_state.py
from enum import Enum, auto


class DeviceState(Enum):
    STARTING = auto()
    READY = auto()
    ERROR = auto()
    STOPPED = auto()


state = DeviceState.STARTING

try:
    print("Initializing device...")
    state = DeviceState.READY
except OSError as error:
    state = DeviceState.ERROR
    print(f"Initialization failed: {error}")
finally:
    print(f"Current state: {state.name}")
```

A real controller can retry transient failures with a bounded delay and enter a safe state after repeated failures.

### Designing fail-safe control mechanisms

A fail-safe system chooses the least dangerous state when an error occurs.

```python name=fail_safe_controller.py
def control_heater(
    temperature: float | None,
    maximum_temperature: float,
) -> bool:
    # Deny-by-default: missing or invalid sensor data turns the heater off.
    if temperature is None:
        return False

    if not -40.0 <= temperature <= 125.0:
        return False

    return temperature < maximum_temperature


heater_enabled = control_heater(
    temperature=None,
    maximum_temperature=20.0,
)

print(f"Heater enabled: {heater_enabled}")
```

Software fail-safes should supplement—not replace—thermal fuses, emergency stops, isolation, and other hardware protections.

## 7.5 MicroPython

### Programming microcontrollers with Python

MicroPython implements a compact version of Python for microcontrollers.

```python name=micropython_blink.py
from machine import Pin
import time

led = Pin("LED", Pin.OUT)

while True:
    led.toggle()
    time.sleep(1)
```

Some boards do not support the `"LED"` name and require a numeric pin.

### Working with GPIO and peripheral interfaces

A reusable digital output class keeps hardware operations organized:

```python name=digital_output.py
from machine import Pin


class DigitalOutput:
    def __init__(self, pin_number: int, active_high: bool = True):
        self._pin = Pin(pin_number, Pin.OUT, value=0)
        self._active_high = active_high

    def set_enabled(self, enabled: bool) -> None:
        physical_value = enabled if self._active_high else not enabled
        self._pin.value(int(physical_value))

    def disable(self) -> None:
        self.set_enabled(False)


output = DigitalOutput(15)
output.set_enabled(True)
```

### Connecting devices to Wi-Fi and MQTT

Wi-Fi credentials should come from protected configuration rather than source control.

```python name=wifi_connection.py
import os
import time
import network

SSID = os.getenv("WIFI_SSID")
PASSWORD = os.getenv("WIFI_PASSWORD")

if not SSID or not PASSWORD:
    raise RuntimeError("Wi-Fi credentials are not configured.")

wlan = network.WLAN(network.STA_IF)
wlan.active(True)
wlan.connect(SSID, PASSWORD)

deadline = time.ticks_add(time.ticks_ms(), 15_000)

while not wlan.isconnected():
    if time.ticks_diff(deadline, time.ticks_ms()) <= 0:
        wlan.disconnect()
        raise TimeoutError("Wi-Fi connection timed out.")

    time.sleep_ms(250)

print("Wi-Fi connected")
```

Environment-variable support differs between MicroPython ports. A production device may use encrypted device storage, secure elements, or credentials provisioned during manufacturing.

### Managing memory and power consumption

Devices can reduce memory and energy use by processing one value at a time and sleeping between readings.

```python name=low_power_sampling.py
from machine import deepsleep
import gc

print("Collect and transmit one measurement here.")

gc.collect()
print(f"Free memory: {gc.mem_free()} bytes")

# Restart the device after 60 seconds.
deepsleep(60_000)
```

Deep sleep resets many boards when they wake, so persistent state may need to be stored carefully.

## 7.7 Raspberry Pi

### Configuring Raspberry Pi hardware and operating systems

A Raspberry Pi is a small Linux computer rather than a microcontroller. It can run full Python applications, databases, containers, and web servers.

Recommended configuration practices include:

- Change default credentials
- Install security updates
- Disable unused services
- Use SSH keys instead of passwords
- Run applications as non-root users
- Grant GPIO access only where required
- Enable a firewall when network services are exposed

### Running local APIs, dashboards, and automation services

For production:

- Place the API behind HTTPS
- Require authentication and authorization
- Bind to a private interface unless external access is required

- Disable verbose production errors

```python name=https_sensor_request.py
from urllib.parse import urlparse

import requests

ALLOWED_HOSTS = {"api.example.com"}


def validate_url(url: str) -> None:
    parsed = urlparse(url)

    if parsed.scheme != "https":
        raise ValueError("Only HTTPS URLs are allowed.")

    if parsed.hostname not in ALLOWED_HOSTS:
        raise ValueError("Destination host is not allowed.")

    if parsed.port not in (None, 443):
        raise ValueError("Only the HTTPS port is allowed.")

    if not parsed.path.startswith("/v1/readings"):
        raise ValueError("Destination path is not allowed.")


url = "https://api.example.com/v1/readings/current"
validate_url(url)

response = requests.get(
    url,
    timeout=(3.05, 10),
    allow_redirects=False,
)
response.raise_for_status()
print(response.json())
```

### Device-to-cloud and device-to-device messaging

Each message should identify its schema and validate its contents.

```python name=device_message.py
import json
from typing import Any


def parse_message(raw_message: bytes) -> dict[str, Any]:
    if len(raw_message) > 4_096:
        raise ValueError("Message exceeds the allowed size.")

    message = json.loads(raw_message.decode("utf-8"))

    if message.get("schema_version") != 1:
        raise ValueError("Unsupported message schema.")

    temperature = message.get("temperature_celsius")
    if not isinstance(temperature, (int, float)):
        raise ValueError("Temperature must be numeric.")

    if not -40 <= temperature <= 125:
        raise ValueError("Temperature is outside the allowed range.")

    return message


message = parse_message(
    b'{"schema_version": 1, "temperature_celsius": 22.4}'
)
print(message)
```

Size limits protect resource-constrained devices from oversized input.

### Offline operation and data synchronization

When disconnected, a device can queue readings locally:

```python name=offline_queue.py
from collections import deque

MAX_QUEUED_READINGS = 100
pending_readings: deque[dict[str, float]] = deque(
    maxlen=MAX_QUEUED_READINGS
)


def record_reading(temperature: float, connected: bool) -> None:
    reading = {"temperature_celsius": temperature}

    if connected:
        print(f"Sending: {reading}")
    else:
        pending_readings.append(reading)


def synchronize() -> None:
    while pending_readings:
        reading = pending_readings[0]

        # Remove only after confirmed delivery.
        print(f"Sending queued reading: {reading}")
        pending_readings.popleft()
```

A production implementation should persist important readings to disk and use unique message IDs to prevent duplicate processing.

### Network failure handling and reconnection strategies

Exponential backoff prevents a disconnected device from flooding the network:

```python name=reconnection_backoff.py
import random
import time

INITIAL_DELAY = 1.0
MAXIMUM_DELAY = 60.0


def connect() -> None:
    raise ConnectionError("Network unavailable")


delay = INITIAL_DELAY

while True:
    try:
        connect()
        delay = INITIAL_DELAY
        break
    except ConnectionError as error:
        jitter = random.uniform(0, delay * 0.2)
        wait_time = delay + jitter

        print(f"Connection failed; retrying in {wait_time:.1f}s")
        time.sleep(wait_time)

        delay = min(delay * 2, MAXIMUM_DELAY)
```

Jitter prevents many devices from reconnecting simultaneously after an outage.

## 7.9 IoT Security and Reliability

### Unique device identities and least-privilege access

Every device should have its own identity and permissions. For example:

- `sensor-01` may publish to `devices/sensor-01/readings`
- It may not publish to another device’s topic
- A dashboard may read readings but not send control commands
- An administrator may manage devices through a separate account

Avoid sharing one password or certificate across an entire fleet.

### Encrypting communications with TLS

Python’s standard library verifies trusted HTTPS certificates by default:

```python name=tls_connection.py
import json
import ssl
import urllib.request

context = ssl.create_default_context()

request = urllib.request.Request(
    "https://api.example.com/v1/readings",
    method="POST",
    data=json.dumps({
        "temperature_celsius": 22.5,
    }).encode("utf-8"),
    headers={"Content-Type": "application/json"},
)

with urllib.request.urlopen(
    request,
    timeout=10,
    context=context,
) as response:
    print(response.status)
```

Do not disable certificate validation to work around TLS errors. Install the correct CA certificate and verify the hostname instead.

### Secure secret storage and key rotation

Read secrets from the environment or a secrets manager:

```python name=secrets_configuration.py
import os

api_token = os.getenv("IOT_API_TOKEN")

if not api_token:
    raise RuntimeError("IOT_API_TOKEN is not configured.")

# Avoid printing the token.
authorization_header = {
    "Authorization": f"Bearer {api_token}",
}
```

Good secret management includes:

- Separate credentials for every device
- Short-lived credentials where possible
- Scheduled key rotation
- Immediate revocation for compromised devices
- No secrets in source control, logs, or firmware images

### Signed firmware and secure update mechanisms

A device should verify a firmware signature before installing an update. This desktop-side example uses Ed25519:

```python name=verify_firmware.py
from pathlib import Path

from cryptography.exceptions import InvalidSignature
from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PublicKey

MAX_FIRMWARE_SIZE = 16 * 1024 * 1024

firmware = Path("firmware.bin").read_bytes()
signature = Path("firmware.bin.sig").read_bytes()
public_key_bytes = Path("firmware-public-key.bin").read_bytes()

if len(firmware) > MAX_FIRMWARE_SIZE:
    raise ValueError("Firmware exceeds the allowed size.")

public_key = Ed25519PublicKey.from_public_bytes(public_key_bytes)

try:
    public_key.verify(signature, firmware)
except InvalidSignature as error:
    raise RuntimeError("Firmware signature is invalid.") from error

print("Firmware is authentic and may be installed.")
```

The trusted public key should be protected against modification. Secure updates should also prevent downgrade attacks by checking a signed version number.

### Input validation, watchdog timers, and fail-safe states

A watchdog automatically resets an unresponsive microcontroller:

```python name=watchdog.py
from machine import WDT
import time

watchdog = WDT(timeout=8_000)

while True:
    try:
        # Perform bounded work here.
        print("Controller is healthy")
        watchdog.feed()
    except Exception as error:
        # Put outputs into their safest available state.
        print(f"Controller error: {error}")
        break

    time.sleep(1)
```

Only feed the watchdog after completing meaningful health checks. Feeding it unconditionally could hide a failed subsystem.

### Logging, health monitoring, and device recovery

Structured logs are easier to search and process:

```python name=device_health.py
import json
import logging
import time

logging.basicConfig(
    level=logging.INFO,
    format="%(message)s",
)

started_at = time.monotonic()
```
