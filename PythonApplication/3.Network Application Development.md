# 3. Network Application Development

Network applications allow computers or processes to communicate and exchange data through protocols such as TCP, UDP, HTTP, and SSH.

---

## 3.1 Networking Fundamentals

### Client-server architecture

- A **server** listens for requests and provides a service.
- A **client** connects to the server and requests that service.

Example flow:

`Client → request → Server → response → Client`

```python name=client_server_concept.py
# Client sends a request
request = {"action": "greet", "name": "Alice"}

# Server processes it
response = {"message": f"Hello, {request['name']}"}

print(response)
```

A server can usually serve many clients.

---

### IP addresses, ports, and DNS

- **IP address:** Identifies a device, such as `192.0.2.10`.
- **Port:** Identifies an application on that device, such as `443`.
- **DNS:** Converts a hostname into an IP address.

```python name=dns_lookup.py
import socket

addresses = socket.getaddrinfo(
    "example.com",
    443,
    type=socket.SOCK_STREAM,
)

for address in addresses:
    print(address[4])
```

A network endpoint is commonly represented as `host:port`.

---

### TCP and UDP

**TCP:**

- Reliable and ordered
- Detects lost data
- Requires a connection
- Used by HTTPS, SSH, and many database protocols

**UDP:**

- Sends independent datagrams
- Does not guarantee delivery or order
- Has lower protocol overhead
- Used by DNS, streaming, games, and device discovery

```python name=socket_types.py
import socket

tcp_socket = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
udp_socket = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)

tcp_socket.close()
udp_socket.close()
```

---

### Connection-oriented and connectionless communication

- **Connection-oriented:** A connection is established before communication. TCP follows this model.
- **Connectionless:** Each message is sent independently. UDP follows this model.

TCP:

`Connect → exchange data → close`

UDP:

`Send datagram → optionally receive datagram`

---

### Network protocols

A network protocol defines:

- How a connection starts and ends
- Message structure
- Valid operations
- Authentication requirements
- Error responses
- Version compatibility

Examples include HTTP, HTTPS, DNS, SSH, SMTP, and custom application protocols.

---

### Timeouts, retries, and connection lifecycles

A timeout prevents an application from waiting forever.

```python name=socket_timeout.py
import socket

try:
    with socket.create_connection(
        ("example.com", 443),
        timeout=5,
    ) as connection:
        print("Connected")
except TimeoutError:
    print("Connection timed out")
except OSError as error:
    print(f"Connection failed: {error}")
```

Retries should:

- Be limited
- Use increasing delays
- Include small random delays for many clients
- Retry only temporary failures
- Avoid retrying unsafe operations blindly

```python name=limited_retry.py
import socket
import time

for attempt in range(3):
    try:
        with socket.create_connection(("example.com", 443), timeout=5):
            print("Connected")
            break
    except OSError:
        if attempt == 2:
            raise
        time.sleep(2**attempt)
```

---

### Message framing and serialization

TCP provides a byte stream, not separate messages. Applications must define where each message ends.

Common framing methods:

- Newline-delimited messages
- Fixed-size messages
- Length-prefixed messages
- Connection closure
- Structured protocols such as HTTP

Serialization converts objects into transferable bytes.

```python name=newline_message.py
import json

message = {"type": "greeting", "name": "Alice"}
encoded = json.dumps(message).encode("utf-8") + b"\n"

decoded = json.loads(encoded.decode("utf-8"))
print(decoded)
```

Newline framing works only when the protocol handles embedded newlines correctly.

## 3.2 Socket Programming

### Creating socket servers and clients

A server normally:

1. Creates a socket.
2. Binds it to an address.
3. Starts listening.
4. Accepts connections.
5. Exchanges data.
6. Closes the connection.

A client:

1. Creates a socket.
2. Connects to the server.
3. Exchanges data.
4. Closes the connection.

Use loopback address `127.0.0.1` during local development so the server is not exposed to other devices.

---

### TCP socket communication

#### TCP server

```python name=tcp_server.py
import socket

HOST = "127.0.0.1"
PORT = 9000

with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as server:
    server.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    server.bind((HOST, PORT))
    server.listen()

    connection, address = server.accept()
    with connection:
        connection.settimeout(10)
        data = connection.recv(1024)
        connection.sendall(b"Received: " + data)
```

#### TCP client

```python name=tcp_client.py
import socket

with socket.create_connection(("127.0.0.1", 9000), timeout=5) as client:
    client.sendall(b"Hello")
    response = client.recv(1024)
    print(response.decode("utf-8"))
```

`sendall()` continues until all provided bytes are sent or an error occurs.

---

### UDP socket communication

#### UDP server

```python name=udp_server.py
import socket

with socket.socket(socket.AF_INET, socket.SOCK_DGRAM) as server:
    server.bind(("127.0.0.1", 9001))
    data, address = server.recvfrom(1024)
    server.sendto(b"Received: " + data, address)
```

#### UDP client

```python name=udp_client.py
import socket

with socket.socket(socket.AF_INET, socket.SOCK_DGRAM) as client:
    client.settimeout(5)
    client.sendto(b"Hello", ("127.0.0.1", 9001))
    response, _ = client.recvfrom(1024)
    print(response.decode("utf-8"))
```

One UDP datagram corresponds to one message, but it may be lost, duplicated, or delivered out of order.

---

### Sending and receiving data

Sockets transfer bytes rather than Python strings.

```python name=encode_decode.py
text = "Hello"
data = text.encode("utf-8")
restored_text = data.decode("utf-8")

print(restored_text)
```

A single `recv()` call is not guaranteed to return the complete TCP message. Continue reading until the framing rule says the message is complete.

```python name=receive_exactly.py
import socket


def receive_exactly(connection: socket.socket, size: int) -> bytes:
    parts = bytearray()

    while len(parts) < size:
        chunk = connection.recv(size - len(parts))
        if not chunk:
            raise ConnectionError("Connection closed before message completed")
        parts.extend(chunk)

    return bytes(parts)
```

Always impose a maximum message size.

---

### Handling multiple clients

A simple approach is to assign each client to a thread.

```python name=threaded_server.py
import socket
import threading


def handle_client(connection: socket.socket) -> None:
    with connection:
        connection.settimeout(10)
        data = connection.recv(1024)
        connection.sendall(data)


with socket.socket() as server:
    server.bind(("127.0.0.1", 9000))
    server.listen(100)

    while True:
        connection, _ = server.accept()
        threading.Thread(
            target=handle_client,
            args=(connection,),
            daemon=True,
        ).start()
```

For many concurrent connections, `asyncio` is often more efficient than creating one thread per client. Production systems should also limit total connections.

---

### Blocking and non-blocking sockets

- **Blocking socket:** Waits until an operation completes.
- **Non-blocking socket:** Returns immediately if it cannot proceed.

```python name=nonblocking_socket.py
import socket

client = socket.socket()
client.setblocking(False)

try:
    client.connect(("127.0.0.1", 9000))
except BlockingIOError:
    print("Connection is in progress")
finally:
    client.close()
```

Direct non-blocking programming can be complex. `asyncio` or `selectors` usually provides a clearer structure.

---

### Connection cleanup

Use context managers to close sockets even when errors occur.

```python name=connection_cleanup.py
import socket

with socket.create_connection(("example.com", 80), timeout=5) as client:
    client.sendall(
        b"HEAD / HTTP/1.1\r\n"
        b"Host: example.com\r\n"
        b"Connection: close\r\n\r\n"
    )
```

For secure Internet communication, use HTTPS rather than raw unencrypted HTTP.

---

### Socket error handling

Handle expected errors without hiding programming mistakes.

```python name=socket_errors.py
import socket

try:
    with socket.create_connection(("127.0.0.1", 9000), timeout=3):
        print("Connected")
except TimeoutError:
    print("Error: connection timed out")
except ConnectionRefusedError:
    print("Error: server is not accepting connections")
except OSError as error:
    print(f"Network error: {error}")
```

Avoid exposing sensitive hostnames, credentials, or internal details in production error messages.

## 3.3 Asynchronous Networking with `asyncio`

### Event loops

The event loop schedules asynchronous operations. While one operation waits for network data, another task can run.

```python name=event_loop.py
import asyncio


async def main() -> None:
    print("Starting")
    await asyncio.sleep(1)
    print("Finished")


asyncio.run(main())
```

`asyncio.run()` creates, runs, and closes the event loop.

---

### Coroutines and tasks

A coroutine is defined with `async def`. A task schedules a coroutine to run concurrently.

```python name=coroutines_tasks.py
import asyncio


async def worker(name: str) -> None:
    await asyncio.sleep(1)
    print(f"{name} completed")


async def main() -> None:
    tasks = [
        asyncio.create_task(worker("A")),
        asyncio.create_task(worker("B")),
    ]
    await asyncio.gather(*tasks)


asyncio.run(main())
```

This provides concurrency, not necessarily parallel CPU execution.

---

### Asynchronous streams

Streams provide high-level asynchronous TCP communication.

#### Async server

```python name=async_server.py
import asyncio


async def handle_client(
    reader: asyncio.StreamReader,
    writer: asyncio.StreamWriter,
) -> None:
    try:
        data = await asyncio.wait_for(reader.readline(), timeout=10)
        writer.write(b"Received: " + data)
        await writer.drain()
    finally:
        writer.close()
        await writer.wait_closed()


async def main() -> None:
    server = await asyncio.start_server(
        handle_client,
        "127.0.0.1",
        9000,
        limit=64 * 1024,
    )

    async with server:
        await server.serve_forever()


asyncio.run(main())
```

#### Async client

```python name=async_client.py
import asyncio


async def main() -> None:
    reader, writer = await asyncio.open_connection(
        "127.0.0.1",
        9000,
    )

    try:
        writer.write(b"Hello\n")
        await writer.drain()
        response = await asyncio.wait_for(reader.readline(), timeout=5)
        print(response.decode("utf-8").strip())
    finally:
        writer.close()
        await writer.wait_closed()


asyncio.run(main())
```

---

### Concurrent client connections

Each accepted client runs as a separate coroutine. The event loop switches between clients when operations are waiting.

Use a semaphore to limit expensive concurrent work:

```python name=concurrency_limit.py
import asyncio

limit = asyncio.Semaphore(50)


async def process_request() -> None:
    async with limit:
        await asyncio.sleep(1)
```

Concurrency limits protect memory, CPU, databases, and downstream services.

---

### Timeouts and cancellation

```python name=async_timeout.py
import asyncio


async def slow_operation() -> str:
    await asyncio.sleep(10)
    return "done"


async def main() -> None:
    try:
        result = await asyncio.wait_for(slow_operation(), timeout=2)
        print(result)
    except TimeoutError:
        print("Operation timed out")


asyncio.run(main())
```

Cancelled tasks should release resources:

```python name=async_cancellation.py
import asyncio


async def worker() -> None:
    try:
        await asyncio.sleep(60)
    except asyncio.CancelledError:
        print("Worker cancelled")
        raise
    finally:
        print("Cleaning up")
```

Re-raise `CancelledError` after cleanup so cancellation can complete correctly.

---

### Queues and synchronization

An `asyncio.Queue` safely passes work between coroutines.

```python name=async_queue.py
import asyncio


async def producer(queue: asyncio.Queue[str]) -> None:
    await queue.put("message")


async def consumer(queue: asyncio.Queue[str]) -> None:
    message = await queue.get()
    try:
        print(message)
    finally:
        queue.task_done()


async def main() -> None:
    queue: asyncio.Queue[str] = asyncio.Queue(maxsize=100)
    await asyncio.gather(producer(queue), consumer(queue))


asyncio.run(main())
```

A bounded queue prevents unlimited memory growth.

---

### Backpressure and flow control

Backpressure slows producers when consumers cannot keep up.

```python name=backpressure.py
writer.write(large_data)
await writer.drain()
```

`drain()` waits when the transport's write buffer becomes too full.

Other backpressure techniques include:

- Bounded queues
- Connection limits
- Message-size limits
- Request-rate limits
- Pausing reads temporarily

---

### Graceful shutdown

Graceful shutdown stops accepting new clients and allows current work to clean up.

```python name=graceful_shutdown.py
import asyncio


async def main() -> None:
    server = await asyncio.start_server(
        lambda reader, writer: writer.close(),
        "127.0.0.1",
        9000,
    )

    try:
        async with server:
            await server.serve_forever()
    except asyncio.CancelledError:
        server.close()
        await server.wait_closed()
        raise


try:
    asyncio.run(main())
except KeyboardInterrupt:
    print("Server stopped")
```

Production applications should also cancel tracked client tasks and apply a shutdown timeout.

## 3.4 Network Protocol Design

### Defining message formats

A clear protocol defines required fields, types, limits, and allowed values.

```python name=message_format.py
message = {
    "version": 1,
    "type": "request",
    "id": "req-123",
    "action": "status",
    "payload": {},
}
```

Reject unknown or invalid operations by default.

---

### JSON and binary messages

**JSON:**

- Human-readable
- Easy to debug
- Larger and slower than many binary formats

```python name=json_message.py
import json

encoded = json.dumps({"temperature": 24}).encode("utf-8")
decoded = json.loads(encoded.decode("utf-8"))
```

**Binary:**

- Compact
- Efficient
- Requires a precise schema

```python name=binary_message.py
import struct

encoded = struct.pack("!I", 42)
number = struct.unpack("!I", encoded)[0]

print(number)
```

`!I` means an unsigned 32-bit integer in network byte order.

---

### Request-response communication

A client sends a request and expects a corresponding response.

```python name=request_response.py
request = {
    "type": "request",
    "id": "req-1",
    "action": "health",
}

response = {
    "type": "response",
    "id": request["id"],
    "status": "ok",
}
```

Every request should have a timeout.

---

### Message identifiers and correlation

Identifiers allow clients to match responses to requests.

```python name=correlation_id.py
import uuid

request_id = str(uuid.uuid4())

request = {"id": request_id, "action": "status"}
response = {"id": request_id, "result": "healthy"}
```

Do not treat a correlation ID as proof of authorization or identity.

---

### Authentication messages

Authentication proves identity before protected actions are allowed.

```python name=authentication_message.py
message = {
    "type": "authenticate",
    "token": "<access-token>",
}
```

Security requirements:

- Send credentials only through TLS.
- Never log tokens or passwords.
- Expire and rotate credentials.
- Authorize every protected operation after authentication.
- Prefer standard protocols such as OAuth 2.0 or mutual TLS where appropriate.

---

### Protocol versioning

Versioning supports future changes.

```python name=protocol_version.py
SUPPORTED_VERSIONS = {1, 2}

message = {"version": 2, "type": "request"}

if message["version"] not in SUPPORTED_VERSIONS:
    raise ValueError("Unsupported protocol version")
```

Major incompatible changes should use a new protocol version.

---

### Heartbeats and keep-alive messages

Heartbeats detect disconnected or unresponsive peers.

```python name=heartbeat_message.py
heartbeat = {
    "version": 1,
    "type": "ping",
    "timestamp": 1_800_000_000,
}
```

The peer may answer with `pong`. A missing response after a defined timeout can trigger reconnection.

Heartbeats do not replace authentication or application-level health checks.

---

### Compatibility and error responses

Error responses should be structured and safe.

```python name=protocol_error.py
error_response = {
    "version": 1,
    "type": "error",
    "id": "req-123",
    "code": "INVALID_MESSAGE",
    "message": "The 'action' field is required.",
}
```

Do not return stack traces, secrets, database queries, or internal paths.

## 3.5 File-Transfer Applications

### File upload and download

A basic transfer sends file bytes from one endpoint to another.

```python name=send_file.py
from pathlib import Path
import socket

with socket.create_connection(("127.0.0.1", 9000), timeout=10) as client:
    with Path("report.pdf").open("rb") as file:
        while chunk := file.read(64 * 1024):
            client.sendall(chunk)
```

The protocol must communicate metadata such as file size and name separately.

---

### Chunked file transfer

Chunking prevents loading the complete file into memory.

```python name=read_chunks.py
from collections.abc import Iterator
from pathlib import Path


def read_chunks(path: Path, size: int = 64 * 1024) -> Iterator[bytes]:
    with path.open("rb") as file:
        while chunk := file.read(size):
            yield chunk
```

Apply limits to total file size, chunk size, and transfer duration.

---

### Transfer progress

```python name=transfer_progress.py
from pathlib import Path

path = Path("large.bin")
total_size = path.stat().st_size
sent = 0

with path.open("rb") as file:
    while chunk := file.read(64 * 1024):
        # Send the chunk here.
        sent += len(chunk)
        percentage = sent / total_size * 100 if total_size else 100
        print(f"\rProgress: {percentage:.1f}%", end="")

print()
```

Progress is based on bytes transferred, not necessarily bytes safely written by the receiver.

---

### Checksums and integrity verification

A checksum detects accidental corruption.

```python name=file_checksum.py
import hashlib
from pathlib import Path


def sha256_file(path: Path) -> str:
    digest = hashlib.sha256()

    with path.open("rb") as file:
        while chunk := file.read(64 * 1024):
            digest.update(chunk)

    return digest.hexdigest()


print(sha256_file(Path("large.bin")))
```

For protection against malicious modification, use authenticated TLS and signed metadata or a keyed MAC, not an unauthenticated checksum alone.

---

### Resuming interrupted transfers

The receiver reports how many verified bytes it already has. The sender continues from that offset.

```python name=resume_transfer.py
from pathlib import Path

resume_offset = 1_048_576

with Path("large.bin").open("rb") as file:
    file.seek(resume_offset)
    next_chunk = file.read(64 * 1024)
```

Validate the partial file and offset before resuming. Chunk-level hashes are useful for large transfers.

---

### Handling large files

For large files:

- Stream in chunks.
- Avoid `read_bytes()`.
- Set size and time limits.
- Monitor free disk space.
- Write to a temporary file.
- Verify integrity before renaming.
- Clean up incomplete transfers.

```python name=atomic_file_completion.py
from pathlib import Path

temporary = Path("uploads/report.pdf.part")
completed = Path("uploads/report.pdf")

# Rename only after size and checksum validation.
temporary.replace(completed)
```

The rename is atomic only when source and destination are on the same filesystem.

---

### Secure file naming and storage

Never trust a client-supplied path.

```python name=secure_file_name.py
from pathlib import Path
import uuid

upload_directory = Path("uploads").resolve()
safe_name = f"{uuid.uuid4().hex}.bin"
destination = upload_directory / safe_name

assert destination.parent == upload_directory
```

Store the original display name as validated metadata rather than using it directly as a filesystem path.

---

### Access control and transfer limits

Before each upload or download:

1. Authenticate the user.
2. Verify permission for the requested file.
3. Enforce file-size and storage quotas.
4. Restrict allowed file types where appropriate.
5. Rate-limit transfers.
6. Record a security audit event.

Authentication alone is insufficient; every file operation needs authorization.

## 3.6 Remote Administration with Paramiko

Paramiko is a third-party Python SSH library.

Install it in an isolated environment:

`python -m pip install paramiko`

---

### SSH connections

```python name=ssh_connection.py
import os
import paramiko

hostname = os.environ["SSH_HOST"]
username = os.environ["SSH_USER"]

client = paramiko.SSHClient()
client.load_system_host_keys()
client.set_missing_host_key_policy(paramiko.RejectPolicy())

try:
    client.connect(
        hostname=hostname,
        username=username,
        key_filename=os.environ["SSH_KEY_FILE"],
        timeout=10,
        banner_timeout=10,
        auth_timeout=10,
    )
    print("Connected")
finally:
    client.close()
```

`RejectPolicy` prevents silently trusting an unknown server.

---

### Secure authentication

Prefer:

1. Hardware-backed or managed identity, when supported
2. Short-lived credentials
3. Password-protected SSH keys
4. Password authentication only when necessary

Never hardcode credentials.

```python name=ssh_environment.py
import os

hostname = os.environ["SSH_HOST"]
username = os.environ["SSH_USER"]
key_file = os.environ["SSH_KEY_FILE"]
```

Use a secret manager for production secrets.

---

### Remote command execution

```python name=remote_command.py
import paramiko

client: paramiko.SSHClient  # Already connected

stdin, stdout, stderr = client.exec_command(
    "uptime",
    timeout=10,
)

exit_code = stdout.channel.recv_exit_status()
output = stdout.read().decode("utf-8", errors="replace")
error = stderr.read().decode("utf-8", errors="replace")

if exit_code == 0:
    print(output)
else:
    print(f"Remote command failed with code {exit_code}")
```

Do not build shell commands by joining untrusted strings. Prefer fixed commands, allow-listed arguments, or a remote API with structured parameters.

---

### SFTP file transfer

```python name=sftp_transfer.py
from pathlib import Path
import paramiko

client: paramiko.SSHClient  # Already connected
local_path = Path("report.txt")

with client.open_sftp() as sftp:
    sftp.put(str(local_path), "/srv/uploads/report.txt")
```

Verify that the authenticated account is restricted to the required directories.

---

### SSH key management

Good practices include:

- Use a separate key per application or environment.
- Protect private keys with strong passphrases.
- Restrict private-key file permissions.
- Rotate keys regularly.
- Remove unused public keys.
- Never commit private keys.

Key generation is normally performed with platform tools such as `ssh-keygen`.

---

### Host-key verification

A host key proves the identity of the SSH server.

```python name=host_key_verification.py
import paramiko

client = paramiko.SSHClient()
client.load_system_host_keys()
client.load_host_keys("known_hosts")
client.set_missing_host_key_policy(paramiko.RejectPolicy())
```

Avoid `AutoAddPolicy` in production because it automatically trusts unknown hosts and enables impersonation attacks.

---

### Connection pooling and cleanup

Reuse connections carefully to reduce repeated setup costs, but:

- Check whether a connection is still active.
- Set idle limits.
- Limit the pool size.
- Never share one unsafe channel concurrently.
- Close all connections during shutdown.

```python name=ssh_cleanup.py
client = None

try:
    client = paramiko.SSHClient()
    # Configure and connect.
finally:
    if client is not None:
        client.close()
```

---

### Remote administration workflows

A secure workflow is:

1. Validate the target against a host allow-list.
2. Authenticate with a restricted account.
3. Verify the server host key.
4. Check authorization for the requested action.
5. Execute only approved commands.
6. Capture the exit code.
7. Log the action without credentials.
8. Close the connection.

Use `sudo` only for narrowly defined commands and only when necessary.

## 3.7 Network Application Types

### Basic chat clients and servers

A chat system accepts messages and broadcasts them to connected users.

```python name=chat_message.py
message = {
    "version": 1,
    "type": "chat",
    "sender": "alice",
    "text": "Hello",
}
```

Validate message length, authenticate users, rate-limit messages, and encode displayed text safely.

---

### File-transfer tools

These tools upload, download, synchronize, or share files.

Typical features:

- Chunked transfer
- Progress display
- Resume support
- Integrity verification
- TLS encryption
- Authentication and per-file authorization

Prefer established protocols such as HTTPS or SFTP instead of inventing a new protocol when possible.

---

### Remote administration utilities

These tools run approved operations on remote systems.

Examples:

- Restart a service
- Check disk space
- Retrieve logs
- Install an approved update

Use least-privileged accounts and allow-listed operations instead of unrestricted remote shell input.

---

### Network monitoring tools

Monitoring tools collect availability and performance data.

```python name=connection_monitor.py
import socket
import time

start = time.perf_counter()

try:
    with socket.create_connection(("example.com", 443), timeout=3):
        duration_ms = (time.perf_counter() - start) * 1000
        print(f"Available in {duration_ms:.1f} ms")
except OSError:
    print("Unavailable")
```

A successful TCP connection does not prove that the application itself is healthy.

---

### Port and service health checks

A port check tests whether a TCP connection can be established.

```python name=port_check.py
import socket


def port_is_open(host: str, port: int) -> bool:
    try:
        with socket.create_connection((host, port), timeout=2):
            return True
    except OSError:
        return False


print(port_is_open("example.com", 443))
```

Only scan systems you own or are explicitly authorized to test.

### Device communication applications

Applications may communicate with:

- Sensors
- Network appliances
- Industrial equipment
- IoT devices
- Serial-to-network gateways

Device protocols often require fixed message formats, checksums, timeouts, retries, and strict validation.

Place untrusted devices on segmented networks and avoid exposing them directly to the Internet.

### Distributed command-line tools

A distributed CLI sends commands to a remote service.

Example:

`deploy status --environment production`

Recommended flow:

1. CLI validates input.
2. CLI authenticates to an HTTPS API.
3. Server verifies authorization.
4. Server performs an allow-listed action.
5. CLI displays the structured result.

The server must never trust the CLI to enforce authorization.

## 3.8 Network Security

### TLS-encrypted communication

TLS protects data confidentiality and integrity in transit.

```python name=tls_client.py
import socket
import ssl

context = ssl.create_default_context()

with socket.create_connection(("example.com", 443), timeout=5) as raw_socket:
    with context.wrap_socket(
        raw_socket,
        server_hostname="example.com",
    ) as tls_socket:
        print(tls_socket.version())
```

Use `create_default_context()` rather than disabling security checks.

### Certificate validation

Certificate validation confirms that:

- The certificate is issued by a trusted authority.
- It matches the requested hostname.
- It is currently valid.

Never use this in production:

```python name=insecure_tls_example.py
# Insecure: disables certificate and hostname verification.
# context.check_hostname = False
# context.verify_mode = ssl.CERT_NONE
```

For private services, configure a trusted private certificate authority rather than disabling verification.

### Authentication and authorization

- **Authentication:** Who are you?
- **Authorization:** What may you do?

```python name=authorization.py
user_permissions = {"files:read"}
required_permission = "files:delete"

if required_permission not in user_permissions:
    raise PermissionError("Operation not permitted")
```

Use deny-by-default rules and check permissions on the server for every protected operation.

### Host and port allow-listing

Outbound connections should be restricted to approved destinations.

```python name=destination_allowlist.py
from urllib.parse import urlsplit

ALLOWED_DESTINATIONS = {
    ("api.example.com", 443),
}


def validate_url(value: str) -> tuple[str, int]:
    parsed = urlsplit(value)

    if parsed.scheme != "https":
        raise ValueError("Only HTTPS URLs are allowed")

    if parsed.username or parsed.password:
        raise ValueError("Credentials are not allowed in URLs")

    host = parsed.hostname
    port = parsed.port or 443

    if (host, port) not in ALLOWED_DESTINATIONS:
        raise ValueError("Destination is not allowed")

    return host, port
```

For strong server-side request forgery protection, also control DNS resolution and block private, loopback, link-local, and metadata-service addresses where inappropriate.

### Message-size limits

Reject oversized messages before allocating excessive memory.

```python name=message_size_limit.py
MAX_MESSAGE_SIZE = 64 * 1024

data = b"example"

if len(data) > MAX_MESSAGE_SIZE:
    raise ValueError("Message is too large")
```

For length-prefixed protocols, validate the declared length before reading the body.

### Rate limiting

Rate limiting controls how frequently a client may perform an action.

```python name=simple_rate_limit.py
import time

WINDOW_SECONDS = 60
MAX_REQUESTS = 10

request_times: list[float] = []


def allow_request() -> bool:
    now = time.monotonic()
    request_times[:] = [
        timestamp
        for timestamp in request_times
        if now - timestamp < WINDOW_SECONDS
    ]

    if len(request_times) >= MAX_REQUESTS:
        return False

    request_times.append(now)
    return True
```

Production rate limiting usually uses a shared data store and limits by authenticated identity, API key, and possibly source IP.

### Input validation

Validate all incoming fields:

- Required keys
- Data types
- Lengths
- Numeric ranges
- Allowed operations
- Character rules
- Protocol version
- Total message size

```python name=validate_message.py
def validate_message(message: object) -> str:
    if not isinstance(message, dict):
        raise ValueError("Message must be an object")

    action = message.get("action")

    if action not in {"status", "ping"}:
        raise ValueError("Unsupported action")

    return action
```

Allow-listing accepted values is safer than trying to identify every dangerous value.

### Replay and impersonation protection

A replay attack resends a previously valid request.

Common protections include:

- TLS
- Short-lived access tokens
- Nonces
- Timestamps with a small accepted time window
- Unique request identifiers
- Message authentication or digital signatures
- Storage of recently used nonces

```python name=replay_fields.py
import secrets
import time

message = {
    "timestamp": int(time.time()),
    "nonce": secrets.token_hex(16),
}
```

A nonce is effective only if the receiver verifies uniqueness and authenticates the complete message.

### Secure logging without exposing secrets

Log useful metadata, but redact sensitive data.

```python name=secure_logging.py
import logging

logger = logging.getLogger(__name__)

request_id = "req-123"
user_id = "user-42"

logger.info(
    "Request completed",
    extra={"request_id": request_id, "user_id": user_id},
)
```

Do not log:

- Passwords
- Private keys
- Access or refresh tokens
- Full session identifiers
- Sensitive message contents
- Unnecessary personal data

## 3.9 Testing Network Applications

### Unit testing protocol logic

Keep message validation separate from sockets so it can be tested easily.

```python name=protocol.py
def validate_action(message: dict[str, object]) -> str:
    action = message.get("action")

    if action not in {"ping", "status"}:
        raise ValueError("Unsupported action")

    return str(action)
```

```python name=test_protocol.py
import pytest
from protocol import validate_action


def test_accepts_ping() -> None:
    assert validate_action({"action": "ping"}) == "ping"


def test_rejects_unknown_action() -> None:
    with pytest.raises(ValueError):
        validate_action({"action": "delete-all"})
```

### Client-server integration testing

Integration tests run a real server and client together, normally on loopback.

Bind to port `0` to let the operating system choose an available port.

```python name=integration_server.py
import socket

with socket.socket() as server:
    server.bind(("127.0.0.1", 0))
    host, port = server.getsockname()
    print(f"Test server uses {host}:{port}")
```

This prevents tests from depending on a fixed port.

### Mocking network dependencies

Mocking avoids contacting real external services.

```python name=test_mock_connection.py
from unittest.mock import patch


@patch("socket.create_connection")
def test_connection(mock_connect) -> None:
    mock_connect.return_value.__enter__.return_value = object()

    # Call the function that creates the connection here.

    mock_connect.assert_called_once()
```

Mock at the boundary your application owns rather than mocking every low-level socket method.

### Testing timeouts and disconnections

Test situations where:

- The server never responds.
- The connection closes halfway through a message.
- The client disconnects before sending everything.
- A write fails.
- Cancellation happens during cleanup.

```python name=test_timeout.py
import asyncio
import pytest


@pytest.mark.asyncio
async def test_operation_times_out() -> None:
    with pytest.raises(TimeoutError):
        await asyncio.wait_for(asyncio.sleep(1), timeout=0.01)
```

Keep test timeouts short but not so short that CI becomes unreliable.

### Load and concurrency testing

Load testing checks behavior with many connections or requests.

```python name=basic_concurrency_test.py
import asyncio


async def simulated_client() -> None:
    reader, writer = await asyncio.open_connection("127.0.0.1", 9000)

    try:
        writer.write(b"ping\n")
        await writer.drain()
        await asyncio.wait_for(reader.readline(), timeout=2)
    finally:
        writer.close()
        await writer.wait_closed()


async def main() -> None:
    await asyncio.gather(*(simulated_client() for _ in range(100)))


asyncio.run(main())
```

Measure:

- Requests per second
- Response latency
- Error and timeout rates
- Memory and CPU use
- Open connections
- Recovery after overload

Run load tests only against systems you own or are authorized to test.
