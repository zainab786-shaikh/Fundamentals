# 2. Automation Application Development

Automation applications perform repetitive tasks consistently with minimal human involvement. Examples include organizing files, generating reports, processing spreadsheets, sending emails, and controlling browsers.

---

## 2.1 Automation Fundamentals

### Identifying repeatable workflows

Choose tasks that:

- Follow predictable steps.
- Are performed frequently.
- Use structured input.
- Are time-consuming or error-prone.

Example workflow:

**Read orders → validate data → create invoices → email results → record completion**

Start by documenting the manual steps before automating them.

---

### Designing idempotent automation

An **idempotent** workflow produces the same result when run multiple times. It should not repeatedly create duplicate data.

```python name=idempotent_file.py
from pathlib import Path

directory = Path("reports")
directory.mkdir(parents=True, exist_ok=True)

report = directory / "daily.txt"
if not report.exists():
    report.write_text("Daily report\n", encoding="utf-8")
```

Running this repeatedly creates only one report.

---

### Sequential and parallel workflows

Sequential tasks run one after another and are appropriate when order matters.

```python name=sequential.py
def download() -> None:
    print("Downloading")


def validate() -> None:
    print("Validating")


download()
validate()
```

Independent I/O tasks can run concurrently.

```python name=parallel.py
from concurrent.futures import ThreadPoolExecutor


def process(file_name: str) -> str:
    return f"Processed {file_name}"


with ThreadPoolExecutor(max_workers=4) as executor:
    results = executor.map(process, ["a.txt", "b.txt", "c.txt"])

print(*results, sep="\n")
```

Use limited concurrency to avoid exhausting memory, network connections, or API quotas.

---

### Retry and recovery strategies

Retry only temporary failures, such as timeouts or unavailable services.

```python name=retry.py
import time


def unstable_operation() -> None:
    raise TimeoutError("Service temporarily unavailable")


for attempt in range(1, 4):
    try:
        unstable_operation()
        break
    except TimeoutError:
        if attempt == 3:
            raise
        time.sleep(2 ** (attempt - 1))
```

This uses **exponential backoff**: 1 second, then 2 seconds. Do not retry permanent validation or authentication errors.

---

### Dry-run and preview modes

A dry run displays planned changes without applying them.

```python name=dry_run.py
from pathlib import Path


def delete_file(path: Path, dry_run: bool = True) -> None:
    if dry_run:
        print(f"Would delete: {path}")
        return

    path.unlink(missing_ok=True)


delete_file(Path("old.txt"), dry_run=True)
```

Dry-run mode is especially important for deletion, renaming, deployment, and bulk updates.

## 2.2 File and Directory Automation

Use `pathlib` for cross-platform path operations and `shutil` for high-level file operations.

### Creating, copying, moving, and deleting files

```python name=file_operations.py
from pathlib import Path
import shutil

source = Path("input.txt")
copy = Path("backup/input.txt")
moved = Path("archive/input.txt")

copy.parent.mkdir(parents=True, exist_ok=True)
shutil.copy2(source, copy)

moved.parent.mkdir(parents=True, exist_ok=True)
shutil.move(copy, moved)

moved.unlink(missing_ok=True)
```

Confirm destructive operations and create backups when appropriate.

---

### File organization and classification

Files can be organized by extension, date, size, or content.

```python name=organize_files.py
from pathlib import Path
import shutil

source_directory = Path("downloads")

for file in source_directory.iterdir():
    if not file.is_file():
        continue

    extension = file.suffix.lower().removeprefix(".") or "other"
    destination = source_directory / extension / file.name
    destination.parent.mkdir(exist_ok=True)

    if not destination.exists():
        shutil.move(file, destination)
```

Handle duplicate destination names instead of silently overwriting files.

### Duplicate-file detection

File hashes can identify files with identical content.

```python name=find_duplicates.py
from hashlib import sha256
from pathlib import Path

seen: dict[str, Path] = {}

for path in Path("documents").rglob("*"):
    if not path.is_file():
        continue

    digest = sha256(path.read_bytes()).hexdigest()

    if digest in seen:
        print(f"Duplicate: {path} and {seen[digest]}")
    else:
        seen[digest] = path
```

For large files, calculate hashes in chunks to avoid high memory usage. Compare file sizes before hashing to improve performance.

### File-system monitoring

The third-party `watchdog` package can detect file changes.

Install:

`python -m pip install watchdog`

```python name=monitor_directory.py
from pathlib import Path
from watchdog.events import FileSystemEventHandler
from watchdog.observers import Observer


class ChangeHandler(FileSystemEventHandler):
    def on_created(self, event) -> None:
        if not event.is_directory:
            print(f"Created: {event.src_path}")


observer = Observer()
observer.schedule(ChangeHandler(), str(Path("inbox")), recursive=False)
observer.start()

try:
    observer.join()
except KeyboardInterrupt:
    observer.stop()
    observer.join()
```

Real applications should debounce repeated events and shut down cleanly.

### Safe path handling and path-traversal prevention

Never directly append untrusted paths such as `../../secret.txt` to a trusted directory.

```python name=safe_path.py
from pathlib import Path


def safe_path(base_directory: Path, user_name: str) -> Path:
    if Path(user_name).name != user_name:
        raise ValueError("Nested or absolute paths are not allowed")

    base = base_directory.resolve()
    candidate = (base / user_name).resolve()

    if not candidate.is_relative_to(base):
        raise ValueError("Path escapes the permitted directory")

    return candidate


print(safe_path(Path("uploads"), "report.pdf"))
```

Also validate extensions, file sizes, symbolic links, and actual file content where security matters.

### Import and export workflows

An import/export workflow typically:

1. Reads source data.
2. Validates its schema.
3. Converts values.
4. Writes the destination format.
5. Records successes and failures.

```python name=json_to_csv.py
import csv
import json
from pathlib import Path

records = json.loads(Path("users.json").read_text(encoding="utf-8"))

with Path("users.csv").open("w", encoding="utf-8", newline="") as file:
    writer = csv.DictWriter(file, fieldnames=["name", "email"])
    writer.writeheader()
    writer.writerows(records)
```

Validate that `records` is a list and that every entry contains the expected fields before exporting.

```python name=encrypt_pdf.py
import os

password = os.environ["PDF_PASSWORD"]
```

## 2.8 Email Processing

### Sending email securely

Use TLS and obtain credentials from environment variables or a secret manager.

```python name=send_email.py
import os
import smtplib
import ssl
from email.message import EmailMessage

message = EmailMessage()
message["Subject"] = "Automation completed"
message["From"] = os.environ["SMTP_FROM"]
message["To"] = "recipient@example.com"
message.set_content("The report is ready.")

context = ssl.create_default_context()

with smtplib.SMTP_SSL(
    os.environ["SMTP_HOST"],
    465,
    context=context,
    timeout=30,
) as smtp:
    smtp.login(
        os.environ["SMTP_USERNAME"],
        os.environ["SMTP_PASSWORD"],
    )
    smtp.send_message(message)
```

### Exception handling

Catch only errors you can meaningfully handle.

```python name=exception_handling.py
from pathlib import Path
import logging

logger = logging.getLogger(__name__)

try:
    content = Path("input.txt").read_text(encoding="utf-8")
except FileNotFoundError:
    logger.error("Required input file is missing")
    raise SystemExit(2)
except UnicodeError:
    logger.error("Input file is not valid UTF-8")
    raise SystemExit(3)
```

Do not silently ignore errors with an empty `except` block.

### Retries with backoff

A reusable retry function can use exponential backoff plus random jitter.

```python name=backoff.py
import random
import time
from collections.abc import Callable


def retry(operation: Callable[[], str], attempts: int = 3) -> str:
    for attempt in range(attempts):
        try:
            return operation()
        except TimeoutError:
            if attempt == attempts - 1:
                raise

            delay = (2 ** attempt) + random.uniform(0, 0.5)
            time.sleep(delay)

    raise RuntimeError("Unreachable")
```

Jitter prevents many workers from retrying simultaneously.

### Checkpoints and resumable workflows

Store completed steps so interrupted work can continue.

```python name=checkpoint.py
import json
from pathlib import Path

checkpoint_file = Path("checkpoint.json")
state = (
    json.loads(checkpoint_file.read_text(encoding="utf-8"))
    if checkpoint_file.exists()
    else {"completed": []}
)

for item in ["file-1", "file-2", "file-3"]:
    if item in state["completed"]:
        continue

    print(f"Processing {item}")
    state["completed"].append(item)

    temporary = checkpoint_file.with_suffix(".tmp")
    temporary.write_text(json.dumps(state), encoding="utf-8")
    temporary.replace(checkpoint_file)
```

Atomic replacement reduces the chance of leaving a partially written checkpoint.

### Duplicate-execution prevention

A lock file can stop overlapping local executions.

```python name=execution_lock.py
from pathlib import Path

lock_path = Path("automation.lock")

try:
    lock_path.touch(exist_ok=False)

    # Run automation here.
    print("Automation running")
finally:
    lock_path.unlink(missing_ok=True)
```

For distributed applications, use a database constraint, distributed lock, or unique job identifier instead of a local file.

### Notifications and alerting

Send alerts when:

- Automation fails permanently.
- A retry limit is reached.
- A deadline is missed.
- Output validation fails.
- Resource usage crosses a threshold.

Avoid alerting on every temporary failure because excessive notifications hide important incidents.

## Recommended Automation Workflow

1. Document the manual process.
2. Identify inputs, outputs, and side effects.
3. Validate all external input.
4. Implement a dry-run mode.
5. Make operations idempotent.
6. Add structured logging and execution identifiers.
7. Add timeouts and limited retries.
8. Save checkpoints for long-running workflows.
9. Test success, failure, and repeated execution.
10. Schedule the workflow with least-privilege credentials.
11. Monitor execution and alert only on actionable failures.
