Lesson 5: Tasks

So far, our flow looks like this:

Agent Card  → Discover agent

Skill       → Discover capability

Message     → Request work

Response    → Get result


This works great when work is instant:

10 + 20

Weather in Mumbai


But now let's face a more realistic problem.

The Problem

Suppose you ask an agent:

Generate a 200-page financial report


or

Analyze 50,000 documents

Research all competitors in the market

Minutes
Hours
Even days


A normal message-response approach breaks down.

Token #123

A2A Solution: Task

A task represents a unit of work that may take time to complete. Instead of returning the final result immediately, an agent creates a task and gives back a task identifier that can be tracked. This is a core concept in the A2A Protocol.

Think:

Message = Request

Task = Work Order

First Task

Instead of returning the report immediately:

{
    "report": "..."
}


return:

{
    "task_id": "123",
    "status": "submitted"
}

Visual Flow
Client Agent
      |
      | generate_report
      |
      v
Report Agent

Returns

Task #123
Status=Submitted

Simple Python Example
import uuid

class ReportAgent:

    def create_task(self):

        task = {
            "task_id": str(uuid.uuid4()),
            "status": "submitted"
        }

        return task


Usage:

agent = ReportAgent()

task = agent.create_task()

print(task)


Example output:

{
    'task_id': '5d23...',
    'status': 'submitted'
}

Task Lifecycle

At creation:

{
    "task_id": "123",
    "status": "submitted"
}


Meaning:

I received your request.


Nothing more.

Let's Simulate a Task
class ReportAgent:

    def submit_task(self):

        return {
            "task_id": "123",
            "status": "submitted"
        }


Client:

agent = ReportAgent()

response = agent.submit_task()

print(response)


Output:

{
    'task_id': '123',

Adding Internal Storage

A task should not disappear.

class ReportAgent:

    def __init__(self):

        self.tasks = {}

    def submit_task(self):

        task = {
            "task_id": "123",
            "status": "submitted"
        }

        self.tasks["123"] = task

        return task


Now the agent remembers the task.

Retrieving a Task Later

Add:

def get_task(self, task_id):

    return self.tasks.get(task_id)


Usage:

agent = ReportAgent()

agent.submit_task()

task = agent.get_task("123")

print(task)


Output:

{
    'task_id': '123',
    'status': 'submitted'
}

Problem-Solving Exercise

agent = TranslationAgent()

What We've Learned

A Message asks for work.

A Task tracks work.

Message
    |
Create
    |
Task
    |
Track
    |
Result


The key insight is:

Messages are for communication. Tasks are for long-running work.
