Lesson 10: Coordinator Agent

In the previous lesson, we learned delegation:

Travel Agent
    |
    +--> Weather Agent
    +--> Hotel Agent


Now let's solve the next problem:

If there are many specialist agents, who coordinates everything?

The A2A Protocol is designed to support multi-agent collaboration where one agent can orchestrate work across multiple other agents.

The Problem

Suppose a user asks:

Plan my Bangalore trip


To answer this, we need:

Weather Agent
Hotel Agent
Flight Agent


Question:

Who talks to all these agents?
Who combines the results?
Who returns the final response?


If the user directly talks to each agent:

User
 ├── Weather Agent
 ├── Hotel Agent
 └── Flight Agent


the user becomes the coordinator.

That's not ideal.

A2A Solution: Coordinator Agent

Introduce a special agent:

Coordinator Agent


Architecture:

User
  |
  v
Coordinator Agent
  |
  +--> Weather Agent
  |
  +--> Hotel Agent
  |
  +--> Flight Agent


The user only talks to one agent.

The coordinator handles the complexity.

Real-World Analogy

Think of a project manager.

You don't directly coordinate:

Developer
Tester
UX Designer
DevOps


Instead:

Project Manager


coordinates everyone and reports back.

Similarly:

Coordinator Agent


coordinates specialist agents.

Step 3: Delegate Work
class CoordinatorAgent:

    def __init__(self):

        self.weather = WeatherAgent()
        self.hotel = HotelAgent()
        self.flight = FlightAgent()

    def plan_trip(self):

        weather_result = self.weather.handle_message(
            {"skill": "weather_lookup"}
        )

        hotel_result = self.hotel.handle_message(
            {"skill": "hotel_search"}
        )

        flight_result = self.flight.handle_message(
            {"skill": "flight_search"}
        )

        return {
            "weather": weather_result,
            "hotel": hotel_result,
            "flight": flight_result
        }

Combined Response

Why Not Let Every Agent Talk to Every Agent?

Imagine 50 agents.

Without a coordinator:

Agent A talks to B,C,D,E,F

Agent B talks to A,C,D,E,F

Agent C talks to A,B,D,E,F


This becomes a tangled network.

With a coordinator:

         Coordinator
        /     |      \
       /      |       \
      A       B        C


Much cleaner.

Coordinator Producing a Final Artifact

Instead of returning raw responses:

return {
    "weather": "Sunny",
    "hotel": "Taj",
    "flight": "AI101"
}


the coordinator can build a final artifact.

final_artifact = {
    "artifact_id": "trip-plan-001",
    "content": """
    Weather: Sunny
    Hotel: Taj Bangalore
    Flight: AI101
    """
}


Return:

{
    "status": "completed",
    "artifact": final_artifact
}


This is closer to how real multi-agent systems work.

Problem-Solving Exercise
Requirement

Build a Research Coordinator.

Specialists:

NewsAgent
FinanceAgent

News Agent
class NewsAgent:

    def get_data(self):
        return "Latest news collected"

Finance Agent
class FinanceAgent:

    def get_data(self):
        return "Financial data collected"

Coordinator
class ResearchCoordinator:

    def __init__(self):

        self.news = NewsAgent()
        self.finance = FinanceAgent()

    def research(self):

        news = self.news.get_data()

        finance = self.finance.get_data()

        return {
            "news": news,
            "finance": finance
        }


Output:

{
    "news": "Latest news collected",
    "finance": "Financial data collected"
}

What We've Learned

A Coordinator Agent:

Receives user requests.
Identifies required skills.
Delegates to specialist agents.
Collects artifacts.
Combines results.
Returns a final artifact.

Flow:

User
  |
Coordinator
  |
  +--> Agent A
  +--> Agent B
  +--> Agent C
  |
Combine Results
  |
Final Artifact


This is one of the most common architectures built using the A2A Protocol.
