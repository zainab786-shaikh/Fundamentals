Lesson 7: Artifacts

So far, our A2A journey looks like this:

Agent Card → Who am I?

Skill → What can I do?

Message → What work do you want?

Task → Track the work

Task State → What's happening now?


Now comes a critical question:

The task is completed. Where is the actual result?

The answer is: Artifact.

In the A2A Protocol, an artifact represents the output produced by a task. Tasks track work; artifacts contain deliverables.

The Problem

Suppose we submitted:

Generate Annual Sales Report


Task:

{
    "task_id": "123",
    "status": "completed"
}


Great!

But where is the report?

The task only tells us:

Work finished ✅


It doesn't contain:

The actual output

Real-World Analogy

Imagine ordering food.

Task = Token #45

Status = Ready


Token #45 is not the pizza.

The pizza is the actual deliverable.

Similarly:

Task = Work Tracking

Artifact = Deliverable

A2A Solution

Separate:

Task


from

Artifact


Think:

Task = Process

Artifact = Result

First Artifact

Suppose report generation completed.

Artifact:

artifact = {
    "artifact_id": "report-001",
    "content": "Sales increased by 25%"
}


This is the result produced by the task.

Simple Python Example
Create Artifact
artifact = {
    "artifact_id": "001",
    "content": "Sales increased by 25%"
}

print(artifact)


Output:

{
    'artifact_id': '001',
    'content': 'Sales increased by 25%'
}

Attaching Artifact to Task

Let's enhance our task.

task = {
    "task_id": "123",
    "status": "completed",
    "artifact": {
        "artifact_id": "001",
        "content": "Sales increased by 25%"
    }
}


Now the client can retrieve both:

Status
Result

Building a Simple Report Agent
class ReportAgent:

    def generate_report(self):

        task = {
            "task_id": "123",
            "status": "completed",
            "artifact": {
                "artifact_id": "001",
                "content": "Sales increased by 25%"
            }
        }

        return task

Usage
agent = ReportAgent()

result = agent.generate_report()

print(result)


Output:

{
    'task_id': '123',
    'status': 'completed',
    'artifact': {
        'artifact_id': '001',
        'content': 'Sales increased by 25%'
    }
}

Why Not Put the Result Directly in the Task?

Beginners often ask:

Why not store everything inside task?


Because results can be very different.

Examples:

Report
"Sales increased by 25%"

Translation
"Hola Mundo"

Image Generation
image.png

Research
50-page document


The task tracks execution.

The artifact represents output.

This separation keeps the model clean.

Multiple Artifacts

One task can produce multiple outputs.

Example:

Research Task


Produces:

Executive Summary
Charts
Detailed Report


Represented as:

task = {
    "task_id": "123",
    "status": "completed",
    "artifacts": [
        {
            "artifact_id": "summary"
        },
        {
            "artifact_id": "chart"
        },
        {
            "artifact_id": "report"
        }
    ]
}

Mini Exercise
Problem

Build a Weather Agent.

Input:

{
    "skill": "weather_lookup",
    "city": "Mumbai"
}


Expected Artifact:

{
    "artifact_id": "weather-001",
    "content": "Sunny in Mumbai"
}

Solution
class WeatherAgent:

    def weather_lookup(self, city):

        return {
            "task_id": "W001",
            "status": "completed",
            "artifact": {
                "artifact_id": "weather-001",
                "content": f"Sunny in {city}"
            }
        }


agent = WeatherAgent()

print(agent.weather_lookup("Mumbai"))


Output:

{
    'task_id': 'W001',
    'status': 'completed',
    'artifact': {
        'artifact_id': 'weather-001',
        'content': 'Sunny in Mumbai'
    }
}
