Lesson 6: Task States

In Lesson 5, we created a Task:

{
    "task_id": "123",
    "status": "submitted"
}


That solved one problem:

✅ Long-running work can be tracked.

But now a new problem appears:

What is the task doing right now?

The Problem

Suppose you submitted:

Generate Annual Report


Agent returns:

{
    "task_id": "123"
}


Ten seconds later, you ask:

Is it done?


How does the agent answer?

Possible situations:

1. Not started
2. Working
3. Completed
4. Failed


Without states, the client has no idea.

Real World Example

When you order from Swiggy/Zomato:

Order Received
Preparing Food
Picked Up
Delivered


These are states.

Without them, you'd only see:

Order #123


which isn't very useful.

A2A Solution: Task States

A2A tasks move through states so that clients can monitor progress instead of waiting blindly. The protocol models long-running work through trackable task status updates.

We'll use a simplified version:

submitted
working
completed
failed

State 1: submitted

Client sends request:

{
    "skill": "generate_report"
}


Agent creates task:

{
    "task_id": "123",
    "status": "submitted"
}


Meaning:

I received your request.

State 2: working

Agent starts actual execution.

{
    "task_id": "123",
    "status": "working"
}


Meaning:

I am processing the request.

State 3: completed

Agent finishes work.

{
    "task_id": "123",
    "status": "completed"
}


Meaning:

Your result is ready.

State 4: failed

Something goes wrong.

{
    "task_id": "123",
    "status": "failed"
}


Meaning:

I could not complete the request.

Complete Example
class ReportAgent:

    def __init__(self):
        self.tasks = {}

    def submit_task(self):

        task = {
            "task_id": "123",
            "status": "submitted"
        }

        self.tasks["123"] = task

        return task

    def start_task(self, task_id):

        self.tasks[task_id]["status"] = "working"

    def complete_task(self, task_id):

        self.tasks[task_id]["status"] = "completed"

    def get_task(self, task_id):

        return self.tasks[task_id]

Running It
agent = ReportAgent()

task = agent.submit_task()

print(task)


Output:

{
    'task_id': '123',
    'status': 'submitted'
}

}


Finish work:

agent.complete_task("123")

}

What We've Learned

A task is not just an ID.

A task has a lifecycle:

submitted
working
completed
failed


This allows agents to coordinate long-running work and provide visibility into execution progress.
