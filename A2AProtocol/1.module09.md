Lesson 9: Delegation

This is where A2A starts becoming truly powerful.

Until now, we've assumed:

One Request
      ↓
One Agent
      ↓
One Result


But real-world requests are rarely that simple.

The Agent2Agent (A2A) Protocol was designed so agents can collaborate and delegate work to other agents, enabling complex multi-agent workflows.

The Problem

Suppose a user asks:

Plan a trip to Bangalore


Can a Weather Agent do that?

❌ No

Can a Hotel Agent do that?

❌ No

Can a Flight Agent do that?

❌ No

Each agent only knows its specialty.

What Information Is Needed?

To plan a trip, we need:

Weather Information
Hotel Information
Flight Information


Which means:

WeatherAgent
HotelAgent
FlightAgent


must all participate.

Naive Solution

Put everything inside one giant agent.

class TravelAgent:

    def get_weather():
        pass

    def get_hotels():
        pass

    def get_flights():
        pass


Problem:

TravelAgent becomes huge.


Over time:

Payments
Weather
Hotels
Flights
Restaurants
Maps
Visa
Insurance


One agent does everything.

This defeats the purpose of specialization.

A2A Solution: Delegation

Instead of doing everything itself:

Travel Agent
      |
      +----> Weather Agent
      |
      +----> Hotel Agent
      |
      +----> Flight Agent


The Travel Agent acts like a manager.

Specialists do the work.

Real-World Analogy

Imagine you're a software architect.

A project arrives.

Do you:

Code everything?
Test everything?
Deploy everything?
Operate everything?


No.

You delegate:

Developer
Tester
DevOps


Similarly:

Travel Agent


delegates work to specialist agents.

First Delegation Example
Weather Agent
class WeatherAgent:

    def handle_message(self, message):

        return {
            "artifact": {
                "content": "Sunny"
            }
        }

Travel Agent
class TravelAgent:

    def __init__(self):

        self.weather_agent = WeatherAgent()

    def plan_trip(self):

        weather = self.weather_agent.handle_message(
            {"skill": "weather_lookup"}
        )

        return weather


Usage:

agent = TravelAgent()

print(agent.plan_trip())


Output:

{
    'artifact': {
        'content': 'Sunny'
    }
}

What Just Happened?

The user never talked to WeatherAgent.

User
  |
Travel Agent
  |
Weather Agent


Travel Agent delegated the work.

Adding Another Agent

Let's add a Hotel Agent.

class HotelAgent:

    def handle_message(self, message):

        return {
            "artifact": {
                "content": "Taj Bangalore"
            }
        }

Travel Agent Delegates Twice
class TravelAgent:

    def __init__(self):

        self.weather_agent = WeatherAgent()
        self.hotel_agent = HotelAgent()

    def plan_trip(self):

        weather = self.weather_agent.handle_message(
            {"skill": "weather_lookup"}
        )

        hotel = self.hotel_agent.handle_message(
            {"skill": "hotel_search"}
        )

        return {
            "weather": weather,
            "hotel": hotel
        }

Result
{
    "weather": {
        "artifact": {
            "content": "Sunny"
        }
    },
    "hotel": {
        "artifact": {
            "content": "Taj Bangalore"
        }
    }
}

Why Delegation Is Powerful

Without delegation:

Agent A knows everything


With delegation:

Agent A knows who knows


Huge difference.

A good agent doesn't need all knowledge.

It needs to know where to get knowledge.

Aggregating Results

The delegating agent often combines results.

trip_plan = {
    "city": "Bangalore",
    "weather": "Sunny",
    "hotel": "Taj Bangalore"
}


This combined output becomes the final artifact.

Problem-Solving Exercise
Requirement

Build:

MathAgent


with two specialist agents:

AdditionAgent
MultiplicationAgent

Addition Agent
class AdditionAgent:

    def calculate(self, a, b):
        return a + b

Multiplication Agent
class MultiplicationAgent:

    def calculate(self, a, b):
        return a * b

Math Agent
class MathAgent:

    def __init__(self):

        self.add_agent = AdditionAgent()
        self.mul_agent = MultiplicationAgent()

    def solve(self):

        add_result = self.add_agent.calculate(10, 20)

        mul_result = self.mul_agent.calculate(10, 20)

        return {
            "addition": add_result,
            "multiplication": mul_result
        }


Output:

{
    'addition': 30,
    'multiplication': 200
}

What We've Learned

Delegation means:

One agent receives a request


and decides:

I cannot do everything myself.


So it:

Finds another agent
Sends a message
Receives a result
Combines outputs
Returns final artifact


The flow now looks like:

Discovery
    ↓
Agent Found
    ↓
Message
    ↓
Task
    ↓
Delegation
    ↓
Artifacts
    ↓
Final Result
