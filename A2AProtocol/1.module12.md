Lesson 12: Streaming & Progress Updates

Up to now, our task lifecycle looks like this:

submitted
    ↓
working
    ↓
completed


But there's a user experience problem.

The Problem

Suppose a user requests:

Analyze 100,000 documents


The agent responds:

{
    "task_id": "123",
    "status": "working"
}


Then for the next 10 minutes...

working
working
working
working
working


As a user, you'd wonder:

Is it stuck?
Did it crash?
Is it still running?

Real-World Analogy

When downloading a file:

Downloaded 1%
Downloaded 25%
Downloaded 60%
Downloaded 90%
Completed


That's much better than:

Downloading...


for 10 minutes.

A2A Solution

Instead of only reporting:

working


the agent can send progress updates while the task executes. This allows clients to monitor task execution continuously. A2A Protocol supports task status tracking and event-based updates for long-running work.

First Progress Update

Instead of:

{
    "task_id": "123",
    "status": "working"
}


we can provide:

{
    "task_id": "123",
    "status": "working",
    "progress": 25
}


Meaning:

25% completed

Visual Timeline
Submitted
   ↓
10%
   ↓
30%
   ↓
60%
   ↓
90%
   ↓
Completed

Simple Python Simulation
task = {
    "task_id": "123",
    "status": "working",
    "progress": 0
}


Update progress:

task["progress"] = 25

print(task)


Output:

{
    'task_id': '123',
    'status': 'working',
    'progress': 25
}


Update again:

task["progress"] = 80


Output:

{
    'task_id': '123',
    'status': 'working',
    'progress': 80
}

Simulating Long Running Work
import time

task = {
    "task_id": "123",
    "status": "working",
    "progress": 0
}

for progress in [10, 30, 60, 90, 100]:

    task["progress"] = progress

    print(task)

    time.sleep(1)

task["status"] = "completed"

print(task)


Output:

10%
30%
60%
90%
100%
completed

Why Polling Is Not Ideal

One approach is:

Client asks every 5 seconds:
"Are you done?"

get_task("123")


again...

get_task("123")


again...

get_task("123")


This is called polling.

Problem With Polling

Imagine:

10,000 clients


checking every second:

Are you done?
Are you done?
Are you done?


The agent gets overloaded.

Better Solution: Streaming Events

Instead of the client asking:

What's happening?


the agent proactively sends updates.

Task Submitted

↓

10%

↓

50%

↓

90%

↓

Completed

Mental Model

Think about food delivery apps.

You don't keep asking:

Where is my driver?


The app pushes updates:

Restaurant accepted order

↓

Food prepared

↓

Driver picked up

↓

Arriving soon


Streaming works the same way.

Simple Event Example

Let's represent updates as events.

events = [

    {
        "task_id": "123",
        "progress": 10
    },

    {
        "task_id": "123",
        "progress": 50
    },

    {
        "task_id": "123",
        "progress": 90
    },

    {
        "task_id": "123",
        "status": "completed"
    }
]

How a Client Uses Events
for event in events:

    print(event)


Output:

10%
50%
90%
Completed

Coordinator Example

Imagine a coordinator delegated work to:

WeatherAgent
HotelAgent
FlightAgent


Progress might look like:

Weather Completed
33%

Hotel Completed
66%

Flight Completed
100%


The coordinator can stream these updates to the user.
