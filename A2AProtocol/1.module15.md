Lesson 15: Modeling Real A2A Objects with Python Dataclasses

So far we've used dictionaries everywhere:

message = {
    "role": "user",
    "parts": [...]
}


That's fine for learning.

But real A2A SDKs typically model protocol objects as classes.

Why?

Because classes provide:

Validation
Auto-completion
Type safety
Cleaner code

The A2A Protocol defines structured protocol objects such as Agent Cards, Messages, Tasks, Artifacts, and related entities.

Problem

As the application grows:

message["text"]
message["parts"]
message["role"]
message["artifact"]


becomes error-prone.

Example:

message["parst"]


Typo!

Runtime error.

Solution: Dataclasses

Python provides:

from dataclasses import dataclass


which lets us create lightweight protocol objects.

Step 1: Part

Recall:

Message
  |
  +-- Parts


Let's model a Part.

from dataclasses import dataclass

@dataclass
class Part:
    type: str
    content: str


Usage:

part = Part(
    type="text",
    content="Weather in Mumbai"
)

print(part)


Output:

Part(
    type='text',
    content='Weather in Mumbai'
)

Step 2: Message

Previously:

{
    "role": "user",
    "parts": [...]
}


Now:

from dataclasses import dataclass

@dataclass
class Message:
    role: str
    parts: list


Usage:

message = Message(
    role="user",
    parts=[
        Part(
            type="text",
            content="Get weather in Mumbai"
        )
    ]
)

print(message)

Subject
Body
Attachment

↓

Message

Role
Parts

Step 3: Artifact

Previously:

{
    "artifact_id": "001",
    "content": "Sunny"
}


Now:

@dataclass
class Artifact:
    artifact_id: str
    content: str


Usage:

artifact = Artifact(
    artifact_id="weather-001",
    content="Sunny in Mumbai"
)

Step 4: Task

Previously:

{
    "task_id": "123",
    "status": "completed"
}


Now:

@dataclass
class Task:
    task_id: str
    status: str
    artifact: Artifact = None


Usage:

task = Task(
    task_id="123",
    status="completed",
    artifact=artifact
)

Step 5: Skill

Previously:

{
    "id": "weather_lookup"
}


Now:

@dataclass
class Skill:
    id: str
    description: str


Usage:

skill = Skill(
    id="weather_lookup",
    description="Provides weather information"
)

Step 6: Agent Card

Before:

{
    "name": "WeatherAgent",
    "skills": [...]
}


Now:

@dataclass
class AgentCard:
    name: str
    description: str
    skills: list


Usage:

weather_card = AgentCard(
    name="WeatherAgent",
    description="Weather Service",
    skills=[
        Skill(
            id="weather_lookup",
            description="Get weather"
        )
    ]
)

Building a Realistic Agent
class WeatherAgent:

    def get_agent_card(self):

        return AgentCard(

            name="WeatherAgent",

            description="Weather Service",

            skills=[
                Skill(
                    id="weather_lookup",
                    description="Get weather"
                )
            ]
        )

Processing a Message
class WeatherAgent:

    def handle_message(
        self,
        message: Message
    ):

        return Artifact(

            artifact_id="weather-001",

            content="Sunny in Mumbai"

        )


Usage:

message = Message(

    role="user",

    parts=[
        Part(
            type="text",
            content="Weather in Mumbai"
        )
    ]
)

agent = WeatherAgent()

result = agent.handle_message(message)

print(result)


Output:

Artifact(
    artifact_id='weather-001',
    content='Sunny in Mumbai'
)

End-to-End Example
message = Message(
    role="user",
    parts=[
        Part(
            type="text",
            content="Weather in Mumbai"
        )
    ]
)

artifact = Artifact(
    artifact_id="weather-001",
    content="Sunny in Mumbai"
)

task = Task(
    task_id="123",
    status="completed",
    artifact=artifact
)


Flow:

Message
   ↓
Task
   ↓
Artifact


Exactly the same as before, but now represented cleanly.

Why This Matters

When you later see official A2A SDK examples, you'll encounter objects like:

AgentCard
Message
Task
Artifact


Instead of feeling overwhelmed, you'll immediately recognize:

AgentCard = Introduction

Message = Request

Task = Work Tracking

Artifact = Result


That's the most important understanding.
