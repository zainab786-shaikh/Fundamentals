Lesson 11: Discovery + Delegation Together (A Real A2A Flow)

Until now, we've been cheating a little.

Our coordinator already knew other agents:

self.weather = WeatherAgent()
self.hotel = HotelAgent()


But in a real Agent2Agent (A2A) Protocol system, agents discover other agents through their Agent Cards and capabilities instead of hardcoding dependencies.

The Problem

Suppose your company has:

WeatherAgent
HotelAgent
FlightAgent
TranslationAgent
FinanceAgent


Tomorrow:

WeatherAgentV2


is deployed.

Question:

Should you modify CoordinatorAgent source code?

❌ No

The coordinator should discover agents dynamically.

Real World Analogy

Think about hiring.

You don't hardcode:

Employee #123 will solve every problem


Instead:

Need: Java Developer

↓

Search Company Directory

↓

Find Matching People

↓

Assign Work


A2A works the same way.

Step 1: Agent Registry

We'll create a simple registry.

agents = [
    {
        "name": "WeatherAgent",
        "skills": ["weather_lookup"]
    },
    {
        "name": "HotelAgent",
        "skills": ["hotel_search"]
    },
    {
        "name": "FlightAgent",
        "skills": ["flight_search"]
    }
]


Think of this as a mini Agent Directory.

Step 2: Discovery Function

Instead of knowing agent names:

def discover_agent(skill):

    for agent in agents:

        if skill in agent["skills"]:
            return agent

    return None


Usage:

agent = discover_agent("weather_lookup")

print(agent)


Output:

{
    "name": "WeatherAgent",
    "skills": ["weather_lookup"]
}

What Just Happened?

The coordinator didn't ask:

Where is WeatherAgent?


Instead it asked:

Who supports weather_lookup?


This is a major mindset shift.

Capability-Based Thinking

Beginners think:

Find Agent


A2A thinks:

Find Capability


Because many agents might support the same capability.

Step 3: Actual Agent Implementations
class WeatherAgent:

    def handle_message(self, message):
        return "Sunny"

class HotelAgent:

    def handle_message(self, message):
        return "Taj Bangalore"

class FlightAgent:

    def handle_message(self, message):
        return "AI101"

Step 4: Runtime Agent Map

Imagine discovered agents become available.

available_agents = {

    "WeatherAgent": WeatherAgent(),

    "HotelAgent": HotelAgent(),

    "FlightAgent": FlightAgent()

}

Step 5: Dynamic Coordinator

Now the coordinator no longer depends on specific agents.

class Coordinator:

    def execute(self):

        weather_card = discover_agent(
            "weather_lookup"
        )

        weather_agent = available_agents[
            weather_card["name"]
        ]

        weather_result = weather_agent.handle_message(
            {
                "skill":"weather_lookup"
            }
        )

        return weather_result

Adding More Skills

Trip planning needs:

weather_lookup
hotel_search
flight_search


Coordinator discovers all three.

required_skills = [

    "weather_lookup",
    "hotel_search",
    "flight_search"

]


Loop:

for skill in required_skills:
    agent = discover_agent(skill)


No agent names involved.

Only capabilities.

Imagine tomorrow:
