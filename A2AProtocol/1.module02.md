Lesson 2: Agent Card
The Problem

In Lesson 1, we learned that agents should communicate through messages.

But a new question appears:

Before sending a message, how do I know what the other agent can do?

Imagine meeting a new employee in your company.

You wouldn't immediately ask them to review an architecture document.

First, you'd ask:

Who are you?
What do you do?
What are your skills?


Agents have the same problem.

Without Agent Cards

Suppose you have three agents:

Weather Agent
Finance Agent
Translation Agent


Your Travel Agent discovers them.

Now what?

Can Weather Agent:

weather_lookup


or

get_forecast


or

weather_service


Nobody knows.

Naive Solution

Hardcode everything.

agent_capabilities = {
    "WeatherAgent": ["weather_lookup"],
    "FinanceAgent": ["stock_analysis"]
}


Problems:

Not scalable
Every change requires code updates
New agents are unknown
A2A Solution: Agent Card

The Agent2Agent (A2A) Protocol introduces the concept of an Agent Card. It is a machine-readable description of an agent, including its identity, capabilities, and skills.

Think of it as:

LinkedIn Profile
+
Business Card
+
API Documentation


for an agent.

First Agent Card

Let's create one.

agent_card = {
    "name": "WeatherAgent",
    "description": "Provides weather information",
    "skills": [
        "weather_lookup"
    ]
}

What Each Field Means
Name
"name": "WeatherAgent"


Who am I?

Description
"description": "Provides weather information"


What do I do?

Skills
"skills": [
    "weather_lookup"
]


What am I capable of?

Why This Matters

Now your Travel Agent doesn't need prior knowledge.

Instead it asks:

Show me your Agent Card.


and gets:

{
    "name": "WeatherAgent",
    "description": "Provides weather information",
    "skills": [
        "weather_lookup"
    ]
}


Now it knows:

I can ask this agent about weather.

Simple Python Example
Weather Agent
class WeatherAgent:

    def get_agent_card(self):

        return {
            "name": "WeatherAgent",
            "description": "Provides weather information",
            "skills": [
                "weather_lookup"
            ]
        }

Client Agent
weather_agent = WeatherAgent()

agent_card = weather_agent.get_agent_card()

print(agent_card)


Output:

{
    'name': 'WeatherAgent',
    'description': 'Provides weather information',
    'skills': ['weather_lookup']
}

Making It More Useful

Let's add another skill.

agent_card = {
    "name": "WeatherAgent",
    "description": "Provides weather services",
    "skills": [
        "weather_lookup",
        "weather_forecast"
    ]
}


Now other agents know:

Current Weather ✅

Forecast ✅

Real-World Analogy

Imagine joining a Teams meeting.

The participant list shows:

Arif
Digital Technology Advisor
Software Architecture


Immediately you understand:

Who this person is
What they do


Agent Cards serve exactly this purpose.

Problem-Solving Exercise
Requirement

Create a Calculator Agent that advertises two skills.

add
subtract

Solution
class CalculatorAgent:

    def get_agent_card(self):

        return {
            "name": "CalculatorAgent",
            "description": "Performs math operations",
            "skills": [
                "add",
                "subtract"
            ]
        }


agent = CalculatorAgent()

print(agent.get_agent_card())


Output:

{
   'name': 'CalculatorAgent',
   'description': 'Performs math operations',
   'skills': [
      'add',
      'subtract'
   ]
}

Mental Model

Remember this:

Person      -> Resume

Company     -> Website

API         -> Swagger/OpenAPI

Agent       -> Agent Card

What We've Learned

An Agent Card answers three questions:

1. Who are you?
2. What do you do?
3. What skills do you provide?


Without Agent Cards:

Discovery is guesswork.


With Agent Cards:

Agents can introduce themselves automatically.
