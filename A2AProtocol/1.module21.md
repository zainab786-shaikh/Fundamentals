Lesson 21: Production-Style A2A Travel Planner

This lesson combines everything you've learned into one realistic architecture.

Problem Statement

A user asks:

Plan a 3-day trip to Bangalore with a budget of ₹30,000


To answer this, we need:

Weather Agent
Hotel Agent
Flight Agent
Budget Agent


No single agent has all the information.

Architecture
                User
                  |
                  v
          Coordinator Agent
                  |
     +------------+------------+
     |            |            |
     v            v            v
 Weather      Hotel       Flight
  Agent       Agent        Agent
                  |
                  v
            Budget Agent

                  |
                  v
           Final Trip Plan


This is the classic Coordinator + Specialist pattern supported by the A2A Protocol, where agents discover capabilities, delegate work, and aggregate results.

Production Coordinator Code

Simplified:

class TravelCoordinator:

    async def plan_trip(self, city):

        weather, hotel, flight, budget = \
            await asyncio.gather(

                get_weather(city),

                get_hotel(city),

                get_flight(city),

                analyze_budget(city)
            )

        return {

            "task_id": "TRIP-001",

            "status": "completed",

            "artifact": {

                "artifact_id": "PLAN-001",

                "content": {

                    "weather": weather,

                    "hotel": hotel,

                    "flight": flight,

                    "budget": budget
                }
            }
        }

Progress Aggregation

Suppose:

Weather = 100%
Hotel = 100%
Flight = 50%
Budget = 50%


Overall:

(100+100+50+50)/4


Result:

75%


User sees:

{
    "task_id": "TRIP-001",
    "status": "working",
    "progress": 75
}

Failure Handling

Suppose:

Weather ✅
Hotel ✅
Flight ❌
Budget ✅


Coordinator can:

Option A: Fail Entire Workflow
{
    "status": "failed"
}

Option B: Partial Result
{
    "status": "partial_success",

    "available":
    [
        "weather",
        "hotel",
        "budget"
    ],

    "missing":
    [
        "flight"
    ]
}


Enterprise systems often prefer partial success.
